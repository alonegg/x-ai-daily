## 开发工具与 Agent 工程实践
- **Claude Code 代码评审文章发酵：宝玉「瑞士奶酪」讲解视频，meng shao 补出收敛数据** {#claude-code-review-ga} [长推]：Anthropic《How the Claude Code team does code review》的主要内容昨天已收录。后续：宝玉发布中英双语讲解视频和完整文稿，用「一摞带洞的奶酪片 + 底下一张网」来讲：每道检查都会漏，叠起来就很难漏；人的时间花在审代码和救火两头，只省前一头没有意义。他按一次修改的流程讲了一遍（自验→CI 自动检查→多 AI 并行找问题再投票→安全审查→按风险定人工审批→合并队列→功能开关与分批发布→快速撤回），并回答五个问题：哪些修改还要人看，AI 审 AI 会不会没完（三轮封顶后，一轮通过率 65%→78%，要五轮以上的从 8.9% 降到 1.5%），审查 AI 漏了怎么办（拿历史事故做「错题本」每日评测），人不读代码怎么懂代码（让 Claude 为要动的那块代码现写讲解），出了事算谁的（「你合并的你负责」，复盘不追究个人，只问「本该由哪一片奶酪拦住」）。meng shao 的长文拆解补充：团队不追踪「评审覆盖率」，而是追踪每个 PR 平均几个人审批和等待时长，以回滚率和事故率作护栏；Boris Cherny 认为给 Claude 一个验证方法是「最重要的事」，效果能提升 2–3 倍；发现分 Important / Nit / Pre-existing 三类；PR 模板强制写「如何测试」和「如何回滚」；批准只对单个 commit 有效，有新提交就要重审；平均评审轮次从 2.08 降到 1.32。Gorden Sun 总结人类剩下的五件事：该不该做、高危代码、架构、审「证据」、为结果兜底。Daniel San 最感兴趣的是如何防止 agent 互审死循环，并预告要写一篇按预算和需求比较各种 agent 代码评审方案的文章。来源：[宝玉 @dotey](https://x.com/dotey/status/2111384189656252712) · [meng shao @shao__meng](https://x.com/shao__meng/status/2111274173192638932) · [Gorden Sun @Gorden_Sun](https://x.com/Gorden_Sun/status/2111472904148058121) · [Daniel San @dani_avila7](https://x.com/dani_avila7/status/2111494506495328608)
- **poteto 的「倒金字塔」：要信任 agent，先改代码库** {#poteto-trust-pyramid} [长推]：meng shao 解读 Grok Bot 团队 Lauren（@poteto）提出的四层框架，精力投入从上到下递减：①代码库改进（投入最多）——更好的架构、更强的类型与不变量、清晰的模块边界；agent 天生爱复制现有代码、走最短路径，那就让最短路径本身是对的；②静态分析——lint、测试、CI、形式化验证（如 TLA+），token 成本极低，反馈是确定性的；③文字性指导（尽量少用）——注释、AGENTS.md、Skill 描述，弱点是无法强制执行；④人工审查（最难规模化）——人的精力应该投向「设计让 agent 默认就做对的环境」。之所以是「倒置」的，是因为越往上手段越确定、越省 token，越往下越依赖不可靠的理解和不可扩展的人力。meng shao 认为这比「从 prompt 工程转向上下文工程」更进一步：连提示词也只是第三等手段，真正的杠杆在代码库里。来源：[meng shao @shao__meng](https://x.com/shao__meng/status/2111261981735067819) · [Lauren @poteto](https://x.com/poteto/status/2111133080526495985)

- **Buehler：从静态论文到「活的科学记录」，去中心化多 agent 做材料发现** {#living-scientific-record} [长推]：MIT 的 Markus Buehler 团队在 MRS Bulletin 发表观点文章《Toward living scientific records through decentralized multi-agent systems for materials discovery》（Wang、Berkovich、Marom 等，2026）。核心主张：科学发现正从人工编排工具和中央规划的 AI 工作流，转向通过一份共享的「活的科学记录」自主协调的去中心化系统。这份记录是一张带溯源链接的图，持续记录证据、假设、失败、批评和悬而未决的问题；论文、方法、数据集和批评都成为它的「视图」，人和 AI agent 都能检查、复现、质疑和扩展。他们的实现是 ScienceClaw × Infinite：数百个 AI 可调用的科学技能注册表，加一个共享的「工件与需求公共池」——agent 广播未满足的需求，按「压力」排序，自行认领关键空缺，没有中央规划者分派任务（类似白蚁无建筑师筑巢的 stigmergy）。案例：把蛛丝、鸟类鸣管膜、蟋蟀翅膀、声子晶体、乐器结构等 15 种共振体放进同一个六维特征空间，群体找到工程设计稀疏的区域；第一个候选偏离目标 2.12 个单位，系统根据候选自身几何算出的坐标发现了偏差，重新设计出预张紧柔性膜板，误差降到 0.007，再做有限元模态筛选（最低 10 阶弹性模态在 74.8–411.6 Hz）。要点：知识的持久单位决定科学方法，活的记录把它从「整理过的产出」推向「整理过的过程」；出版变成接口，评审可以细到单个节点；失败结果会保留，假设可复用、可组合；但持久不等于可信，还需要质量分、不确定性字段、对抗式评审和人的问责。他认为这扩展了开放科学的定义——开放的不只是最终结果，还有它如何得出的可执行、可检查、可持续扩展的完整记录。论文提供免费访问链接。来源：[Markus J.
