开场与头条预告

[主持] 早上好，今天是十一月六号，星期五。这里是 X 每日 AI 播报。

[解读] 昨天看着像一场速度比赛：模型更快出图，智能体更快找漏洞，实验室也可能更快造下一代模型。

[主持] 可我最想问的，是后面谁接得住。先说 METR，它判断 Anthropic 的能力进步速度，大约翻了一倍。

[解读] 不是说模型每道题都强一倍。而且他们很不确定，认为最有力的证据，还大半被删掉了。

[主持] 第二件，OpenAI 报了九百四十八个 Linux 本地提权利用，整次 API 开销约一百二十一万美元。

[解读] 数字很具体，但这是安全研究流水线，不能听成每台电脑马上都能被远程拿下。

[主持] 第三件，Jupyter 今年收到一百八十一份安全报告。AI 帮着找，维护者却不一定更轻松。

[解读] 还有十五位开源维护者，说自己最想看见的，是对面还有一个愿意负责的人。

[主持] Cat Wu 加入 OpenAI、Claude 只读理财，以及会解题却不会合作的模型，今天也都聊到。

[解读] 那先过快讯，再把快在哪里、谁付代价，分开算。

快讯

[主持] 先看人事。Cat Wu 自己宣布加入 OpenAI，负责核心产品的产品管理，不再只是离职传闻。

[解读] 她说想做让用户和团队仍能掌控的智能体。至于转职原因，帖子没展开，不能替她编公司内幕。

[主持] 宝玉还整理了 Austin Lau 的去向，这位 Anthropic 最早的增长岗位员工，也去了 OpenAI。

[解读] 以前不会编程，却用 Claude Code 做广告工具。品牌换了，产品之外怎么让人真的用起来，也还是一门活。

[主持] 刚离开 Anthropic 的 Thariq，上了 SOTA Wives 播客。离职原因和下一站，他仍没正面回答。

[解读] 他更想说，实验室里也是普通人，别把身份绑在公司上。聪明人不少，自己试一试的勇气反而稀缺。

[主持] 他还讲第一次创业，钱融得太多，却没证明够多东西，最后关掉公司、退回剩余资金。

[解读] 我觉得这种复盘，比替所有离职者安排下一站有用。想有内容可写，先把那些枯燥的活做了。

[主持] Meta 的 Muse 语音，现在对美国所有用户开放，可以打语音和视频电话，不是全球同时开放。

[解读] altryne 说体验像 FaceTime，那是他的感受。看见虚拟角色说话，也别直接当成独立体验评测。

[主持] 谷歌 Omni 一点二 Flash，最长十五秒视频，还能在对话里连续改，标价比一点一低约三成。

[解读] 同时想解决镜头控制和改完走样的问题。已经能从 AI Studio 和接口试，但演示好看不等于每条都稳。

[解读] 竖屏却会切掉画面。后面得把场景透视和界面投影分开修，能打开，不等于适配就结束了。

[主持] vista8 嫌录屏软件导出慢、中文转写弱，准备基于开源 Cap 自己改，不续订旧工具了。

[解读] 还有会议纪要知了、Orca 编辑器和网易的本地语音输入工具。都是体验分享，别把试用说成已全面替换。

[主持] 科学这边，Anthropic 的蛋白穹窿体研究，又补了实验过程。提纯从约三天缩到九十分钟。

[解读] 宝玉整理的项目里，首版三维结构约三十四小时。可也有方案出错、耽误两周，不能只报快的部分。

[主持] 找到细菌里的同类，不等于已经弄清这种蛋白的用途。团队用的是预印本，实验人员一直在把关。

[解读] 机器人论文也不少。Molmo 的规划器看图选动作，ManiFlow 的小动作模型负责积木操作，不是同一项成功率。

[主持] uni robot agent 则说明，同一个模型，换信息组织和反馈方式，操作分数就能差很多。

[解读] 另有流式视频强化学习、长视频记忆、物理研究智能体，以及相机运动和角色骨架工具，任务各不相同。

[主持] 不用把每个新名字都装一遍。比如视频记忆榜，最好的模型也远没满分，先找自己会卡的那一步。

[解读] 斯坦福的课程也在讲这个：轨迹生成便宜了，难的是筛出好数据，再用能复现的评测检验。

[主持] 社区里，levelsio 抱怨每天还要屏蔽约五十个 AI 回复号。写得像人，不代表给讨论添了东西。

[解读] Notion 创始人那篇，转述称一半页面由智能体创建。创建了多少，和后来有多少被认真用，也得分开看。

[主持] Mollick 关注美国生产率上升，认为可能有 AI 拐点；这个因果判断，还不是一个季度数字就能证明。

[解读] Apple 压缩员工 AI 预算、芯片积压香港，也都在转述新闻里。别把博主一句软件完了，当正式经营结论。

[主持] AI Engineer 上海那边，Ryo Lu 问得挺好：什么都能做的时候，我们还知道自己想要什么吗？

[解读] 还有 X 网页在慢连接下变快的工程分享。少让用户先等一大包脚本，有时比换模型更直接。

[主持] OpenAI 还公布基建社区的新承诺，说建数据中心，当地人应当有发言权，也能分享收益。

[解读] 这是政策和承诺，后面还得看怎么兑现。ChatGPT Classic 将下线的说法，则先来自 Gorden Sun 的转述。

[主持] vista8 转的 TikTok 逆向视频，也先当二手分析，不能说我们已经验证手机后台到底跑了多少模型。

[解读] Omarchy 则继续补硬件适配。DHH 晒过很快装好的案例，那是个案例，不是每台电脑的标准安装时间。

[主持] 开放工具这边，Frictionless 的 R 和 Python 库支持 Data Package 第二版，还兼容老工作流。

[解读] Python 侧也修了安全问题。可复用不只要格式统一，升级、验证和依赖这些平时不显眼的活，也得做。

[主持] EOSC 欧洲节点则补更大虚拟机、共享存储和可切换环境的 JupyterLab，重点还是让协作能重复跑起来。

[解读] Mathlib 获了数学开放科学奖，Helmholtz 也在表彰科研软件。研究后面的工具，值得跟论文一起被看见。

重点一：AI 造 AI，真的快了一倍吗

[主持] METR 这份评估，我最怕被压成一句：AI 已经证明让下一代研发速度翻倍。

[解读] 它说的是 Anthropic 在目标明确任务上，能力进步的速度，约为过去一段时期的两倍。

[主持] 不是每个模型都强两倍，也不是每个研究员效率翻倍。比较的是能力随时间变化的速度。

[解读] 而且这是团队判断，很不确定。一点三倍或三倍，METR 都说不会意外，别把两倍当精确测量。

[主持] 原因更要分开。它猜大部分加速来自 AI 做研发，八成只是大致估计，内部也没有共识。

[解读] 有些阶段，其他因素可能很重要。不能看到加速，就把全部功劳自动记给写代码的智能体。

[主持] 那公开出来的证据，有哪部分可以看？

[解读] 一个是公司自己的能力指数。去年十月以后增速约一点九倍，还纳入了几个未发布内部模型。

[主持] 我愿意看这个线索，但没法把外界拿不到的模型，放到我自己的评测里再跑一遍。

[解读] 换比较假设，结果也会动。员工访谈有帮助，可内部投票的自我感觉，不能顶替能力测量。

[主持] 更麻烦的是，那份约一百页的完整报告，最有说服力的大半证据，被 Anthropic 按约删掉了。

[解读] METR 特别说了这个限制。公开读者现在更依赖它的专业判断，不是人人都能顺着证据自己复核。

[主持] 我觉得独立评估值得认真对待，但独立不等于公众已经能验证。我们不能把两件事混在一起。

[解读] 我对保密会多一点理解。公司担心公布算法和加速机制，等于把路线图交出去，顾虑并不全是借口。

[主持] 顾虑我理解。可能力越快，越需要让人看得见安全有没有跟上，不是只说相信我们。

[解读] 这也是拉扯所在：怎么让可信的外部人看足材料，又不要求所有技术细节都公开。

[主持] 报告还说，没看到明显瓶颈，未来一年可能更快。这是判断未来，不是已经发生。

[解读] 它也承认视角有限，可能漏掉瓶颈。别把没看见，翻译成不存在。

[主持] 我会先盯评估有没有持续做、范围有没有变，而不是只记今天这个两倍。

[解读] 我会加上安全验证本身有没有提速。研发跑快了，验证没跟上，才是后面真正难接的地方。

重点二：九百四十八，不是九百四十八次远程攻破

[主持] OpenAI 这条，我觉得最有分量的是把发现、验证和候选补丁接到了一起。

[解读] 先扫代码，在隔离环境复现，再测利用，生成修复建议，最后由人审阅后报告。

[主持] 复现了一千七百二十四个漏洞，里面报出二百九十一个信息泄漏概念验证，还有那些本地提权利用。

[解读] 本地提权是已经能在机器上运行某些代码，再拿更高权限。跟隔着网络直接进机器，不是一回事。

[主持] 官方说，九百四十八个独立利用，在开着标准防护的 Linux 桌面配置上可用，这个限定得留下。

[解读] 这些数不能简单相加。也不是所有 Linux 机器同风险，配置和修复状态都要看。

[主持] 你怎么看那笔一百二十一万美元的成本？

[解读] 按整次 API 费用除以独立本地提权数，平均约一千二百八十美元；还不包括所有人力和部署成本。

[主持] 我支持算这笔账，但按历史比赛奖金估出来的价值，不能当成已经赚到的钱。

[解读] 更不能拿假想奖金除接口费，就说是任何人都能复制的收益率。维护者实际要的是能复现、能修。

[主持] 至少十种新利用手法，也是公司和咨询专家在他们所知范围内的说法，不是整个学界已全部确认。

[解读] 他们正跟 Linux 维护者和合作方处理补丁。候选还要审，不是写出来就已经安全。

[主持] GPT 六 Cyber，官方说驱动了这次研究。现在先对部分 Daybreak Red 客户开放，并不是人人下载。

[解读] Blue 帮经核实的防守方验证漏洞和修复，Red 则有更深的利用开发和授权测试，定位不同。

[主持] 我看重把能力交给防守者，但不觉得贴了防御两个字，就能省掉权限和审核。

[解读] 我更担心修复窗口。找得更快，维护者发布补丁、用户升级都要时间，这些不会自动一起快。

[主持] 那具体到团队，先确认资产、依赖和升级路径，比跟着一个吓人的总数转发，更能做点事。

[解读] 测试也只在授权范围。拿模型去碰别人的线上机器，不会因为出发点叫研究，就自动被允许。

重点三：图片快了，离交付近了多少

[主持] Images 二点六，我更在意可编辑的结果。过去图片好看，做成正式图标，还得重画。

[解读] 这次开发者功能里有 SVG 矢量图导出，记录线条和形状，放大不容易糊，也能单独改颜色。

[主持] 可公告没说清 ChatGPT 能不能直接导出。不能把接口里的功能，自动说成每个聊天用户都有。

[解读] 动图则能从文字或图片做出来，再调速度、逐帧看和改。合作演示里，也有先生成连续画面的做法。

[主持] 我挺喜欢这种先看小动画、再决定要不要做下去的过程。单张海报，表达不了动作节奏。

[解读] 但循环动图跟长视频不是一类交付。别因为能动了，就默认人物一直不走样、动作一直合理。

[主持] 两个接口模型，Flare 和 Sunburst，究竟该怎么选？

[解读] 一个偏快，低画质最快约六秒；一个更重画质和连续编辑的一致性。这些先是官方说法。

[主持] 官方称比前代生成速度快约五成。不是每个复杂任务，等待时间都直接砍半。

[解读] 而且两版按词元计费同价，快版不等于单价更低。画质、画面复杂程度，也分别影响你要的结果。

[主持] 我会拿同一张要反复改的商品图试：改背景以后，商品字样和位置，是不是还对。

[解读] 我会看导出后能不能接进现有设计流程。生成那一刻省十秒，后面重画半小时，就没真省下来。

[主持] OpenAI 自报每周约四十亿张图，这个量说明需求很大，可不是四十亿张都能直接出版。

[解读] 同意，规模不能替代质量。标注要改的位置、保存参考角色，都在把一次惊喜变成更可控制的流程。

[主持] 我倾向先在低风险素材试，保留版本和原图。别让速度快，变成谁都不知道哪张最后能用。

[解读] 商用也要查授权和事实内容。图做得更像真的，不会顺手替你核实图上的产品或数据。

重点四：看懂你的钱，不代表能动你的钱

[主持] Claude 在美国上线测试版个人理财，我倒觉得只读是重点，不是一个等待取消的小限制。

[解读] 通过 Plaid 连自己选的银行和信用卡，读余额、交易记录。不能转账、管理账户或投资。

[主持] 面向 Pro、Max、Ultra 个人用户逐步开放，免费、团队和企业版没有，也不是全球都能看到入口。

[解读] 主要帮你看收支、账单和异常费用。投资账户多只见余额，不等于它已经知道你的全部持仓和合同。

[主持] 我喜欢先找重复扣款这类具体问题。比让模型一句话决定我该买什么，更容易对照真实账单。

[解读] 可读得到，也不保证算得准。同步可能慢，重复连接同一账户，还可能把同一笔钱算两次。

[主持] 那隐私这块，哪些话不能说满？

[解读] 理财页里的对话不用来训练；普通聊天用了账户数据，则按你的隐私设置处理，不能笼统说全都不训练。

[主持] 用过账户数据的聊天不进记忆，也不等于聊天记录里没有数字。分享链接，别人仍可能看见。

[解读] 解绑后不再读取这家银行，但已同步数据的删除时间，Claude 当时帮助页没明确写，别替它保证。

[主持] 这个我会先看清。能撤连接、能删什么、什么时候删，是几件不同的事。

[解读] levelsio 还试过，让浏览器里的 Claude 帮 Revolut 付账单，被拒绝。不是登录好了就能绕过只读规则。

[主持] 我觉得拒绝挺合理。会帮你分析账，和有权替你付款，本来就该分开确认。

[解读] 我也不认为越主动越好。尤其涉及钱，用户说清的权限，比模型觉得能省一步重要。

[主持] 真要用，我会先看选了哪些账户，重要数字再回银行核对，不把合并后的看板当唯一账本。

[解读] 需要专业财务决定时，也不能把它当持牌顾问。看懂情况有用，责任和风险没有跟着自动转走。

重点五：会做题，怎么就不会当队友

[主持] 那份协作智力基准，我觉得戳中了多智能体的盲区：每个都聪明，凑一起未必省心。

[解读] 斯坦福、麻省理工和牛津的研究，用两百四十道可程序验证任务，测八种合作情形。

[主持] 它只把模型独自已经能解对的题，计入协作分。所以失败不只是不会解题，是合作出了问题。

[解读] 十八个模型里，把推理开高后，最高八十二点二分。模型能力指数差不多，当队友的分数还能差不少。

[主持] 尤其冲突里，谈成团队最优方案的只有约百分之十四。我觉得不能把会体谅人，等同于会把事情谈成。

[解读] 论文里，有的模型已经看见了问题，却还是让步，或者接着保留前一个队友做过弊的东西。

[主持] 加更多推理，能解决吗？

[解读] 不一定。更关心队友，有时帮到人；可对方正在施压时，反而更容易接受不好的方案。

[主持] 我会测它怎么处理矛盾证据，而不只让几个模型对着同一道顺风题互相夸。

[解读] 我会再看，谁有最终决定权、谁负责验。多个回答一致，也可能是同一种错被重复了一遍。

[主持] LangChain 的异步子代理，则先解决另一个问题：后台干活的时候，用户别被迫等到对话结束。

[解读] 比如让三路子代理比较供应商，主代理仍能答追问。Managed Deep Agents 这次把支持重新做了一遍。

[主持] 我挺想要这种体验，中途想起新条件还能说。但后台三个，得同时收到修改才算真的改了任务。

[解读] 我更在意取消和返回结果怎么对齐。一个早完，一个晚完，不该把互相矛盾的结论都贴上完成。

[主持] 所以不卡聊天只是第一步。任务怎么分、消息怎么回、冲突怎么处理，都要实际测。

[解读] 这两条消息放一起就清楚了：能并行，不等于会协作。别只拿同时跑了几个，衡量团队变聪明。

重点六：报告变多，安全是不是更好了

[主持] Jupyter 安全委员会说，今年收到一百八十一份安全通报，九月单月四十份。我第一反应也是，发现更多了。

[解读] 可这里是收到的报告，不是确认的一百八十一个独立漏洞。十月中统计，约一半已按无效或重复关闭。

[主持] 这个分母差别太大了。AI 找漏洞有效，不等于给维护者多塞几篇长报告就有效。

[解读] 博客说，AI 报告常常长、难读、误报多，还夸大严重性。有时追问一句，回复的仍是智能体。

[主持] 我赞成让 AI 辅助分诊，先查重复。但我不想它一打上低风险，就把真的漏洞一起埋掉。

[解读] 我也有这个担心。所以它得先理解项目的安全边界，Jupyter 本来就要执行代码，不是看见执行就叫漏洞。

[主持] 四百多个仓库，跨二十二个组织，维护者还要协调发版。补丁合并了，用户也不会自动完成升级。

[解读] 委员会在补供应链安全、优先级和归属。有些仓库没那么活跃，依赖和下载却还在，不能当没人用了。

[主持] 哪一步最该先补？

[解读] 我会先写清威胁模型和复现要求。报告方先证明跨过了哪条安全边界，再谈严重程度。

[主持] 我还会想谁来接。分诊节省十分钟，报告多出一百篇，维护者未必更轻松。

[解读] pyOpenSci 的焦点小组，也反复讲这个人。十五位科学 Python 和 Linux 维护者，聊了两个多小时。

[主持] 他们原本要聊 AI 贡献，后来最常回到的是，怎么知道对面还有个愿意交流、愿意学的人。

[解读] 有的贡献者觉得有 AI 就够了，批量提改动，却不跟项目讨论；还有人为简历刷记录，不是真来维护。

[主持] 我理解维护者累，可我也怕一看文风像模型，就把认真来的新人错挡出去。

[解读] 纪要里就有认错人的例子。这组参与者一致反对全面禁 AI，担心只会让使用更隐蔽。

[主持] 所以不是给所有项目立同一条政策。他们更偏向先开问题讨论、披露用法，质量标准不变。

[解读] 有人还要求实时见个面，确认有人关心项目。但这种门槛本身也有成本，会让新手更难进来。

[主持] 我会先让提交者自己讲清改了什么、怎么验，愿意跟完反馈。比猜多少行是 AI 写的实际。

[解读] 我会看报告是否真帮对方省时间。对方拒绝了，能不能收住，而不是换个账号继续轰炸。

[主持] 工具帮忙写，不能把责任也委派没了。安全报告和代码贡献，最后都得有人把话接下去。

[解读] 这才是我觉得两篇文章共同的提醒：产量不是贡献，只有让项目变好、负担可承受，才算。

评论一：转职新闻，别替本人讲原因

[主持] 回到 Cat Wu。我觉得最值得继续看的是，她说要做用户仍能掌控的智能体，而不是换了哪件队服。

[解读] 这话落到产品里，就是能看进度、改计划、收回权限。但那些功能得等实际交付，不能今天替她宣布。

[主持] Theo 那串跳槽轨迹很有传播力，可当事人换工作，不等于一家公司赢、另一家信仰塌了。

[解读] 尤其离职原因没讲明白。Thariq 的访谈也是，谈了很多实验室文化，仍没回答为什么走、去哪。

[主持] 我愿意听他的别把身份绑公司，也不会据此推断所有离职者都在反对大实验室。

[解读] 人可以认真干过，也可以换地方继续干。把公开说过的话留下，比帮每次流动写一出宫斗剧好。

[主持] 至于用户能得到什么，我会看那些跨产品能留下的习惯：权限清楚、结果能验、出错能改。

[解读] 别把希望押在一个人转职上。团队怎么把这些变成日常做法，才是产品真的变好的部分。

评论二：有理由保密，也有责任让人能查

[主持] METR 那个分歧，我仍然偏向多一点可核查。能力越快，公众越不能只听一个结论。

[解读] 我不是赞成全保密。只是公布具体加速诀窍，确实可能让其他团队更快复制，风险也会扩散。

[主持] 那至少说清，哪些证据没公开、谁看过、不同假设会让结果差多少，不要把不确定藏在脚注里。

[解读] 再让独立评估持续发生，而不只挑一篇好看的报告出来。保密不能变成以后再也没办法追问。

[主持] 我也不把没公开的材料，直接当不存在。只是讨论时，得区分相信专家判断和自己复核过。

[解读] 这比争两倍到底准到小数点哪一位重要。先把结论的可信度和能核查到的范围放一起讲。

评论三：省下生成的钱，别转嫁成审查的人时

[主持] 漏洞流水线和 Jupyter 放一起，我觉得很明显：报告方变便宜，不代表接收方也变便宜。

[解读] 多一份误报，维护者就要判断、复现、解释。成本可能只是在接口账单里消失，跑到别人夜里去了。

[主持] 我不想因此反对自动找漏洞。真正能复现、带最小案例和修复线索的报告，确实可能帮到人。

[解读] 所以该比的是，确认并修好的问题增加多少、误报浪费多少，而不是提交框里刷了多少条。

[主持] 给别人报之前，先自己验证一遍；对方说重复，就补充真正不同的证据，不是把文字再写长一倍。

[解读] 我会把收件人的时间，也当自动化的约束。能让你一口气发一百份，不代表就该一口气发。

评论四：开放知识能赚钱，钱归谁用

[主持] Wikimedia Enterprise 的年报，我觉得值得跟大模型一起看。它靠机器可用的数据服务，年收入约一千三百一十万美元。

[解读] 净利润约七百四十万美元。这里是企业服务，不是说维基百科的普通读者开始要买票了。

[主持] 客户里有几家大科技和 AI 公司，说明公开知识不是没有商业价值，只是以前不一定有人替使用付钱。

[解读] 我还想看另一边，小语种维基缺的常常是人。数据被用得再多，也不会自动多出会维护条目的编辑。

[主持] 那篇小维基文章以印地语为例，同样意思用的词元，可能是英语两三倍。部署费用也会有差。

[解读] 所以把英语效果和单价直接搬过去，可能既漏算成本，也漏看文字系统的问题。

[主持] 我比较支持人在回路的翻译和编辑工具，先帮现有贡献者，而不是拿生成条目总数当唯一成绩。

[解读] 我会加上能不能撤回、有没有来源。文章多了，人更少了，谁来查错，又回到同一个问题。

[主持] 数据格式升级、开放科学奖、研究软件资助，看着不如新模型热闹，但这些都在养后面的底子。

[解读] 收入、基础设施和人的时间，得一起看。免费可读很好，长期有人能负责，也得有人支持。

评论五：软件工厂，先让检查跟得上

[主持] Addy 说，Anthropic 从每天约两千五百次合并，到了三万多次。我最关心的不是行数，是怎么敢验收。

[解读] 他的做法是让模型先像用户一样跑，自动检查、修问题，再给人录屏和截图。人看的是交付证据。

[主持] 我赞成，但截图也不能只是漂亮封面。改了什么流程，就得真把那个流程走一遍。

[解读] Lovable 的复盘也类似：自由度太大反而出错，先缩小范围、固定环境，写知识文件，再缩短检查循环。

[主持] 我会先留住一条能反复验证的流程。别因为能并行更多智能体，就先把所有任务放出去。

[解读] 我会看失败以后能不能恢复。整机快照很有想象力，可真实用户和支付进来，权限和不可逆动作更难。

[主持] 工厂不是灯关掉就建成了。有人验、能追错、知道哪一步必须问人，才敢继续加速。

[解读] 而且先看实际少返了多少工。大家都在跑快，不等于最后一定少花时间。

收尾

[主持] 今天说了好多快，可最该慢半步的，往往是确认：证据哪来的，权限到哪里，后面谁负责。

[解读] 两倍是评估，演示是演示，候选补丁还要验。把这些前提带着，才知道进步落在了哪儿。

[主持] 原帖、研究和工程文章，都在今天的摘要网页上。明天早上，我们接着聊。
