今日要点

Google 发布 Gemini 4 系列首个模型 Argon，Vals Index 第三方榜单以微弱优势登顶，评测者认为它首次让 OpenAI、Anthropic 之外的模型跨过前沿门槛。AI 写代码的规模正在倒逼基础设施重构：Anthropic 因每日合并量从约 2,500 次涨到 3 万次以上而自研版本控制系统 Scion。与此同时，模型路由与成本成为 Agent 工程的焦点：LangChain 路由实验成本降 64%，Agents on Rails 评测中 GPT-6.1 Sol 以约 1/13 的成本接近 Opus 5.5 的成功率。

模型发布与评测

  • # Google 发布 Gemini 4 Argon，第三方榜单小幅领先
    Argon 是 Gemini 4 系列首个模型，主打代码、金融、法律、网络安全和科研等多步复杂任务，已向 Gemini API 付费层、Gemini App 的 Pro/Ultra 会员以及 Antigravity 的 Ultra 用户全球开放，API 免费层不提供。引入价为每百万 token 输入 2 美元、输出 10 美元（缓存 0.1 美元），12 月 1 日起翻倍；上下文为 1,048,576 token，输入、思考与输出共用，另有可接力生成的“长输出”模式。第三方 Vals Index 上 Argon 以 68.90% 排第一，领先 Claude Sonnet 5.5（67.04%）和 Opus 5.5（66.97%）不到两个百分点；Logan Kilpatrick 称上线前一个月已有超过 10 万名 Google 员工试用。
    来源：宝玉 @dotey · Logan Kilpatrick @OfficialLoganK
  • # Ethan Mollick 上手评价：首个跨过前沿门槛的非 OpenAI/Anthropic 模型
    Mollick 上线前用了较长时间，认为 Gemini 4 相比前代是大跃进，更好相处、更能自主完成任务，也没有 Gemini 3 系列那种怪异的性格问题，审美与 Claude、Astra 很不同。他认为它在创意和写作上至少与 OpenAI、Anthropic 持平，但在复杂多 Agent 工作上落后，容易对结论过于自信、有点“偷懒”，Antigravity 的执行框架也不如竞品。他还放出了同一提示词下 Astra Max、5.1 Max 和 Argon 各自生成的“粗野主义城市建造”游戏供对比。
    来源：Ethan Mollick @emollick
  • # Agents on Rails 第三阶段：GPT-6.1 Sol 性价比最高
    Rails 官方的 Agent 评测新增 7 个多步任务，每个横跨 3–8 张工单，包括从零建应用和改造遗留代码库。GPT-6.1 Sol 成功率 60.8%、每次运行约 0.80 美元，综合最佳；Opus 5.5 最高强度成功率最高（65.3%），但最贵也较慢；最便宜的是 GPT-6 Luna（0.19 美元，43.5%）。DHH 转发称 Sol 与 Opus 相差不到 5 个百分点，成本却不到十分之一（0.80 vs 10.53 美元）。
    来源：DHH @dhh

AI 编程与开发基础设施

  • # Anthropic 弃用 Git，五个月自研版本控制系统 Scion
    Anthropic 工程博客称，每天合并的代码变更从 5 月约 2,500 次增至 9 月 3 万次以上，为人类规模设计的开发基础设施成了瓶颈，于是在五个月内自研新系统并把 monorepo 完全迁出 Git。按 Gorden Sun 的解读，Scion 的思路是按需从服务器拉取文件、把重计算放在服务端、只记录增量且不锁整个仓库，以支撑上万任务并发提交；项目由 7 人团队借助 Claude 完成。
    来源：Gorden Sun @Gorden_Sun
  • # Google Play 开放“个人 App”：AI Studio 写的安卓应用可直接装到自己设备
    10 月 13 日起，用 AI Studio vibe coding 做出的安卓 App 可通过 Google Play 无线安装到自己的手机、平板等设备，只需普通 Google 账号，不用交 25 美元开发者注册费。首批覆盖包括美国在内的部分市场、限 18 岁以上，应用仅自己可见，分享给亲友的功能将在未来几个月推出；自用阶段是否审核、安全如何保障，官方未细说。同日还上线了 Ask Play 应用对比、Play in Gemini 和 Game Finder 等功能。
    来源：宝玉 @dotey

Agent 与工程实践

  • # yetone 公开 Magpie 维护工作流：3 个并行 /loop 让 AI 自主运维开源项目
    yetone 用 Claude Code 加 Opus 5.5 并行跑 3 个 /loop：一个盯 GitHub issue/PR 和 Discord（PR 要逐行审并实际运行再合并），一个监听推特反馈并先用便宜的判断模型 Jev 过滤无关内容，一个定期清理“屎山”代码、记录经验教训并拉黑低质量提交者。他自己每晚只处理 UI/UX 问题。宝玉总结的关键前提：AI 要在 Mac、Windows、Linux 三端真实复现 bug，并依靠早期写进记忆和设计文档的偏好来做决策。
    来源：宝玉 @dotey
  • # Harrison Chase：模型路由应放在 Agent harness 而非网关
    他认为路由器应放在运行 Agent 的 harness 里，因为只有 harness 知道任务上下文。他引用的 LangChain 实验中，开源编程 Agent Open SWE 把每个线程交给最可能完成任务的最便宜模型，在 973 个线程上与全程用 GPT-6 Astra 对比：中位成本 0.94 vs 2.61 美元（降低 64%），合并 PR 比例 29.2% vs 27.3%（p=0.49，差异不显著）。始终用快速模型的对照因质量差一天内就停了，LangChain 也说明路由器还只是概念验证。
    来源：Harrison Chase @hwchase17
  • # Anthropic 反蒸馏文章的“避封”启示
    歸藏认为不少刚注册就被封的账号是被误判为在蒸馏模型。他据文章总结的建议：不要诱导 Claude 展示或反复索取思维链，不要搬运或篡改其思维链；账号注册与付款渠道要干净，避免代理 IP 和转售账号；不要在同一个 Agent 环境里混用国产模型和 Claude。
    来源：歸藏 @op7418
