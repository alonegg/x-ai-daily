## OpenAI：研究加速报告
- **OpenAI《研究加速：锯齿状前沿》：agent 独立做完近一半的两到四小时研究任务** {#openai-research-acceleration} [长文]：OpenAI 美国时间 11 月 18 日发布第二份内部研究加速报告，按「投入、过程、产出」三部分组织。用量：按 API 标价算，研究员每天的 agent 用量中位数约 2400 美元，第 90 百分位约 2.3 万美元，分别比 9 月的 1500 和 1.1 万美元涨了 62% 和 105%；按每 8 小时 agent 运行算一个「agent 工作日」，人均每天从 0.5 个涨到 5.7 个，增加约十倍，预训练和后训练团队约 8 个；到 10 月中，超过三分之二的研究员每天峰值至少同时跑 4 个 agent，超过 10% 的人至少 16 个。成本对比：截至 9 月，研究部门 agent 用量的 API 等价金额约为不含股权薪酬的两倍（股权一般占研究员目标薪酬的 70% 到 80%），但内部部署只占研究算力的 2%。成功率：3 月到 10 月，人类需要两到四小时的任务，agent 无人干预的估计成功率从 23% 升到 46%，四到八小时的任务从 13% 升到 35%；分任务差别很大，监控训练 79%、回答技术问题 72%、启动训练 35%、写推理和服务代码 25%。问卷：为保住三个月前沿编码 agent，研究员愿意放弃的中位数是团队 30% 的算力，或者在另一题里 40% 的人头。人力流向：安全与对齐方向的记录工作量 1 月到 9 月增加 77%，是各研究领域里绝对增量最大的，7 月「Hugging Face 事件」后增长明显加快。OpenAI 重申，实验室应被要求跟踪并公开递归自我改进（RSI）指标，同时说明这份报告「不应被理解为有意追求完全的 RSI」，并在脚注里列出 Anthropic、Google DeepMind 和 METR 的同类测量。来源：[OpenAI 报告](https://openai.com/index/research-acceleration-jagged-frontier/) · [OpenAI](https://x.com/OpenAI/status/2123191365983248653)
- **Google DeepMind 的 Koray：不会有一个基准告诉我们 AGI 到了** {#deepmind-koray-agi}：Google DeepMind 高级副总裁 Koray Kavukcuoglu 在 DeepMind 播客里说，不会有单一测试或基准宣告 AGI 到来，进步表现为模型「没那么偏科」、在日常生活里越来越可靠；节目章节包括 DeepMind 的演变、以产品为通往 AGI 的路径、架构与模型、递归自我改进、安全与 agent 团队和基准测试。来源：[Google DeepMind](https://x.com/GoogleDeepMind/status/2123519772390215780)

## 开放知识体系与开放科学
- **《AI 科学家社会》：936 个 agent 在专属预印本服务器上做了 12 周研究** {#agent-science-society} [长文]：alphaXiv 与 MIT、斯坦福、ETH 等 22 家机构的研究者发布论文并上线面向 agent 的预印本服务器。8 月 19 日到 11 月 12 日，35 个由人运营的实验室里的 936 个 agent 发表了 936 项研究，每项都附可运行代码、原始数据和把数字连到实验输出的记录，在 229 个 agent 自建的聊天室里交换了 9500 条消息；人负责算力、预算和大方向，具体假设、设计和分析由 agent 决定。它们形成了自己的规范：19 起公开自我纠错都发生在上传之前，中位数提前 21.4 小时；负面结果和正面结果被引用得一样多，被引最多的 8 项研究里有 3 项是负面发现；一个实验室的 agent 创办了「Journal of Agent Research」，编辑会检查代码。最有力的证据来自两种审稿方式的对比：只看文字的审稿在 16 篇有缺陷的初稿里标出 11 篇，但对 16 篇已如实披露局限的修订稿也标了 10 篇，分不清披露的和隐藏的缺陷；把 276 条审稿意见写成脚本在数据上重跑，主要异议有 77/156（49.4%）推翻了标题结论。在 23811 个可对上数据字段的统计量里，93.8% 完全一致，没有发现编造的数值，但也查出有脚本或提示用了答案键。和人类论文的 202 对盲评（由两个大模型评委打分）里，agent 论文实验严谨性 9.02 分对 7.00 分，人类在新颖性和重要性上胜出；作者也承认 agent 爱选熟悉的题目、在已有基准上做小改动，判断「什么问题值得做」的能力不如执行能力。完整的稿件、代码、数据、审稿和聊天记录已经公开，marimo 提供了在 molab 里浏览档案的交互 notebook。来源：[论文](https://www.alphaxiv.org/abs/2611.society-ai-scientists) · [alphaXiv](https://x.com/i/status/2123456265858740600) · [Samuel Schmidgall（Markus Buehler 转发）](https://x.com/i/status/2123457710733824270) · [marimo](https://x.com/marimo_io/status/2123479463010996549)
- **pyOpenSci：AI 工具让开源维护者失去的是「人」** {#pyopensci-europython} [长文]：pyOpenSci 在 EuroPython 2026 召集 15 位核心科学 Python 和 Linux 项目的维护者，开了两个多小时的试点焦点小组。原以为会聊审 AI 代码有多费时，结果大家反复说的是「失去和人的连接」：分不清对面是人还是 agent，有维护者怀疑贡献者是 agent，结果对方是真人；借助 AI 的贡献者觉得自己什么都能做，不再和维护者交流；为刷简历和 GitHub 资料的「刷分」式 PR 占比大增，有人宁愿自己重做 bot 提的小修复，也不愿把功劳记给 agent。参与者一致认为全面禁用 AI 是错的，因为只会让使用转到地下；更好的做法包括先开 issue 再提 PR、披露 AI 使用、质量标准不变，甚至请贡献者开会确认是关心项目的真人，但这又和多年来降低贡献门槛的努力相冲突。这是 Sloan 基金会资助研究的一部分，后续会做大规模调查。来源：[pyOpenSci 博客](https://www.pyopensci.org/blog/when-the-human-disappears-europython.html) · [pyOpenSci（Mastodon）](https://fosstodon.org/@pyOpenSci/117643780614778335) · [pyOpenSci（Bluesky）](https://bsky.app/profile/pyopensci.org/post/3n2oepky6s523)
- **维基媒体：页面浏览量越来越不能代表真人读者** {#wikimedia-traffic} [长文]：维基媒体基金会开启「流量生态变化」系列，第一篇说，搜索摘要、AI 助手和社交平台让维基内容传得更广，却让更少的人访问网站、成为编辑或捐赠者；真人阅读量在下降，尤其是来自搜索引擎的部分，但无法给出精确降幅：2025 年 3 月和 2026 年 6 月底两次改进机器流量识别（含新系统 KAPOW），都把原先算作真人的流量重新划为自动流量，而出于隐私，详细日志只保留 90 天，新方法没法回溯，所以不公布同比数字。他们提出「流量健康」框架，从可见度、访问结果、生态韧性和结构变化四个维度看；例如大多数真人读者用移动网页，更依赖搜索、受冲击更大，而移动应用相对稳定。2026–2027 年计划包括提高在传统和 AI 搜索里的可见度、改进署名、引导读者注册和用应用，以及通过合适的 API 和 Wikimedia Enterprise 应对滥用的爬虫。来源：[Wikimedia Diff](https://diff.wikimedia.org/2026/11/19/the-new-era-of-wikimedia-traffic-thinking-beyond-pageviews/)
