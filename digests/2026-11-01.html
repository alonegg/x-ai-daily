开场与头条预告

早上好，今天是十一月一号，星期天。这里是 X 每日 AI 播报，接下来二十多分钟，我们把昨天 AI 圈的事情过一遍。

先说今天最重要的三件事。

第一件，agent 的瓶颈换了地方。DeepSeek Harness 团队说，单个 agent 已经够强，现在卡住的是人，一个人通常只盯得住三到五个会话。他们公开了一整套让 agent 常驻、并行、主动干活的设计。

第二件，一条爆料被网友当场拆穿。有人在网上兜售所谓 Claude 旗舰模型的权重，结果文件和 DeepSeek 免费公开的模型一模一样。

第三件，有人把一颗完整的处理器，编进了一个大模型的权重里。模型不调用任何外部工具，自己在内部跑程序。

另外，评论环节还会聊一篇关于 AI 时代开放科学的长文，里面有 Jupyter 联合创始人的一段话，很值得听。

快讯

下面是快讯。后面重点和评论要细讲的，这里先跳过，只说其余的新鲜事。

先看模型和研究。有开发者把一个二十亿参数的全模态模型，完全放在浏览器里本地运行。它能听、能看、能说，不需要单独的语音识别和语音合成，第一段声音不到零点二秒就出来了。

腾讯放出一个可以交互的世界生成模型，用文字和镜头控制，一段一段往下生成，模型和数据都公开了。

英伟达昨天开源了三样东西。一份印度语言的预训练数据，覆盖二十二种语言。一个只有不到一千万参数的语音降噪模型。还有一个给数字人和机器人用的动作生成模型，给出前后几个关键动作，它能补全中间的过渡。

论文这边，有一项研究不改模型权重，只更新外部记忆，在五个数学发现任务上都赢过了测试时训练，计算量最多省下八成以上。还有一项机器人研究，让世界模型能倒带，回到关键决策点，试另一种做法，再从差别里学习。

模型性格也有新观察。有人画出各家模型的性格画像，发现 Kimi 和另一个模型几乎重合。沃顿商学院教授 Ethan Mollick 补充说，几家大的闭源模型彼此差别其实很大。

再看开发者工具。知名开发者 Theo 说，他听朋友的建议，把 Opus 五点五的推理档位从最高调低一档，几乎所有时候效果都更好。另一位知名开发者 swyx 也说，低档位加一个让模型自我批评的循环，胜过各种超高档位。

Theo 还在做一个电脑操作测试，看 AI 在不同操作系统上完成任务的成功率。目前苹果系统垫底，只有百分之二十七。他还和另一位网红程序员争了起来：对方夸谷歌的新模型 Argon 四，Theo 说它在真实代码库里幻觉严重，差的不是一点，是十倍。

中文开发者圈，DeepSeek Harness 的插件很热。宝玉把 Claude 的设计工具做成插件搬了上去，还给自己的设计工具加了局域网共享，同事可以一起评论和编辑。AI 博主归藏把自己的几个设计 Skill 合成一个插件，新加了针对中文排版的网页排版功能。

其他小更新：Theo 的编程工具 T3 Code 加了旁聊功能。独立开发者 yetone 开源了 Alma 的中继服务器，端到端加密，中继只看得到密文。Rails 作者 DHH 把一个本地运行的语音输入工具，加进了他做的 Linux 发行版。

关于 agent 怎么搭，LangChain 创始人和同事唱了一出对台戏。有人说 agent 工程已经有标准答案，没意思了。他的同事反驳说，好的外围框架，也就是 harness，本身就是产品的核心竞争力。

Ethan Mollick 也说，个人 agent 现在最大的问题是看不清：你不知道它在干什么、知道你什么、会替你做什么。他自己对重要任务，更愿意定时跑本地的 Codex，因为能随时改提示词。他还说，遗留系统迁移这个市场一年大约三百亿美元，现在一批原来嫌贵的迁移项目，正在被 AI 很快释放出来。

Anthropic 用 Claude 重写后端的故事也有后续。有人总结得很好：agent 不需要值得信任，它只需要一个糊弄不了的裁判。写代码几乎免费以后，贵的是验证。

再看产品和行业。苹果智能要在国内上线了，更聪明的 Siri 由阿里千问驱动。归藏估计会在十二月随系统更新推送，他觉得实时翻译这些功能更有用。

谷歌 DeepMind 做了一个帮英国政府审批建房申请的工具，规划官员审一份住户申请的时间，最多能省一半以上，现在推广到另外十二个地方议会。团队还为万圣节，从一句英文提示出发，让 AI agent 设计并造出一台会跳舞的南瓜灯机器人。

Meta 的 Muse 语音模式据说上周已经悄悄上线，有用户说非常好用。另外，有中文用户发现，Grok Bot 已经可以用支付宝和银联卡付款。

OpenAI CEO 奥特曼有一段话被翻出来：在资源紧缺时，让每个人在电脑里放大量内存跑本地模型，却只用百分之五的时间，是一种浪费。这个观点，我们在评论环节会拿来对照。

最后是开放科学和 Jupyter。伦敦的 Connected Data 大会有一堂两小时的实操课，带大家用 Jupyter 或 Colab 从真实网页建知识图谱，做图检索增强问答。一款叫 Junoview 的幻灯片工具更新了：notebook 重跑以后，按一下更新，幻灯片上的图就换成新的，还会先把新旧两张并排给你看。PHP 语言也有了自己的 Jupyter 内核。Wikidata 过了十四岁生日，说达格巴尼语的一个维基社区办了编辑活动。雅加达的维基社区和一家电台合作，把当地方言的词汇录成节目，再收进维基词典。麻省理工的科学 AI 黑客松也正式开幕了。

重点一：一个人能盯几个 agent，DeepSeek 给出系统答案

为什么重要？因为 agent 越来越能干，但人只有一双眼睛。下一阶段的竞争，是谁能让一个人同时管住更多的 agent。

DeepSeek Harness 团队发了一篇工程文章，一位中文技术博主做了详细整理。他们的判断是，单个 agent 已经够强，瓶颈变成了人的注意力。一个人通常只能跟住三到五个活跃会话，多了就乱。

他们想做的叫 Super-agent。目标有四个：连续，在聊天软件和代码平台上像同一个人；高效，能并行干好几件事；主动，自己观察环境，该出手才出手；持久，一直在线，出了错能自己恢复。

怎么做？核心是两层。上面一层叫路由，常驻在线，负责和人说话、分派任务，可以用便宜一点的模型。下面一层叫工人，每个工人只干一件事，上下文互相隔离，用最强的模型。工人不直接对外说话，进展都报给路由，由路由统一回复。

他们还把驱动方式改了。不再等人一条条打字，而是把群聊、邮件、日程、代码评审这些事件当输入。先用简单规则过滤噪音，再交给模型判断。同一个代码合并请求的后续消息，直接转给负责它的工人，不再绕路由。外面还有一个看门狗，定时检查每个工人有没有真进展。

他们做了模拟测试。大约三百条消息、二十个工作请求，这套设计完成任务的时间，最慢的情况大约十六分钟。对照组是一个会话加子 agent，最慢要接近半小时。

我们的看法是，这篇文章最有价值的，是它坦白的未解问题。会话对人隐藏以后，人怎么中途介入？云端常驻加本地执行，攻击面怎么控制？文章自己说，安全隐私解决不了，这种系统只能在很小的可信范围里用。数字来自合成负载，不是真实生产，参考就好。

重点二：自动红队、假冒扩展和一个新开关

为什么重要？因为 agent 和插件拿到的权限越来越大，攻击和防御都在自动化。

先说 Anthropic 的新研究。红队测试，就是专门扮演攻击者，找模型的安全漏洞。过去这件事受限于研究员的时间。Anthropic 这次让几千个 Claude agent 去做一件事：生成能骗过训练数据监控器的数据。

结果很吓人。这些 agent 造出的训练数据，看起来完全无害，比如一位老摔跤手带新人，或者一段专业养蜂的问答。但实际上，拿这些数据训练，会教给模型错误的行为。Anthropic 说，这些例子可以直接用来改进监控器，这只是第一步。

再说插件。前天我们讲过，Cursor 的插件市场出现了被篡改的 Claude Code 扩展。昨天，一位在 VS Code 和 Cursor 市场都发过扩展的开发者说，拿到认证发布者的徽章非常容易，只要在自己的域名上放一个文本文件。任何人都能仿冒大公司的品牌，而扩展装上以后，能执行代码、读你的仓库、跑终端命令。

同一位开发者测了 Claude Code 新加的一个开关：禁止写工作目录以外的文件。写和编辑都被拦住了，但通过命令行还是能写出去，所以要同时打开沙箱。他后来又推荐了配套的开关，禁止读取工作目录以外的文件。

我们的看法是，攻击者用 AI 批量造看似无害的数据，防守方也只能用 AI 批量找。普通开发者能做的，是把自己能控制的边界收紧。

重点三：AI 原生的公司长什么样

为什么重要？因为两家一线 AI 公司，同一天公开了自己内部怎么干活，细节很具体。

先看 Manus。宝玉推荐并提炼了他们的一手分享。第一，工程基础设施从对人友好，变成向 AI 开放接口：让 agent 能读线上日志、看报警、自己跑端到端测试。第二，人对 AI 不再微管理，而是只给目标、要证据。工程师把 Slack 里的需求原文直接丢给 agent，让 agent 用测试账号走完注册和支付，全程录屏。第三，工程师一个人同时开十到二十个会话。

结果是，七个人维护四个应用，所有产品经理都提交过代码，一半能自己上线功能。他们的产品经理甚至用 AI 把需求做成视频，当作需求文档交出去。宝玉觉得，直接做成能点的高精度原型会更直观。代价是每人每月大约一万美元的 token。他们说，买的是时间和注意力。

再看编程工具 Amp。这家二十一个人的公司，允许人人直接把代码推上主干，不强制评审。怎么防止垃圾代码？他们说靠文化：每个人直接对客户负责，自己维护自己写的东西，敢当面说这是垃圾。他们还说，严苛的代码评审，挡住的 bug 看得见，拖慢的速度看不见。

我们的看法是，两家说的其实是一件事：人往上移，从亲手做，变成定目标、看证据、做决定。但要注意，这两家本身就是卖 agent 的，他们的做法是理想样本，不一定适合每个团队。宝玉那句话说得好：执行可以交给 AI，思考要留给自己。

重点四：国产文字识别模型，三家各有所长

为什么重要？因为把 PDF、扫描件变成可用的文字，是很多 AI 应用和科研数据整理的第一步。

一位中文技术博主横向对比了三个刚发布的模型。OCR 就是光学字符识别，把图片里的文字读出来。

第一个，面壁智能的 MiniCPM OCR，十三亿参数，强项是速度和工程完整，适合批量流水线。第二个，小米的 OCR 模型，只有八亿参数，单页解析分数最高，还能回答关于文档内容的问题。第三个，百度的 Unlimited OCR 二，专攻一两百页的长文档一次读完，跨页的表格也不断开。

他的建议是按场景选：单页、要理解，看小米；批量、要速度，看面壁；整本书、整份合同，看百度。

同一天，腾讯也发了一个五十亿参数的模型，能把文档、图表、音频、视频统一解析成结构化数据。

我们的看法是，这些分数都是各家自己报的。真正选型时，拿你自己最难的那几页文档去试，比看榜单靠谱。

重点五：欧洲开始向外国 AI 收钱？

为什么重要？因为税收会改变 AI 公司在欧洲的成本，也会影响用户能用到什么。

昨天的节目里说过，法国议会通过一项修正案，打算按数据流量收税。昨天，预测市场平台 Polymarket 发帖说，德国一位部长提议对 AI 创造的所有经济价值征税。知名独立开发者 levelsio 评论说，欧洲国家养老和福利开支吃紧，会不断向外国公司要钱。他后来又说，意大利在提议退出税。

他转发了一篇长文，作者是一位加密领域的投资人，观点很尖锐。他说，AI 让收入从劳动者流向资本，而欧洲的税主要收在工资上。替代欧洲白领的，又是加州的 AI 公司，于是没有东西可收。他预测欧洲会三管齐下：禁止 AI 提供医疗法律建议，扶持本土模型，向外国 AI 公司收罚款，而且都不会太奏效。

我们的看法是，德国的提议目前只是一句来自预测市场账号的消息，我们没看到具体方案。那篇长文是一家之言，带着明显的立场。但它提出的问题是真的：如果 AI 替代的是本国劳动，赚钱的是外国公司，税基会怎么变？这个问题，不只欧洲要面对。

评论一：AI 时代，重看开放科学

下面进入评论环节。我们会讲清楚原文说了什么，也会明确说出我们自己的判断。

第一条，我们按原文的四个论点拆开讲。

这是一篇长文，作者 Carly Strasser 做了多年开放科学，当过工具开发者、资助方和顾问。她说自己以前有点狂热，现在改了说法：科学第一，严谨是目标，开放是通往严谨的路。

论点一，开放模型。她引用了 Jupyter 联合创始人 Fernando Pérez 的采访。Pérez 说，大型前沿模型对很多真实任务完全是大材小用。他还说，我不想要一个科学的未来，是给某一家公司交订阅费的未来。在他看来，自己运行开放模型，就不用靠公司的承诺来保证数据安全。另一位作者估计，开放模型大约落后前沿六个月。

论点二，所谓可供 AI 使用的数据。现在的问题不是数据太少，而是太多。谷歌数据集搜索每个月能发现大约两百万个新数据集，缺的是告诉你哪些数据适合哪种用途、值不值得信任。

论点三，怕被抢先。前沿实验室想收集你输入的一切，开放数据又在被机器人大量抓取。她提醒，本地工具不等于本地模型，要看清数据到底有没有离开实验室。

论点四，AI 反过来让开放更容易。很多不写代码的科学家，已经让 AI 帮忙写数据清洗流程。她希望有人做共享的技能，专门帮研究者整理数据、存进仓储。

我们的判断是，这篇文章和奥特曼那段话正好构成对照。奥特曼从全球资源效率出发，主张集中到云端。Pérez 和 Strasser 从科研自主出发，主张掌控在自己手里。两边都有道理，但对科研来说，可复现和数据主权，比资源利用率更根本。

给你一个具体建议：这周挑一个你常做的数据分析任务，试试用一个本地开放模型来完成，记下它和前沿模型差多少，这个差距可能比你想的小。

评论二：一条爆料，四步核查

第二条，我们按核查的步骤来讲。

事情是这样的。一个专门转发黑客论坛动态的账号说，有人声称从亚马逊云上一个权限没设好的存储桶里，拿到了 Claude 旗舰模型 Fable 五权重的一个分片，大约七 G，正在出售。他说完整模型有六百四十个分片，总共八 T。这个账号自己也注明，说法未经证实。

宝玉整理了网友的反驳，一共四步。

第一步，比对文件。有网友说，截图里每个文件的大小和内容，都和 DeepSeek 十月十七号刚开源的模型的一批分片完全一样，任何人都能免费下载。宝玉去查了，那些分片大小确实大约七点四 G，对得上。但他也说，自己没看到卖家截图，没法逐字节比对。

第二步，查地点。卖家材料指向斯德哥尔摩的数据中心，但亚马逊的文档显示，那里调用这个模型时，请求会被转到别的地区处理，当地本身不运行它。

第三步，算数字。六百四十片乘以七点四 G，大约四点七 T，和卖家说的八 T 差了三千多 G。

第四步，看常识。就算是真的，六百四十分之一的权重也跑不起来，好比一套六百四十卷的百科全书只拿到一卷。另有网友发现，发帖的论坛账号这个月才注册。

我们的判断是，这件事最值得学的，是核查的方法：比对公开文件、查官方文档、算一遍数字。每一步都用的是公开信息。宝玉还特意写明哪一步他自己没能验证，这种分寸很难得。截至昨天上午，Anthropic 和亚马逊都没有回应。

给你一个具体建议：下次看到泄露类的爆料，先别转，花五分钟算一算里面的数字能不能对上。

评论三：把处理器编进模型里

第三条，我们像拆论文一样讲。

这个项目叫 Qwenputer。作者用编译器，把一颗完整的处理器，写进了阿里千问三点五、四十亿参数版本的权重里。原来的权重一点没动，只是在前面加了十一层计算机。

它用什么当内存？千问三点五有一种特殊的层，会在内部保存一个状态。作者把这个状态当成可以按地址读写的内存来用。于是，模型在生成文字的过程中，就能跑 C 语言和精简版的 Python，不调用任何外部工具。

效果怎么样？在 DeepMind 的数学题上，原模型正确率大约五成半到九成，外接 Python 工具是九成五以上，Qwenputer 跟外接工具差不多。在超长整数计算上，原模型不到一半，Qwenputer 全对。作者说，跑了大约一千八百万条指令没有出错，对普通文字的影响几乎为零。

代价也很明显。模型文件变成原来的两倍大，每条指令要生成好几个 token，大一点的计算要好几秒，还得用专门的驱动程序。

我们的判断是，这是一个漂亮的实验，但方向值得想一想。对科研和自动化来说，计算放在一个看得见、能复查的环境里，比如一个 notebook，好处是每一步都能留下记录，别人能复现。把计算藏进权重，准确率是上去了，可检查性却下降了。作者自己也提到，后续研究关心的正是有人可能把推理藏进模型状态，逃过监控。

给你一个具体建议：如果你在设计 agent 的计算流程，坚持一条原则，能留下可执行记录的计算，就别让模型在心里算。

评论四：Proton 道歉之后

第四条，我们正反两面都讲。

昨天的节目里我们聊过，隐私公司 Proton 的技术负责人发了一份 AI 备忘录，引起员工反弹。昨天 Proton 发了正式声明。

声明说了四件事。第一，公司没有在员工电脑上装软件统计 AI 写了多少代码，那是对设备管理软件的误解。第二，用 AI 不会牺牲安全，过去一年反而加了安全审查。第三，会公开内部怎么用 AI，包括开源几个内部工具，公布代码审查和安全审查的流程，以及哪里允许用 AI、哪里不允许。第四，不会就 AI 使用重新面试员工，也不会因此裁员。最后，他们道歉了。

Rails 作者 DHH 的反应很不一样。他说其他都合理，唯独不该承诺不因抗拒 AI 而裁员。拒绝执行公司战略，当然该被开除，这就是工作，这就是工资的意义。他还说，别道歉，道歉对暴民永远不够。

正面看，Proton 选择了公开流程，让外界不只看最终的开源代码，还能看代码是怎么产出的。这对一家靠信任吃饭的隐私公司，是对的方向。

反面看，DHH 说出了很多管理者心里的话：公司定了方向，员工就该跟上。

我们的判断是，DHH 混淆了两件事。拒绝执行战略，和对执行方式提出安全顾虑，不是一回事。此前的报道里，有员工建议新代码上线前做几天渗透测试，被当众嘲讽。如果这种声音都被当成抗拒，那最先丢掉的，恰恰是一家隐私公司最值钱的东西。

给你一个具体建议：如果你在团队里推 AI，把哪里可以用、哪里不能用、为什么，写成一页纸公开出来。规则清楚，争议就少一半。

评论五：订阅、第三方工具和一笔 token 账

最后一条，我们从用户体验讲起。

前天 Anthropic 把两百美元的套餐改名 Ultra，取消了五小时限额。昨天有三个后续，都和用户的实际体验有关。

第一，宝玉澄清了一个常见误解。旧名字叫二十倍，指的是每五小时的限额是 Pro 的二十倍，而每周总量一直是 Pro 的十倍。

第二，开源编程工具 OpenCode 宣布，可以直接用 Claude 订阅登录。Theo 说没想到，Anthropic 对订阅的控制松了一点。

第三，独立开发者 yetone 的工具 Magpie，改了接入 Claude Code 的方式。以前用的是命令行的单次调用模式，现在直接驱动 Claude Code 的交互界面。原因是有人发现，在五小时窗口下，单次调用模式要多花两倍的 token。改了以后，额度消耗和直接用一模一样，也几乎不会被识别成第三方使用而封号。他说自己一开始不太情愿，因为工作量大，流式输出也没法做到完美。

我们的判断是，这三件事放在一起，能看出一个趋势：第三方工具和官方之间，正在从猫鼠游戏走向有限的合作。但规则仍然由平台说了算。yetone 那句话很实在，他不确定 Anthropic 以后会不会有别的区别对待。

给你一个具体建议：如果你通过第三方工具用订阅额度，这周对比一下，同一个任务在官方界面和第三方工具里各花多少额度。

  • #DeepSeek Harness 团队：Super-agent 设计探索长推
    meng shao

    meng shao 整理团队的工程文章。出发点：单任务 agent 已经够强，瓶颈变成人的注意力，一个人通常只能跟住约 3 到 5 个活跃会话。Super-agent 要做到四点：连续（IM 和 GitHub 评论里像同一个 agent）、高效（并行多任务）、主动（持续观察环境，该出手才出手）、持久（常驻、能自愈）。

    五个模块：一是双层架构，常驻的 Router 负责与人交互和全局协调，可以用更轻的模型、甚至不挂 Bash，Worker 上下文隔离、挂满工具、用最强模型，只向 Router 汇报；二是事件驱动，程序规则先过滤噪音再交给 LLM 语义判断，同一 PR、话题或邮件串的后续事件直通对应 Worker，上下文窗口当缓存，长内容折叠成摘要和续读入口，还会「投机执行」，比如群里讨论 bug 时后台静默复现；

    三是异步 ReAct，耗时工具改成 start/stop，结果事后作为事件投回，文中说 DeepSeek Harness 已实现但未默认开启，IM 回复不超过约 100 词；四是计算、状态、环境分离，循环放云端无状态容器、状态进数据库，端侧只跑轻量 daemon；五是外部 Watchdog，定时检查基础设施，也用模型判断 Worker 是否有实质进展。

    Richard Sever 在 Bluesky 推荐了这篇 10 月 20 日的文章，并说「数据需要计划，而不只是倾倒」。作者做了多年开放科学（工具建设、资助、顾问），借 Casey Greene 的说法改为「科学第一，严谨是目标，开放是路径」。

    四个观点：一是开放模型，引用 Nature 评论《为什么科学家应带头远离 AI 超大数据中心》和 Berkeley News 对共同作者 Fernando Pérez 的采访，Pérez 说大型前沿模型对许多真实任务是「完全的大材小用」，「我不太想要一个科学的未来是给某一家公司付订阅费的未来」，开源软件和开放模型让研究者能自己掌控数据安全；共同作者 Carl Boettiger 估计开放模型落后前沿约六个月。

    二是「AI-ready 数据」，引用 Julia Lane 与 Natasha Noy 在 Science 的社论：Google Dataset Search 每月发现约 200 万个新数据集，缺的是告诉人哪些数据适合哪种用途的基础设施；NSF 的 National Data Platform 7 月获得 2450 万美元。

    三是怕被抢先：前沿实验室收集用户数据，开放数据又被机器人抓取；最干净的办法是本地运行模型，作者提醒「本地工具」不等于「本地模型」。四是 AI 让开放更容易：她 2013 年做过的 DataUp 当年没成，如今研究者用 AI 写数据清洗流程，能源部 10 月 15 日发布 Genesis Agent Skills，OpenAlex 把 70 多万个数据集关联到资助方，还有 Paper2Agent、CORE-Bench 测 agent 能否复现计算结果。

    结论：仓储、整理标准、开放模型是公共品，应持续资助。作者披露她在为 Astera 和 OpenMined 做顾问。
