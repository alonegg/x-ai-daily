重点一：黎曼猜想证明，Lean 社区正式背书

主持：重点一，接着聊黎曼猜想。Lean 社区和 Mathlib 发了联合声明，完全确信 Alpöge 的证明是对的。

解读：声明还得到了 Lean 背后的非营利组织，和 Mathlib 项目方的背书。分量比昨天那几个独立复核又重了一层。

主持：先给大家提个醒，这份证明是一个一千七百万行的 Lean 代码库。

解读：Lean 是一种定理证明器，你可以理解成，数学证明写成代码，让机器一步一步检查。

主持：昨天说过，四个检查器都跑通了。可还有个大问号。

解读：对，代码证的，到底是不是黎曼猜想本身。

主持：这次怎么补上的？

解读：社区单独写了个文件，只陈述黎曼猜想，再用两个独立工具去比。

主持：比出来，Alpöge 证明的那个定理，和 Mathlib 里专家审过的黎曼猜想陈述，一字不差。

解读：还有个细节我很佩服。有两个检查器本身带形式化证明，保证它们不会把错的证明放过去。

主持：这是防哪一手？

解读：防的是有人担心 Lean 本身的逻辑有漏洞，被证明钻了空子。检查也是在一份导出文件上跑的，碰不到源码里可能藏的恶意代码。

主持：说白了，对不对这个问题，基本问到头了。

解读：对不对是问完了，可懂不懂还没开始。声明最后也说，期待数学界来解释这里面的新思路。

主持：我倒觉得，能验证就够了。我们用计算器，也不会每次去验算它的电路。

解读：可我有点不同意。计算器算的是我们早就懂的东西。数学家要的不只是结论，是那个新想法，下一步还得接着用。

主持：李博杰转的一条帖子里，有位数学家说得更狠。

解读：那位数学家的意思是，没有人能完整读懂的证明，就没有社会意义。相信它，等于相信 AI 这个神谕机。

主持：这我不太认同。机器检查比几个审稿人看几个月，靠谱多了。

解读：检查是靠谱。但他担心的是另一件事：数学会不会变成，只有结论，没人知道为什么。

主持：所以眼下的答案是，人加模型。

解读：我同意眼下是这样。只是「暂时」这两个字，他自己也打了问号。

重点二：众议院报告，中国开源模型在美国用得有多广

主持：重点二，美国众议院国土安全委员会和对华特别委员会，联合发了份调查报告。

解读：调查从今年四月开始，主题就是美国公司为什么在用中国开发的模型，风险在哪。

主持：他们挑了三家公司当案例，第一家是 Airbnb。

解读：Airbnb 在美国的服务器上，跑定制版的千问。一个客服助手，每天处理大约八万次房客和房东的对话。

主持：另一个微调模型，每天要总结大约二十五万条客服工单和通话。

解读：第二家是做 Cursor 的公司。它的旗舰模型 Composer 二，底座来自月之暗面，而且是被独立开发者认出来，才公开的。

主持：第三家是外卖平台 DoorDash。

解读：他们有二十五个中国模型家族，是真正部署上线的，门槛是至少花了五千美元算力。

主持：想换掉也不容易。报告说，嵌在大系统里的一个模型，替换可能要半年。

解读：大盘数字也很醒目。在头部的开源模型平台上，过去一年的下载量，中国模型占了百分之四十一。

主持：美国这边，表现最好的开源模型只排第十，前面有六个是中国的。

解读：这就是为什么公司会选中国模型：便宜，能改，性能又接近前沿。报告自己也承认这一点。

主持：那报告的担心是什么？

解读：一是蒸馏。美国机构评估，有六家中国头部开发商，对美国前沿模型做过工业规模的蒸馏。

主持：还说美国的数据标注公司，每年卖给中国实验室大约五亿美元的训练数据。

解读：二是安全。报告引用评估说，智谱最新开源模型的网络攻击能力，和一个受限的美国顶尖模型差不多。

主持：安全护栏还很容易拆。

解读：原本九成五左右会拒答，估计花大约四千四百美元，就降到百分之三到六。

主持：建议里我最认同的一条，是做模型来源标准，相当于给 AI 一份配料表。

解读：这个我也认。你连系统里跑的是谁家的模型都不知道，就谈不上管。

主持：可另一条是，在联邦系统和联邦合同里，禁用中国模型和它的衍生品。

解读：这条我有保留。衍生品怎么界定？有人在这些底座上微调出自己的模型，算不算？一刀切很容易误伤。

主持：Clem Delangue 的解读是，最好的回应不是禁，是造更多美国开源模型。

解读：报告第一条建议确实是这个，搞国家级的开源模型计划。不过他只挑了好听的那半说。

主持：我倒觉得两半不矛盾。关键基础设施的替换，报告也写了要等有可信的替代品。

解读：可联邦系统那条禁令，没挂这个前提。我担心禁令跑得比替代品快。

重点三：头顶飞过的飞机，能暴露你在哪开会

主持：重点三，李博杰的新研究，开源工具叫 skyhum。

解读：起因很生活。他在加州的时候，老听到头顶有小飞机，就想：录音里的飞机声，能不能暴露录音地点？

主持：结论是能。原理其实不复杂。

解读：大多数飞机都会广播自己的位置，公开记录精确到秒。录音里远处的螺旋桨声，音调会随着靠近和远离慢慢变。

主持：就像救护车开过去，声音先高后低。

解读：对，拿这个音调曲线，去对当时附近飞过的航班，就能推出大概在哪个区域。

主持：要是飞机离得很近呢？

解读：一点五公里以内掠过，会有一声明显的峰值，能把麦克风定在航线上两个对称的点之一。

主持：准到什么程度？

解读：已经知道大概区域的话，七十五次掠过里，百分之四十三能定到一公里以内。

主持：那我们平时开会，用的都是 Zoom 这些软件，线索还留得住吗？

解读：他测了。没人说话的时候，十九次掠过，Telegram 能保住十七次。

主持：那谷歌的 Meet 怎么样？

解读：Meet 保住十三次。Zoom 的默认降噪，一次都没留。

主持：那 Zoom 反倒成了最安全的。

解读：前提是没开它的原声模式，开了也能留下十七次。另外只要有人在说话，发送前就只剩两次了。

主持：所以日常开会的录音，其实没那么容易被定位。

解读：单次确实不容易。他自己也把弱点写出来了。

主持：他承认了哪些弱点？

解读：只听一小时的哼声，三百二十七段美国录音里，只对了百分之五，还不如一直猜纽约。

主持：那真正的风险在哪？

解读：在重复。同一个地方录得越多，越容易拼出位置。澳大利亚乡村十四个地点，每个录八小时，十三个都猜中了区域。

主持：他给的防护建议也很朴素：不说话的时候就静音。

解读：模拟里，在说话停顿时，把四百赫兹以下的低频压下去。

主持：这么做效果怎么样？

解读：五十三个小时的录音，能定位的从三十二个小时，降到了四个。

主持：我的感受是，天天在同一个地方开会，还公开放录音的人，最该留意。

解读：同意。他也说，会议比播客危险，因为会议开始时间能精确到秒，播客一般只有日期。

重点四：LangChain 的知识工厂

主持：重点四，Harrison Chase 写了篇长文，讲怎么建一个知识工厂，收藏快三千了。

解读：前两天他就提过这个概念，这次是完整的做法。他开头就说，缺的不是更好的模型，是公司自己的知识。

主持：他把上下文和知识分开了。这个区分我觉得挺有用。

解读：上下文，是 agent 干活时手上有什么。知识，是能反复用的理解，比如某个指标到底怎么算，该信哪个数据源。

主持：他要维护的知识分三类：怎么做事，业务怎么跑，去哪取数据。

解读：有意思的是，数据仓库里已经可靠的数据，他说不用再存一份，只要告诉 agent 去哪查、怎么查。

主持：那这些知识谁来更新？

解读：这是全文的核心。干活的 agent 只负责报错，发现缺了或者错了，就标出来。

主持：真正动手改的，是另一个后台的策展 agent，定期跑一遍。

解读：他的理由是，让忙着干自己活的 agent 顺手改知识库，很快就会乱成一锅粥，前后矛盾。

主持：他举了个做收入报表的例子，我觉得很直观。

解读：报表 agent 发现数据库改了列名，就上报。财务负责人又当面纠正了格式。到了夜里，策展 agent 看到这两件事，把相关技能都改了。

主持：这跟快讯里腾讯那套思路挺像，干活的和管规矩的分开。

解读：我有个担心：策展 agent 自己也会出错。它一改错，所有 agent 都跟着错。

主持：可总比每个 agent 各改各的强吧。至少出了错，你知道去找谁。

解读：这点我认。所以我觉得，策展 agent 的改动，最好也留记录，让人能抽查。

主持：他转发的回复里，还有员工问，这到底是在造更好的工具，还是在训练自己的替代者。

解读：这个问题文章没回答。不过照他的写法，人的纠正，反倒成了这套系统最值钱的原料。

评论与讨论：AI 到底能独立干多久

主持：最后聊个能吵起来的。Ramez Naam 发文说，AI 圈最重要的几张曲线图，都画错了。

解读：他说的是任务时长曲线，就是看 AI 能独立完成人类要干多久的活。很多人拿它来预测超级智能快来了。
