开场与头条预告

[主持] 早上好，今天是十一月三号，星期二。这里是 X 每日 AI 播报。

[解读] 昨天最让人兴奋的，是模型不写训练循环，直接对另一个小模型的权重动手，修它的推理死循环。

[主持] 第一件就聊这个。改得少、分数涨得多，很惊艳，但不能直接说大模型已经能无限改进自己。

[解读] 第二件，Claude 的消息线程公测。长对话不用每轮重传历史，开始回答更快，但不是每轮少算了历史。

[主持] 第三件，资深开发者为什么还谨慎。Thoughtworks 让人一周不写代码，最后发现，人主要在白板前。

[解读] 应用能跑，构建却经常红。这种落差，比模型能吐多少行代码，更值得拆开看。

[主持] 还会聊 MCP 会不会和 API 合流，以及 marimo 怎么帮天文学家，让已有数据更容易被用起来。

[解读] 今天的很多进步，其实都在后半程：模型能做以后，怎么接、怎么验、怎么留住判断。

[主持] 不只追演示的第一分钟，也看看下一个用户能不能继续用。

[解读] 那先过快讯，后面把几个前提慢慢展开。

快讯

[主持] Anthropic 开放 Residency，想请有经验的学者、技术创始人和工程师，全职做一段 AI 研究。

[解读] 是付费的固定期限项目，偏安全与对齐，也有训练和基础设施方向，不要求每个人已有机器学习背景。

[主持] 申请十一月二十二号截止。六周、三个月、六个月几种长度，地点和签证也要按岗位看，不是随时自由兼职。

[解读] 导师和算力是项目支持，录用仍要评估。资深经验能转成研究贡献，是机会，不是保证谁申请谁都能进。

[主持] Theo 还不确定 Agents SDK 那个短周期额度 bug 修了没。我看额度问题，得等明确确认。

[解读] 他此前说不影响周额度。用量问题要分时间窗，别把一次短期耗得快，直接当成整周权益缩水。

[主持] Anthropic 修订上市文件的讨论也很多。博主说，未来模型的内部预期，可能很快触及研发加速门槛。

[解读] 关键词是预期，不是已经公开测定。收入增长的转述，也要分哪些来自文件、哪些来自之后报道，评论里再聊。

[主持] 研究速递，DeepMind 那篇看无关小图案怎么影响多模态决策。模型给出的解释，未必知道自己受了什么影响。

[解读] 红心或箭头在特定测试里改变了写法选择，不是任意一张图，都能百分之百控制任何模型。

[主持] DecisionRAG 用决策模型沿目录逐层筛材料，减少大模型长篇思考找资料的开销。

[解读] 这套测试说更快、更准，先按论文的任务和预算看。前面剪错分支，后面也可能再找不到证据。

[主持] Fable 灰度和超大模型权重的消息，仍是传闻。问一道时事题，最多给线索，不是验明模型身份。

[解读] 所谓评估片段也未经证实，别因为文件能下，就认定是真的，更别忽略来源和安全。

[主持] Connected Data 那组文章，把找数据、取数据、定义含义、关联实体和行动分开，提醒别全叫知识图谱。

[解读] 流畅引用也可能引到旧规范。案例里的改善来自标清来源和有效期，不是再换一个更会说的模型。

[主持] 云端智能体、浏览器保活和长期目标也在讨论。保存会话能省重复登录，但不等于授权永远有效。

[解读] 腾讯手册则讲沙箱快速启动、快照和凭证代理。那些吞吐数字是方案自述，实际隔离和恢复也得测。

[解读] 找到最大原图和算法放大是两件事。一次任务有参考，但不是所有个人助手的长期胜负榜。

[主持] 归藏说最近路由和额度更紧，是他的观察与转述，不把它自动当成所有账号一致的正式政策。

[解读] Alma 安卓版也发布了。Omarchy 这边仍是候选版，苹果芯片安装器、平板和新芯片适配，都在推进。

[主持] Legora 的访谈说，一次模型升级让引用准确率大幅上升。我觉得有意思，可还得看他们那套数据和验法。

[解读] 不代表法律判断从此不用审。把资料找对、把规则用对、决定怎么行动，是不同层次。

[主持] 安替转的币安案通缉消息，也要对照执法机关正式公告，不把社交平台的转述当成司法判决。

[解读] 先倾听维护者和贡献者，再写指南，产出开放许可。不是今天已经给所有项目发了一份统一规定。

[主持] MyST、RO-Crate 和可表达主张证据的资料格式，也有人在研究。记下结果以外，最好能留住它从哪来。

[解读] 语义网二十五年的对谈、科学智能体黑客松和地区数据联盟，也都在进行。下面先看那次直接改权重。

重点一：动一点权重，为什么能好这么多

[主持] MIT 这次，我觉得最妙的是先找卡在哪里，不是一上来就再喂一大批数据。

[解读] GPT 六 Astra 直接改 Qwen 小模型约百分之零点零一六的权重，没走梯度训练。

[主持] 被改的只有八亿参数，别听成八十亿。它开思考时容易绕圈，答不完。

[解读] 原来数学测试正确率七点九，改后四十八点一。所谓最多六倍，很大部分来自把循环解除。

[主持] 我看好定点修故障。可低起点上的六倍，不能拿去乘任何模型的能力。

[解读] 不太循环的小模型对照，没明显提高。已有能力被堵住，跟缺一项能力，不是一回事。

[主持] 不训练，就等于完全不用试、不用计算吗？

[解读] 不是。那项修循环实验要用练习题试跑；允许五十次前向，结果才明显，不能把无梯度说成零成本。

[主持] 还有认游戏、写游戏策略。各项实验工具限制不同，不能把最漂亮的条件全拼一起。

[解读] 对，能读出一部分结构，不等于看懂任意网络所有知识。模型也可能分析错，需要明确的评测去验。

[主持] Mollick 说先等复现，但这是大事。我喜欢兴奋里留点刹车，不急着给未来下定论。

[解读] 我会再看完整日志和权重差异。到底改了哪一层、换采样设置还有效吗，这些决定别人能不能接着做。

[主持] 开放权重在这就有用了。改前改后文件摆出来，别人不必只看服务商演示。

[解读] 可我不想让开放等于随便替换。下载了别人改过的权重，来源、许可和实际行为仍得自己核对。

[主持] 我会先保留原版，在固定任务上对照。先确定那项坏行为少了，再看有没有把别的能力一起改坏。

[解读] 这条新路已经很有趣，不用加一句大模型能无限改造自己，才值得关注。

重点二：少上传历史，不是少读历史

[主持] 消息线程先分清省什么。历史不重发，容易让人以为每轮也不再算那些词元。

[解读] 官方说模型仍读完整对话，词元价格不变。省的是重传、验证和处理请求的等待。

[主持] 先传完整对话，后面只带新消息和上一条回复编号。我看好它帮反复加截图的长任务。

[解读] 接口把对话暂存在内存，再拼回完整输入。不是模型突然长出永久记忆。

[主持] 官方在五十万到一百万词元的请求里，开始输出的中位等待少约百分之三十五。是这一批请求的数据。

[解读] 长对话请求大小，中位数从约八百 KB 到一点八 KB。不能拿这个缩小倍数，去算费用也降同样多。

[主持] 那提示词缓存是不是就不用再管了？

[解读] 还要管。缓存省重复计算和部分费用，线程省重传，不自动替你设缓存断点，可以一起用。

[主持] 线程五分钟没请求就过期，我会留完整记录。临时方便，别当成唯一备份。

[解读] 过期得用完整历史重建。客户端要做好恢复，不能普通暂停一下，任务就断掉。

[主持] 中途改工具、系统提示或模型，不能直接沿用。第一轮配置变了，得按规则重开。

[解读] 数据加密放内存、不写硬盘，可这个功能不支持零数据保留。内存暂存和完全不留数据，不是一回事。

[主持] 我看好它给长对话提速。但要医疗合规的团队，不能只听没落盘三个字。

[解读] 我先核对范围，批处理也不支持。快一点，跟满足自家留存政策，要分别确认。

[主持] 我会测过期、恢复和配置改变，不只测连续发一百轮的顺利情况。暂停以后还接得住，才是真方便。

[解读] 我会对着账单再看。说省上传，就按省上传理解，不把体验提升，硬换算成官方没说的省钱比例。

重点三：接口能现读，约定就不重要了吗

[主持] Steve Lacey 给应用做了 MCP，自己的智能体却几乎不用。我觉得比空争协议有意思。

[解读] 卡在安装连接器。很多环境要人先配置，智能体做不了，只好停下来喊人，或者改用能用的接口。

[主持] 说是复制即用，第一步却让人去安装，很容易劝退。这是入口体验的问题。

[解读] 他仍在做 MCP，是觉得模型每次能读新文档，不像传统客户端代码，要为旧接口兼容好多年。

[主持] 我赞成少折腾安装，可不同意没有契约。模型仍得知道调用后会发生什么。

[解读] 我更愿意把它理解成，接口形式能变得快，不是连业务含义都可以随时漂。这里有两个不同的约定。

[主持] 哪些约定不能只靠现读一遍说明？

[解读] 权限和后果。比如能建账号、删账号，是作者举的能力，不代表模型读懂文档，就获得了替人删的许可。

[主持] 还有错误了怎么回、重复调用会怎样。文档很新，模型也仍可能把新旧流程混着理解。

[解读] 我看重可发现、可学习，但能核对的输入输出和版本记录，不会因此丢掉。

[主持] levelsio 预期 MCP 和 API 最终合一，支持接口密钥和账户授权。我愿意看这种整合，不必为名字站队。

[解读] 可那是预测，不是现在所有服务都这样。现有连接器有自己清楚的授权范围，不该偷偷绕开。

[主持] 我想要少配置、看清权限，不是弹窗少了，什么都在背后悄悄发生。

[解读] 我会再留审计。谁用了哪个版本、传了什么、用户准了哪一步，出了问题还能说得清。

[主持] 所以我同意减轻兼容包袱，但不同意取消所有承诺。形式灵活，后果反而要更明确。

[解读] 让模型适应接口，可以省开发；让用户猜接口今天会不会变意思，那就是把成本转给用户了。

重点四：最高十二分，到底说明什么

[主持] GDPx 最高只有百分之十二。有新难题是好事，但先别拿它换算能替掉多少人。

[解读] 它测特定高价值任务，分数由题目和验法决定，不是经济里可替代工作的比例。

[主持] Mollick 想要人类基线，我赞成。不然是题太难、验太苛，还是题没说清，就混了。

[解读] 他还说 GPT 六 Pro 找到评分里一些错误。模型可以帮忙找评测毛病，但不能自己说错，就自动推翻评分。

[主持] 那零分是不是就代表完全没有实际价值？

[解读] 也不一定。只看完整过关没过关，可能藏住有经济价值的局部成功，两个零分也未必一样。

[主持] 可我也不同意看着像就给过。漏一个关键步骤，整体没法交付，可能真该判失败。

[解读] 我想把部分结果和最终完成都展示。不掩盖进步，也不让中间过程顶替最后验收。

[主持] OpenAI 的 LifeVal 是另一种角度，问用户最想让个人助手帮什么，从托育到办公共事务和管账。

[解读] 来自数千名用户反馈，过去一年用于改进模型。场景贴生活，不等于每项都能无监督完成。

[主持] 我想看它验不验后续。找托育得符合家庭条件，不是列一串名字就完成了。

[解读] 但一个用户觉得方便，也不能代替统一测试。体验、正确性和权限边界，最好都能单独看。

[主持] 我先看题例、评法和人类表现，再看名次。失败在哪里，比最高几分更帮人选工具。

[解读] 我会再看成本和时间预算。没有这两项，同样的得分，背后可能是完全不同的可用程度。

[主持] 难榜不是泼冷水，老榜满了也不是没边界。测出还不会什么，才好继续进步。

[解读] 先保留这份好奇心，同时让评测也能被质疑、被修正。模型和尺子，都还需要继续改。

重点五：谨慎，不一定是舍不得亲手写代码

[主持] Rachel Laycock 那篇让我更理解资深开发者。他们见过的，是系统上线以后怎么出事。

[解读] Thoughtworks 一周不写功能代码，全交智能体。航空应用做出约八成，问题却没结束。

[主持] 她粗估三分之二时间在白板，剩下做执行框架。我觉得工作没消失，是换地方了。

[解读] 人在理领域、给可执行步骤，还要设计测试和架构检查。提交功能最多的，反而是产品同事。

[主持] 应用能跑，构建却常红。红灯一直亮，大家不当回事，绿灯还让人放心吗？

[解读] 这正是她担心的。也许并行任务互踩、模块边界不够，也许改得比检查快，不是找到唯一原因了。

[主持] 我赞成带经验去试，不是只害怕。可测试也交同个模型，没自动多一份独立判断。

[解读] 我看测试到底验什么。模型写的能有用，可不能因它和代码一起生成，就信反例想全了。

[主持] 她提 DORA 的相关性，AI 用得多，吞吐更高、稳定性却更低。相关不等于 AI 单独造成不稳定。

[解读] 但也提醒，更多产出不能顶替稳定交付。发得快却老要回滚，团队后面可能更累。

[主持] 我赞成给真实实验空间。问失败怎么办，不代表落后、不好奇。

[解读] 我也希望把担心变成可测条件，不只说不行。旧做法可能要改，有些原则反而更重要。

[主持] 比如一次改多少、谁验边界、回退怎么做，这些可以在小任务里先试，而不必等别人交一张完美地图。

[解读] Fowler 的提醒也是，这更像没画好的野地，不是教练带无数人滑过的初级雪道。还没那么多长期经验。

[主持] 所以一周做出来，不等于安全维护一年。能交差、下个团队接得住，得接着看。

[解读] 也别拿一次实验，给所有团队定论。它有价值，是把不顺利的部分也摆了出来。

重点六：数据没搬家，入口变好用了

[主持] 我喜欢 marimo 的 SDSS 案例。数据不用全搬家，先让人容易点到需要的光谱。

[解读] 数据仍在原来的数据库和归档，marimo 做交互层。选一片散点，就能跟着看对应星体的光谱。

[主持] 期待多年的工具，研究生几天做出来。我看好熟悉问题的人，能直接把想法试出来。

[解读] 可不是整个数据库几天建成。前面几十年的数据、接口和知识，都是它能工作的底子。

[主持] 响应式 notebook，跟普通笔记本最直观的差别是什么？

[解读] 参数变了，依赖它的结果跟着重算，少想单元顺序，也少让旧结果混进新分析。

[主持] 我喜欢存成纯 Python，和依赖一起进版本库，改了哪里比较容易看见。

[解读] 我还问，包和外部数据以后拿得到吗？记依赖有帮助，但不保证几年后必然原样跑。

[主持] 教程能在浏览器里经 Pyodide 运行，不必每次保后端会话，分享更方便。

[解读] 可实际的合作组应用，仍有 Flatiron 维护的 BinderHub。浏览器教程和服务器应用，并不是谁已经全部替掉谁。

[主持] 也不是几十 PB 全塞进浏览器。网页上是交互和分析入口，数据按需要获取。

[解读] 这个区分很重要。计算规模、访问权限和设备能力，决定哪部分适合本地，哪部分仍要后端。

[主持] Casey 说几周变几分钟，我理解是一些发现问题到做工具的周期，不是所有研究统一提速。

[解读] 这是案例自述，不是随机对照。讲清完整场景，也比只说效率暴涨更有参考。

[主持] 我会先挑实验室里反复有人问的一步做入口，比如选对象、看结果，再让不写代码的人真试一遍。

[解读] 我会看出问题能不能找来源、重新跑。入口顺手很重要，结果怎么来，别一起藏掉。

评论一：预计很快，不是已经发生

[主持] Anthropic 那个上市文件的解读，我觉得最需要保住的两个词，就是未来和预期。

[解读] 博主引用的是内部对未来模型的估计，可能很快达到研发大幅加速门槛，不是当场公布了独立验证结果。

[主持] RSP 里的两倍，谈能力进展速度，不是今天模型每一道题的分数直接乘二，也不是收入翻倍。

[解读] 比的是没有显著 AI 研发贡献的预期速度，以及过去多代最快持续进展，还要考虑自动化是否可能推动继续加速。

[主持] 我愿意认真看风险披露，但不会拿它当产品广告。公司预期重要，外界能核对到多少，也同样重要。

[解读] 我还区分文件和转述。Volkov 特别注明，一项收入数字来自后续报道，不是文件披露。

[主持] 所以今天不能把几个渠道的数字拼起来，全部挂成 S 一已经披露。季度和年化口径，也得回财报核清。

[解读] 所以转述的增长轨迹，不能替代完整财务表。统计口径没核清，先不急着下财务结论。

[主持] 我真正想继续看的，是加速以后安全评估有没有跟上。更快做模型，也得更快知道它会在哪里出问题。

[解读] 而不是先赌一个即将到底是哪天。预期可能成真，也可能变，讨论时把这个不确定留着。

评论二：给答案快，跟把任务做到位

[主持] yetone 那次找壁纸挺具体。快找到一张图，可以很好；可用户要最高清，停在哪一步就很关键。

[解读] 我会先分清原始分辨率和超分。放大以后像素更多，不代表原图里本来就有那些细节。

[主持] Alma 把找到的和放大的都给人选，我觉得这个方向对，让用户知道每个结果是怎么来的。

[解读] 我还会看是否真回应完成条件。不是找到了一个可用东西，就自动把最清晰三个字忽略掉。

[主持] 但一次成功不够给全部助手排永久座次。换素材、换来源、换权限，结果可能就不一样。

[解读] 做个人助手，少打断和肯多走一步都有价值。别为了显得主动，就悄悄改掉用户原来要的东西。

评论三：工具便宜，调用也别没有上限

[主持] 搜索每千次零点七五美元，看着很便宜，可智能体一层层循环，成功请求很快就积起来。

[解读] 模型、搜索、网页抓取和沙箱，也可能分开计费。只看到模型单价，就容易漏掉工具这本账。

[主持] 我会先设任务预算和结束条件，已经找到够用证据，就别换个措辞又查同一件事。

[解读] 但也别只为省调用，看到第一个结果就停。该省的是重复和无目标，不是核验关键结论那一步。

[主持] 我还是更怕后台无声地越跑越多。你说的也得防，别为省钱太早收工。

[解读] 留调用记录和结果，能让人知道花在哪、有没有必要。便宜很有用，可不是把判断也一起免掉了。

评论四：知识能被找到以前，得先有人把它留下

[主持] WikiGap 那五百多篇，让我想到新榜单之外，还有一类进步：以前搜不到的人和故事，现在有了出处。

[解读] 而且不只英文。豪萨语、约鲁巴语和伊博语的贡献很多，按英语材料评 AI，很容易看不见这些缺口。

[主持] 我看好工具帮编辑找线索和整理，但不能让它替缺乏来源的人生，编一篇看起来像真的传记。

[解读] 我也想保留导师。新人不只要一个能写段落的工具，还要知道怎样判断来源、跟社区一起改错。

[主持] 从 marimo 到分类学项目，入口和连接很重要；可资料、术语和人的判断，本来就有人花时间维护。

[解读] 工具把已有知识用得更快，也该让后面的人更好参与。不是搜索框更聪明，知识就会自己长出来。

收尾

[主持] 今天最有意思的，是模型开始能碰更深的东西，可验证、接口和人的分工，反而要说得更清楚。

[解读] 改权重等复现，省上传别当省词元，资料入口变顺，也别忘了背后的长期维护。

[主持] 原帖、研究和工程文章，都在今天的摘要网页上。明天早上，我们接着聊。
