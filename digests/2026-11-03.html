  • #Messages API 公测「消息线程」：长对话不必每轮重发历史系列
    Claude Developers · Claude Code 数据 · 用法 · 宝玉 等 5 位

    Claude Developers 宣布消息线程在 Messages API 公测：服务器在轮次之间暂存对话，下一轮只发新消息和上一条回复的 ID，Claude 能更早开始回复。Claude Code 已接入，50 万到 100 万 token 的请求首字等待时间中位数降低约 35%，长对话里请求大小中位数从约 800 KB 降到 1.8 KB。

    用法是在请求里加 thread 参数和 beta 请求头，Claude Platform、AWS 上的 Claude Platform、Microsoft Foundry 和 Google Cloud 上都能用，按标准 token 价格计费。

    宝玉的中文解读

    补充这省的是上传而不是钱，Claude 每轮仍读完整对话，token 消耗不变；它与提示词缓存不同，缓存断点仍要自己设，官方示例两者一起用；线程 5 分钟无请求即过期并返回 404，需用本地保存的完整对话重建；线程中途不能改系统提示词、工具、模型和思考设置；数据加密存在内存、不写硬盘，但不支持零数据保留（ZDR）和 HIPAA，批处理接口暂不支持。

    Daniel Avila 提醒：LLM 仍是无状态的，变成有状态的是 API，不过对长时间运行的编程 agent 是显著改进。

  • #DeepMind：无关的小图形能悄悄改变多模态模型的决策
    Gorden Sun

    Gorden Sun 介绍 Google DeepMind 的论文：在写代码、文字创作等任务里塞入红心、三角、箭头等 288 种基础彩色符号或用 Python 画的图，对比 Claude Opus 4.7、Gemini 3.1 Pro 和 GPT-5.4。

    一张看似无关的红心图能让原本偏好循环写法的模型百分之百改用递归，圆圈会诱导模型优先选环形缓冲区；模型意识不到被影响，在思考链里称纯属巧合或给出看似专业的理由；两个模型用图画互相沟通时会形成人看不懂的暗号。

  • #DecisionRAG：用决策模型逐层打分做检索
    Gorden Sun

    Gorden Sun 介绍：把资料库整理成大类、标题到段落的层级，决策模型不逐字生成，而是一次计算给同级所有选项打分、逐层筛选。在超过 268 万个维基百科段落上，单次查找 0.7 到 1.8 秒、成本 0.2 到 2.3 美分；在多个问答集上比传统搜索加重排准确率高十几个百分点，比让大模型慢慢思考查找快 30 多倍。
