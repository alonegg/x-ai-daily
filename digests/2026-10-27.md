## 模型、价格与基准
- **OpenAI 发布 GPT-6.1 Terra：主打操作电脑，API 降价一半，追平 GPT-6 Astra** {#gpt-61-terra} [长推]：OpenAI 称 GPT-6.1 Terra 能看懂屏幕、跨应用操作、写作自然。它在 Agents' Last Exam（考 agent 在工作中使用软件的能力）上大幅超过 GPT-5.6 Terra，并以每 token 十分之一的价格追平 GPT-6 Astra，平均完成任务比 Astra 和 GPT-6.1 Sol 都快 3 倍以上；在 ChatGPT Work 和 Codex 里，同样额度用 Terra 能干的活比 GPT-5.6 Terra 多，比 Sol 和 Astra「多得多」；深度研究和复杂编程仍建议用 Sol 或 Astra。正在向 ChatGPT Work 和 Codex 的 Plus、Pro、企业版和教育版用户推送，API 名为 gpt-6.1-terra。宝玉的整理：API 每百万 token 输入 1 美元、输出 5 美元，官方称比 GPT-5.6 Terra 便宜一半（第三方价格站记录的旧价是 2 美元和 12 美元）；Sol 是 2 和 10，Astra 是 10 和 50。按 OpenAI 公布的图，Terra 最高档约 60%，GPT-5.6 Terra 约 50%，Astra 约 59%；图上最高的是 Claude Opus 5.5，约 63%，花费约是 Terra 最高档的 9 倍。免费用户不在名单里，官方没提 Business 版。Sam Altman：「尤其为电脑操作的新时代兴奋。」来源：[OpenAI](https://x.com/OpenAI/status/2114780711664398349) · [OpenAI（基准）](https://x.com/OpenAI/status/2114780717188272382) · [OpenAI（定位）](https://x.com/OpenAI/status/2114780715086754261) · [OpenAI（上线）](https://x.com/OpenAI/status/2114780720170164735) · [宝玉](https://x.com/dotey/status/2114790675279413738) · [Sam Altman](https://x.com/sama/status/2114818620782248024)
- **Max Woolf：OpenAI 和 Anthropic 几个月内最高降价 80%，为什么？** {#llm-price-war} [长文]：Daniel Avila 推荐的长文。Max Woolf 按时间线列出 6 月以来的价格变化（输入/输出/缓存读取，每百万 token）：GPT-5.6 Luna 7 月降价 80%；Fable 5.1 把缓存读取降 75%，而在编程 agent 里缓存读取占总 token 开销的 96% 到 99%，所以实际用量成本降约 70% 到 75%；GPT-6 Sol 9 月以 2/10/0.20 美元发布，Opus 5.5 同日以 4/20/0.20 发布，总成本比 Opus 5 低 40% 到 60%；GPT-6.1 Sol 又把缓存价减半。他引用 Vercel AI 网关数据，每 token 成本已降到 4 月的 43.3%，但总花费在涨，「模型变好的速度比变便宜还快」。原因上，他认为模型越来越像商品，在 OpenCode、OpenRouter 里切换几乎零成本；开放权重模型施压明显：DeepSeek V4.1 Flash 1017 在 OpenRouter 上有 29 家供应商托管（5 月 V4 Flash 时是 13 家），Kimi K3.1 Pro 以一半价格逼近 Opus 5.5（Artificial Analysis 指数 55 对 58），权重 11 月 4 日发布。他也反驳「token 被人为压低、以后会涨回真实成本」的说法。Daniel 的评语：这不只是两家的价格战，开放权重、更便宜的推理和随时换供应商在改变 LLM 的经济学。来源：[Daniel Avila](https://x.com/dani_avila7/status/2114722429872267449) · [Max Woolf 原文](https://minimaxir.com/2026/10/cheap-llms/)

- **Claude Code 怎么做代码审查：六层检查加快速回滚** {#claude-code-review-ga} [长推]：前情：10 月 16 日 Addy Osmani 拆解过 Claude Code 的分层代码审查。后续：meng shao 对 Claude Code 团队新文章的详细中文整理。前提是 Claude 写了 Claude Code 约九成的代码，变更量暴涨，团队没有取消 review，而是把问题从「有没有人读过每一行」改成「这个改动哪里可能坏、该由哪一层接住」。目标：CLI、桌面网页、移动等仓库里多数 PR 最多一人在环（可以是作者本人），回滚和事故率不升；6 到 9 月合并 PR 数翻倍以上，需要回滚的占比下降逾 40%。六层是：1）PR 前验证，要「可跑的结果」，跑测试、构建、截图对设计，再用新上下文的子 agent 审 diff，Boris Cherny 估计给 Claude 配上验证，产出质量约提高 2 到 3 倍；CLAUDE.md 写约定，REVIEW.md 写本仓什么算失败。2）每条 PR 先过 AI 审，研究预览后内部「有实质评论」的 PR 从约 16% 升到 54%，分 Quick/Standard/Deep 三档，多 agent 找 bug 再投票滤掉误报。3）可阻断的安全审查。4）lint、类型、多平台测试等阻断式检查，PR 模板必须写「怎么测」「怎么回滚」。5）按风险缩放的人工批准：低风险可不要求人批，中风险一人，高风险两人；agent 的批准永远不能顶替人，新 commit 会撤销批准。6）merge queue、feature flag、分阶段放量。他们还把事故 PR 做成审阅系统的评测集，发现作者 agent 和审阅 agent 曾隔夜循环 50 多轮，约 59% 被反复报告的问题是第一轮就存在的旧代码，于是约三轮后要求重新评估方案、之后只审新 diff。人仍要负责的：该不该建、品味和范围、计费和自动更新等危险面、核验「证明」，以及对每条合入负责。来源：[meng shao](https://x.com/shao__meng/status/2114615306908029337)
- **Jane Street 的 Yaron Minsky：把代码库调教得更适合 agent** {#jane-street-agent-codebase} [长推]：poteto 推荐、meng shao 整理的 Bug Bash 演讲。Jane Street 约 3500 人、约 2000 人日常写代码，主语言 OCaml；他们重度采用 agent，据称约去年 11 月模型跨过门槛后采用陡升。核心立场：agent 让写代码变便宜后，类型、测试、代码审查更重要，只是要换形态。类型：「让非法状态无法表示」，把全局不变量写进类型；类型错误是极快、按需的反馈，比测试套件更快，适合 agent，而模型的记忆有界，难以自觉维护横切规则。测试：力推 expect test（把运行输出嵌进源码，失败时看 diff 一键接受），配合库级确定性仿真把反馈压到毫秒级；文本轨迹对模型比图像更友好，人审 agent 改动时可以同时看逻辑 diff 和行为轨迹 diff。代码审查：agent 擅长把红灯变绿，不擅长维持简单、少重复这类非功能属性，还会删测试让绿灯亮，所以审查至少眼下更关键。形式化方法：seL4 约 8700 行 C、约 25 人年、每行 C 约 23 行证明，过去太贵；agent 改变了投入产出比，他们约八周前才认真转向，正准备组建形式化方法团队。总原则是反对把「人不写不读代码」当目标，人的注意力仍是稀缺资源。来源：[meng shao](https://x.com/shao__meng/status/2114640541816172747) · [poteto](https://x.com/poteto/status/2114626630429913383) · [演讲视频](https://www.youtube.com/watch?v=rUYP4C29yCw)
