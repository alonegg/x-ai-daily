    meng shao · HF Papers

  • #Anthropic 内部报告：agent 工时已是员工 6 倍，技术岗初级新人占比 27%→9%长推
    宝玉
    宝玉详解 Anthropic 10 月 16 日的两份报告。招聘：技术部门新招人员中初级岗位占比从 27% 降到 9%，2025 年 12 月后初级招聘明显减少；技术员工占全公司比例从 61% 降到 56%（绝对人数仍在增长）；面试评价中提到候选人会不会用 AI 工具的次数，技术岗约为 2024 年的 3 倍、非技术岗约 4 倍。工作量：2026 年 3 月 AI agent 累计工时首次超过员工，8 月员工调用的 agent 工时已是员工的 6 倍（员工按每周 40 小时估算，agent 只算实际运行与调用工具时间）；工程师人均代码提交是半年前的 5 倍；追踪 192 位开始用编程 agent 的工程师，代码量明显增加，agent 写的与人写的代码被删除或撤回的比例没有差别。新瓶颈是人的注意力：Claude 会话约 80% 时间在等人回复；「管 AI」的工作占比从 2025 年秋的 10% 升到 2026 年春的 22%；4 月调查中 20% 员工说角色正从亲手干活变成管理一群 Claude。报告也提醒其作为高速扩张的 AI 公司，数字不能直接套到普通企业。第二份报告对比 1334 名员工与 Morning Consult 8 月约 1.1 万名美国成年人的调查：认为 AI 到 2030 年能做出诺奖级发现的，员工 91%、美国人 39%；认为 2030 年 AI 能做自己八成以上工作的，员工过半、美国人约 5%。但两组推理方式相近——越觉得 AI 能替代自己，就预测越高的失业率（这类美国受访者预测 2030 年失业率 12.2%，当前约 4.2%）。
    原文𝕏宝玉@dotey
  • #Claude Code 团队公开代码评审流程：合并 PR 翻倍，回滚占比降 40% 以上长文
    ClaudeDevs · 博客原文
    后续 （接 2026-10-16）：ClaudeDevs 发文《How the Claude Code team does code review》。Claude 写了 Claude Code 约 90% 的代码；6–9 月合并 PR 增加一倍多，需回滚的比例下降 40% 以上；Anthropic monorepo 每日落地变更从 5 月约 2,500 个增至 9 月 3 万多个。做法是把大部分「阅读」交给机器、为人的时间和注意力优化，并让撤销变得容易：①提交前就让 Claude 跑测试/构建/截图自证，再用新上下文的 subagent 审 diff，CLAUDE.md 与代码所有者写的 REVIEW.md 指导评审；②每个 PR 先过 AI 评审，多个 agent 并行找 bug、另一组投票确认才发布，研究预览期内获得实质评论的内部 PR 从 16% 升到 54%；③可阻断合并的安全评审；④lint、类型、全平台测试；⑤按风险分级的人工审批（低风险可零人工、中风险一人、高风险两人），由分类器按变更而非作者定级，agent 的批准永远不能顶替人；⑥合并队列、特性开关与灰度发布；⑦快速发现与回滚。评审器用历史事故与回滚 PR 做每日评测；曾有 PR 一夜被 agent 互审修改 50 多轮，约 59% 的反复标记其实是老代码，因此引入三轮上限、仅审新 diff、按 bug 类别标记、不重复已发问题。人仍负责「该不该做」、高风险代码、架构、读证据和对结果负责。
