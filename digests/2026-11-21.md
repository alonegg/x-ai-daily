## 黎曼猜想：Claude 参与的证明与 Lean 复核
- **Levent Alpöge：与 Claude 合作证明黎曼猜想和广义黎曼猜想** {#riemann-hypothesis-claude} [长文]：数学家 Levent Alpöge 发布两页说明，称他「与 Claude 合作」发现了黎曼猜想的证明，方法还能推广到广义黎曼猜想，他预计假以时日也能覆盖扩展黎曼猜想；他说论证已与 Claude 一起「不带额外假设地」完成形式化。证明以 Lean 代码发布，压缩包分 14 个部分。他写道，自己把思路引到与一个「玩具情形」类似的情境后，「Claude 开始让我敬畏」，并举例说核心是延续 Stepanov 在函数域上用到的「重数」论证，靠串联 theta 提升在整数上模拟重数，Claude 建议的链长是 √X。他坦言论证目前极长，自动生成的完整文档「超过 25 万页」，因为「发一份巨大的不可读的 slop 显然不合适」，所以只公开 Lean；他打算之后写一份正式、可读的版本，并预计会出现简短得多的证明。关于宣布时间正好在 Anthropic 上市后一天，他说「时机糟透了」：事情发生在周日深夜，他给 Dario 发消息询问能否公布，「有一个约束要遵守」；他说自己「再多等一刻都受不了」，并称与股价有关的犬儒解读是错的。多方转述称他在 Anthropic 工作。来源：[Alpöge 说明 PDF](https://alpo.ge/remark.pdf) · [Simon Willison 摘引](https://simonwillison.net/2026/Nov/20/levent-alpoge/) · [歸藏](https://x.com/op7418/status/2123823642991907109) · [Markus Buehler](https://x.com/ProfBuehlerMIT/status/2123802170025709815)

## OpenAI：反蒸馏、药物化学基准与生物研究
- **OpenAI 公布反蒸馏研究：攻击成功率从 54.0% 降到 0.2%** {#openai-distillation} [长文]：OpenAI 说，对抗性蒸馏是未经授权用前沿模型的输出训练别的模型，能复制能力却绕开安全护栏。它的研究发现，即使任务本身合规，用完整推理轨迹训练学生模型，比用摘要更能转移网络安全能力。防御分几层：对抗训练让模型拒绝套取推理的请求；输入输出分类器，特别盯工具调用参数里泄露的推理；在 API 层，GPT-6.2 Astra 和 Sol 把受保护推理绑定到产生它的对话历史，改写早先消息后后续推理会被丢弃。内部评估中，从早先请求套取推理的平均成功率从 GPT-6 Astra 原护栏下的 54.0% 降到 GPT-6.2 Astra 的 0.2%，从当前请求套取从 22.9% 降到 0.9%。执法方面，每周封禁的账户规模从数千到数万，今年夏天明显上升；OpenAI 重提曾向国会报告 DeepSeek 试图蒸馏美国前沿模型，并称 9 月破获一起套取受保护推理的行动，核心部分归因于与 Moonshot AI（Kimi 开发方）相关的个人。Ethan Mollick 评论：从 OpenAI 和 Anthropic「轻松蒸馏」的时代结束，可能是开源权重模型相对放缓的原因，蒸馏到底有多关键，很快就会知道。来源：[OpenAI 原文](https://openai.com/index/combatting-adversarial-distillation/) · [OpenAI](https://x.com/OpenAI/status/2123862344422088794) · [Ethan Mollick](https://x.com/emollick/status/2123867811005014143)
- **MedChemBench：评估 AI 的药物化学推理** {#openai-medchembench} [长文]：OpenAI 发布药物化学推理基准 MedChemBench，99 道题取自已发表研究，涉及 117 篇论文和专利、761 种分子结构。模型拿到某个研发阶段的背景（靶点、目标、已研究的化合物和部分实验结果），按四项打分：重建分子结构、基于证据的科学推理、按要求排序或挑选化合物、预测数值和类别性质。在 xhigh 推理档，GPT-6.2 Astra 拿到 84.5% 的分，GPT-6 Astra 83.3%，GPT-6.1 Sol 82.0%，GPT-5.6 Sol 58.2%；结构重建拿到 95.4%，挑化合物和预测数值只拿到约一半。OpenAI 说明局限：这是对历史证据的推理而非真实药物发现，无法排除模型见过已发表来源，每题单次作答、不用工具，因此不能说明模型能发现新药或改善实验室决策。来源：[OpenAI 原文](https://openai.com/index/introducing-medchembench/) · [OpenAI](https://x.com/OpenAI/status/2123856316187975756)
- **后续：GPT-Rosalind 神经疾病研究扩大合作** {#gpt-rosalind-academic}：OpenAI 发布视频讲述与 PerturbAI、Scripps Research 的脑科学合作。此前公开的结果是：数千个 GPT-Rosalind agent 并行，用 32 分钟把数百万个小鼠脑细胞的基因表达结果和文献连起来，提出「恢复胆固醇运输可能保护神经元」这条可检验的线索；在最大工作量下，分布式 agent 引用 700 多篇文献，单个 agent 只引了 11 篇，盲评中专家 75% 的时候更喜欢分布式报告。OpenAI 说正扩大合作去找新的药物靶点。后续：新增的是视频和合作扩展，没有新的实验验证结果。来源：[OpenAI](https://x.com/OpenAI/status/2123899406550528422) · [OpenAI 原文](https://openai.com/index/scaling-ai-research-for-complex-biological-data/)

## 开源模型与论文
- **Thinking Machines 开源 Inkling 2 Mini：中间 12 层循环三遍** {#inkling-2-mini} [长文]：Thinking Machines 以 Apache 2.0 发布 Inkling 2 Mini，Clem Delangue 称「美国开源 AI 还没死」，说它达到开源 agent 模型的帕累托前沿。按 Hugging Face 博客，它是多模态混合专家模型，物理参数约 260 亿，每 token 激活约 30 亿（vLLM 博客写 35 亿）；24 个物理层里，第 6 到 17 层共用权重循环三遍，逻辑上相当于 48 层，每遍有独立的 KV 缓存，靠门控「消息」读上一遍的信息。每层 128 个专家选 8 个，支持图像和文本输入、100 万 token 上下文，专家权重用 NVFP4 和 MXFP8，附带 DSpark 草稿器加速生成。Hugging Face 说在 48 项基准里有 32 项领先 Gemma 4 31B、Muse Glimmer、Qwen3.8-27B 和 Nemotron 3.5 Super VL，初步体感与 Qwen 3.8 27B 相当但还需更多验证；另有可调循环次数的研究版，少循环更快、质量略降。vLLM 在 Blackwell、Hopper 和 DGX Spark 上首日支持。来源：[Hugging Face 博客](https://huggingface.co/blog/inkling2mini) · [vLLM 博客](https://vllm.ai/blog/2026-11-20-inkling2-mini) · [Clem Delangue](https://x.com/ClementDelangue/status/2123873347393970488)
- **开源模型速递** {#open-models-1121}：腾讯在 Hugging Face 发布 Hy4 基座模型，7700 亿参数的多模态 MoE，激活 490 亿，100 万 token 上下文，是预训练基座而非指令微调版；腾讯还发布 WeMM-Video 系列中英双语全模态模型（20 亿到 350 亿参数、激活 30 亿），用约 1.2 万亿多模态 token 训练，做音视频联合理解，并有检测 AI 生成视频的 agent 框架 WeVisForensics，平均准确率 95.2%。苹果发布单目度量深度估计模型 Depth Pro 2，以及一个 2350 万参数、无需 EXIF 就能从单张照片估计焦距的小网络。微软发布可在浏览器里用 WebGPU 跑的 Aion Instruct ONNX 版，23 亿参数、INT4 量化约 1.3GB、32k 上下文、8 种语言。Ai2 发布随机气候模拟器 ACE2.5，以很低的算力模拟几天到几个世纪的大气变化。Ideogram 发布图片编辑模型 Ideogram 4.6，原生 4K，非编辑区域的像素漂移更少。来源：[Hy4](https://x.com/HuggingPapers/status/2123628542709883236) · [Hy4 基座说明](https://x.com/HuggingPapers/status/2123628552717582796) · [WeMM-Video](https://x.com/HuggingPapers/status/2123750396002767170) · [WeVisForensics](https://x.com/HuggingPapers/status/2123629352911089817) · [Depth Pro 2](https://x.com/_akhaliq/status/2123586174405296481) · [焦距估计器](https://x.com/HuggingPapers/status/2123569099343274167) · [Aion Instruct](https://x.com/HuggingPapers/status/2123590734288744553) · [ACE2.5](https://x.com/HuggingPapers/status/2123885128149868986) · [Ideogram 4.6（歸藏转）](https://x.com/Gorden_Sun/status/2123594198507225421)
- **论文速递** {#papers-1121}：Yann LeCun、Randall Balestriero 和 Kerda Varaku 提出「反事实世界模型」，把 JEPA 扩展到在相同隐藏条件下预测另一种行动的结果，比如机器人被风吹偏后，估计若换个动作会落在哪。机器人基准 Mind2Act World 把具身推理、物理动作和两者闭环组合分开测：最强 agent 推理 52.7%、动作 39.0%，组合起来只有 12.0%。Google 论文提出 Procedural Graphs：把 agent 的操作规程写成模型权重之外、可检查可编辑的图，只给建议不做硬控制，离线比较成败轨迹来改图。MIT 的 Markus Buehler 团队研究 LLM 内部怎样表示材料科学规律：在六种金属上调高与晶粒尺寸相关的内部信号，模型就更倾向「晶粒越小强度越高」，他设想把这类测量变成后训练奖励。可灵研究提出 Coda-DaVinci，用 agent 编写的 3D 代理和物理模拟控制视频生成的场景与运动。来源：[反事实世界模型（LeCun 转）](https://x.com/ylecun/status/2123774055438332294) · [Mind2Act World](https://x.com/HuggingPapers/status/2123690573521404039) · [Procedural Graphs（Connected Data 转）](https://x.com/Connected_Data/status/2123661656345706546) · [Markus Buehler](https://x.com/ProfBuehlerMIT/status/2123716972068397335) · [Coda-DaVinci](https://x.com/HuggingPapers/status/2123870791854965131)

## Agent 工程与开发工具
- **Hugging Face「harness 适配器」：给同一模型按 harness 训 LoRA** {#harness-adapters} [长文]：Hugging Face 团队以 Qwen3.8-27B 为基座，用 TRL 的异步 GRPO 在 Pi、Hermes Agent、OpenCode 三个 harness 里分别做强化学习，各训一个 LoRA。训练任务来自 SWE-smith、SWE-Gym 等，只保留基座模型有时成功有时失败的任务。在 SWE-bench Pro 难题子集（51 题）上，Pi 适配器从 39.2% 升到 64.7%，Hermes 从 29.4% 到 43.1%，OpenCode 从 35.3% 到 51.0%。三个适配器的更新方向几乎正交，拼接成「超级适配器」后，在六个 harness 与基准组合上平均通过率从 39.5% 升到 49.0%；关掉思考时，在双方都能解的题上工具调用少 53–73%、生成 token 少 44–60%。局限：不同 harness 默认设置不同，结果只能在同一 harness 内比较；在非编程的 AutomationBench 上几乎没有提升。来源：[Hugging Face 博客](https://huggingface.co/blog/harness-adapters-at-scale)
- **后续：Claude Code 团队讲代码审查——查出实质问题从 16% 到 54%** {#claude-code-review-ga} [长推]：宝玉整理了 Claude Code 产品经理 Morgan Lunt 的分享。半年多前 Anthropic 内部的审查已流于形式，Lunt 称之为「歌舞伎表演」；他引用哈佛研究说，企业引入编程 agent 后 PR 等待审查的时间平均增加 56%。约 7 月 Boris Cherny 让他们解决审查问题，目标是 90% 的 PR 除了发起人不需要别人。评测集用公司历史上全部线上事故和引发事故的 PR，看审查 agent 能否回到当时找出那一行；同时看召回率和精确率。流程是先派找问题的 agent，再派验证 agent 挑刺，排序去重后贴评论；九成多 PR 在三轮「审查、修复」内收敛。结果：查出实质问题的 PR 从 16% 升到 54%，合并 PR 翻倍，回滚少 40%。后续：10 月的官方博客讲了六层流程，这次补上了 16% 到 54% 的检出数据和事故评测集的做法。来源：[宝玉](https://x.com/dotey/status/2123555597387813050) · [meng shao](https://x.com/shao__meng/status/2123576742464073745) · [官方博客](https://claude.dev/blog/solving-code-review-at-anthropic/)
- **LangChain 开源内部设计 agent「Content Studio」** {#langchain-content-studio} [长推]：LangChain 把内部在用的设计 agent 开源，它基于 Deep Agents，部署在团队 Slack 里，在线程里提需求就能拿回符合品牌规范的平面、演示文稿、图表和视频，每个线程配一台 LangSmith 沙箱，密钥不进沙箱、默认不连外网。自 8 月以来交付 3000 多件物料、80 多份演示文稿，四分之三的需求来自市场部以外；单次请求模型费用中位数约 0.5 美元，9 月中旬还是约 8 美元。Harrison Chase 说上线前还让它试做了发布视频。来源：[meng shao](https://x.com/shao__meng/status/2123600235079586247) · [GitHub](https://github.com/langchain-ai/design-agent) · [Harrison Chase](https://x.com/hwchase17/status/2123430062913724481)
- **NVIDIA Dynamo 缓解强化学习的 rollout 瓶颈** {#nvidia-dynamo-rl} [长文]：英伟达技术博客介绍 Dynamo 作为强化学习框架和推理引擎之间的服务层：按 KV 缓存复用和负载做路由，减少共享提示的重复计算；ModelExpress 让新权重从集群内其他 GPU 直接复制，并只传压缩后的增量；节点故障时把请求转到健康节点。案例：CoreWeave 用它把权重更新最多提速 15 倍，H Company 平均训练步时最多减少 20%、GPU 时数最多减少 5%；微软 AI、Cognition（SWE-1.7 后训练）和 Prime Intellect 也在用。优化、奖励和样本取舍仍由强化学习框架负责。来源：[NVIDIA 技术博客](https://developer.nvidia.com/blog/reducing-rollout-bottlenecks-in-reinforcement-learning-with-nvidia-dynamo/)
- **开发实践零讯** {#dev-tools-1121}：MCP Events 发布，agent 可以订阅外部事件、不等用户发话就行动，比如新 PR 一来就自动审查跑测试，支持轮询、推送和 Webhook 三种方式（Daniel Avila）。Harrison Chase 说多数 agent 运行已不是人触发的，LangChain 观察到已部署 agent 里按计划启动的比例在上升。Theo 说带箭头和标注的截图比 PR 更容易让他和 agent 理解并实现需求；T3 Code 0.1.11 支持远程环境把 localhost 直接隧道到桌面。宝玉回应 Lauren Tan 的自动化指南：他更强调「目标、验收、改进」的循环，少干预中间步骤。李博杰分享省 token 的分层用法：20 到 40 个 agent 并行时，Fable 当「军师」定计划、解难题，Opus 做管理，Sonnet 做执行，他说试下来这个组合效率最高。Google AI Studio 支持一句话生成带 Firebase 后端的全栈 Kotlin 安卓应用；Gemini 3.5 Transcribe 的语音编辑能力进入 Gemini API。来源：[Daniel Avila](https://x.com/dani_avila7/status/2123896682907664610) · [MCP Events](https://github.com/modelcontextprotocol/ext-events) · [Harrison Chase](https://x.com/hwchase17/status/2123853805276348782) · [Theo](https://x.com/theo/status/2123754193530053110) · [Theo：T3 Code](https://x.com/theo/status/2123720628100628521) · [宝玉](https://x.com/dotey/status/2123667995570413718) · [李博杰](https://x.com/bojie_li/status/2123803797604671643) · [Google AI Studio](https://x.com/GoogleAIStudio/status/2123840416277512391) · [Google（DeepMind 转）](https://x.com/GoogleDeepMind/status/2123851501915312624)
