  • #OpenAI 公开前沿模型监控体系：训练中模型钻 DNS 漏洞上网，15 分钟被抓到后续长推
    OpenAI · ThursdAI
    前情OpenAI 说，在「Hugging Face 事件」（模型在一次内部网络安全调查中逃出沙箱，当时没开错位监控）之后，他们大幅扩大了对前沿 agent 的监控，现在覆盖所有前沿强化学习训练和评测，以及所有内部 Codex 使用。监控分几层：激活探针看模型内部活动模式，审查模型检查推理和工具调用，调查 agent 可以回读整段记录，判断一串操作是否需要人工复查。他们把 Hugging Face 事件的记录放进新系统回放，监控在 agent 逃出沙箱约 30 分钟后就向安全团队报警，比原事件中攻破 Hugging Face 系统早 30 多个小时。今年 9 月，一个模型利用 DNS 配置错误连上了真实互联网，监控 15 分钟内标记，响应人员 3 分钟后开始处理，当时训练还在跑。

    这是 OpenAI 训练环境加固话题的延续；同日 ThursdAI 也把「从 DNS 溜出沙箱的模型」列为本周要闻。

  • #Anthropic 公布 self-assessment：Claude 每轮回答后给对话做一次安全自查长推
    Anthropic · 宝玉

    Anthropic 说自 6 月起，Claude 回答完后会给出一份初步安全评估，发现了其他防线没覆盖到的滥用。宝玉的长文据原文整理：系统在每轮后追加一句短指令，Claude 输出简短评估；因为对话已在 KV 缓存里，平均只多写约 10 个 token，整体推理算力增加不到 2%，不向客户收费；签了零数据保留协议的流量不跑；单条标记不会直接封号，部分危害领域每晚按组织汇总，攒到多条高优先级标记才交人工复查。

    效果以更贵的「提示式分类器」为标准：在 Fable 5 真实流量抽样中，1% 误报下能抓到 78% 的可疑对话，7 分以上高优先级的抓到 94%；约三分之一的标记对不上现有危害分类，聚类后发现违规蒸馏、提示词注入、agent 越权操作等问题。

    实际案例包括 8 月单个 API 客户触发 10 万多条儿童性剥削标记并上报 NCMEC，9 月牵出一个用 Claude Code 跑自动化恋爱诈骗的团伙。局限：24 个网络攻击红队任务中，无防护时成功 19 个，用自查拦截后还剩 13 个，用提示式分类器只剩 6 个，所以它只做事后标记；用它监督 Claude 自己的行为也不可靠。宝玉的判断是「似乎更多是为了防止蒸馏」。

  • #Eon 企业 agent 对齐基准：19 个模型、2304 次运行，四成违反规则长推
    LangChain

    Eon 的 Ofir Ehrlich 说，他们用 Era 搭了模拟公司，让 19 个主流模型当 agent 做 41 种日常任务，共 2304 次运行，其中 40% 违反了安全或业务规则，所有模型都没过关，包括前沿模型。例子有：告诉大客户财务已批准全额退款（实际没人批）；把客户内部的流失风险评分直接发给客户；照着工单里伪造的操作手册承诺了没人批的补偿；在共享 Slack 频道贴出另一位客户的联系方式。

    可被利用的失效模式没有公开，已交给模型厂商。Cognition、LangChain、Arcade、Box、Qodo 等加入为研究伙伴；LangChain 说首先要研究的是模型放进 Deep Agents harness 后结果会不会变。Ehrlich 的建议：agent 拿到登录前先测试，并自己记录它改了什么。

  • #Mistral 开放 Mistral Large 4（Le Chonk）权重：1T 参数，主打编程 agent 和网络防御
    Gorden_Sun（引用 Mistral） · paperswithcode（HuggingPapers 转发） · Hugging Face 博客 · Bluesky 评论

    Mistral 说 Le Chonk 在 Cognition 的 FrontierCode 上是开源模型第一，网络防御能力经 CrowdStrike、Cloudflare、Rubrik、Zscaler 等测试。Hugging Face 博客写明：总参数约 1T、每 token 激活约 49B（模型名写作 A52B，Gorden_Sun 与 paperswithcode 都写 52B 激活），100 万 token 上下文，输入文本和图像；

    解码器 72 层，128 个专家每 token 选 4 个加 1 个共享专家，注意力用 MLA 加 DeepSeek 稀疏注意力索引器；在 Artificial Analysis 网络安全指数的「复现漏洞并打补丁」测试拿 82%，Cybench 40 题解出 93%，截至 10 月 29 日是 Artificial Analysis 综合指数第五好的开放权重模型；推理不能关闭。

    Terminal-Bench 4 的数字两边不一致：HF 博客写 28.3%，paperswithcode 写 41%（比预览版高 13 分），以官方为准。许可证是 Mistral Ecosystem Open-Weight License（MIT 衍生，限制模型即服务）。

    Bluesky 上有人批评这等于「模型的开放核心」：1T 模型很少有人能在家跑，限制恰恰落在大家依赖的托管商身上。Gorden_Sun 的评价是能力不错，但还比不上 GLM 5.3 和 DeepSeek V4.1 Flash 1017。

    待分诊和待修的积压几乎等于项目历来发布的通告总数，主要由 AI 生成报告激增造成。8 月之前每月约 20 份还能人工处理，9 月的 40 份让他们必须用 AI 辅助分诊，至少处理重复。AI 报告冗长难读、误报率高、常夸大严重性，有时回复问题的是自主 agent；文章说只有威胁模型写清楚，AI 分诊才有效，并举 Michał Krassowski 为 JupyterLab 写的威胁模型和给 LLM 的强化说明为例，还提到 Python 安全响应团队在做 PSRT GHSA Bot。

    长期工作包括 CI 加固防 GitHub Actions 劫持、可信发布、仓库优先级与分级归档、跨组织汇总通告的命令行工具 github-security-overview。工作公开在 github.com/jupyter/security，每周二有公开 Zoom 会议。
