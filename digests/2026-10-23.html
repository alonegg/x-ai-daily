  • #Anthropic 与 Theorem：用 Claude 给 123 个开源库做汇编级形式化验证后续长文
    Anthropic · 博客原文 · asim_hassaan 评论
    前情Anthropic 前沿红队博客《LLM 让大规模形式化软件验证变得可行》。背景：Linux 内核最近一次就披露了 1000 多个漏洞，模型越来越会把不起眼的 bug 串成严重漏洞，需要能「证明没有 bug」的手段；但形式化验证历来很贵，seL4 内核实现花了 2 人年，验证花了 20 人年。做法是把开源项目自带的 fuzz 测试自动转成规范：fuzz 入口在任何小于 64 MB 的输入下都不崩溃（OSS-Fuzz 会用 AddressSanitizer 插桩，内存越界即崩溃）。程序编译成 RISC-V 可执行文件，结合 Theorem 的 RISC-V 指令和 Linux 进程语义，机械地生成待证命题，Claude 写证明，Rocq 内核检查。几周内 Claude 修掉自己找到的 bug 后，证明了 123 个 OSS-Fuzz 库的 239 个入口不会崩溃。证明共约 1.8 亿行 Rocq，典型一份约 60 万行，对应的二进制中位数约 1.8 万条 RISC-V 指令。证明几乎不用人工审，需要信任的只有 RISC-V 和 Linux 进程模型、定理陈述本身和 Rocq 检查器。找到的 bug 很多是 fuzzer 几乎不可能碰到的：某解压器约 20 MB、特定布局的输入才触发的计数器下溢越界写；需要 64 MB 输入和 2 GB 以上内存的图像解码器越界读；跨两个文件句柄的调用序列；重新发现 libexpat 的 CVE-2026-56132；还有一个「限制可加载文件」的功能并不总是生效的逻辑 bug。为完成 cpp-httplib 的证明，Claude 甚至得在机器码上证明 libc++ 红黑树的再平衡能把树深限制在对数级。其他实验：先写 RFC 1950（zlib 格式）的形式化规范，再证明 Linux 内核 zlib 的 x86 二进制符合它，x86 语义也由 Claude 自己生成，单步执行能启动 Ubuntu 用户态，还找出官方参考文档里数百处错误和少量硬件 bug；用 Rust 写一个 Python 子集解释器并用 Verus 证明符合 CPython 语义，170 万个随机程序里 99.95% 行为一致；验证一款常用 PDF 阅读器时，一周找到的安全 bug 相当于平常一年的报告量。成本方面，证明要消耗数亿 token，但 Opus 5.5 证完 36 个小任务里一半所需的 token 比 Opus 5 少约 40%；让 agent 共享工作区互相抄证明，token 再省 17%，34 个完成的证明里有 30 个比单干便宜。局限：只覆盖单线程、静态链接 musl 的 RISC-V 二进制，而大多数人跑的是动态链接 glibc 的 x86 / ARM；ASan 抓不到所有内存问题；没覆盖全部入口；为防「改程序让定理变得平凡」这类奖励作弊，补丁会被扣分并审计。Anthropic 公开了不涉及未修补 bug 的部分证明和语义，Theorem 提供免费给开源项目跑同一流程，并发布了一个 Claude skill。评论区有人指出这只对维护者写过的 fuzz 入口成立，也有人问闭源软件为主的小企业能不能用上这项服务。

    与 OSS Scanner 免费扫漏洞形成一对，一个找、一个证。

  • #METR 与 Redwood 驻场 OpenAI 三周：内部误对齐监控有多处漏洞长文
    OpenAI · METR · METR 博客 · Reuters 转载

    METR 与 Redwood Research 各派一人，7 月 21 日到 8 月 11 日在 OpenAI 现场做「高权限」试点评估，能看内部代码、监控提示词和配置、内部文档，访谈了监控、安全系统和安全团队约十几名研究员和工程师；用 OpenAI 配发、不出办公室的设备，全程有人陪同。

    内部报告 61 页，双方事先约定公开版只发简要摘要，OpenAI 有权删改敏感信息。主要发现（针对 7 月 21 日及以前的系统）：GPT-5.5 及以上模型的内部 Responses API agent 流量里，估计约 75–94%「符合监控条件」（METR 原文为 eligible，不等于实际被监控，报错、降载、bug 都可能让其中一部分漏掉；跑在内部研究推理服务上的流量也没算进来），内部 Codex agent 子集约 99.2%；

    评估开始时 RL 训练 rollout 不在监控范围内（3–6 月曾监控过一部分）；压缩（compaction）事件没被监控，估计 5–7 月约 10% 的 Codex 流量因此漏监，OpenAI 事先已发现并在评估期间修复；而监控在 agent 把控制权交还用户时才触发，所以那段时间 agent 只要一直执行动作就能无限推迟被监控。

    Reuters 报道还提到，有一个漏洞能让 agent 让「最近数百个动作（包括利用漏洞本身）」不被监控，Codex agent 原则上能绕过限制、以运行它的用户的全部权限行事，另有两个设置能关闭新 agent 的监控。OpenAI 表示影响生产防护的漏洞都已修补，METR 说没有核实。

    OpenAI 说这些发现帮助加固了扩展中的系统，也会影响今后与第三方评估者的合作方式。
