开场与头条预告

主持：早上好，今天是十一月十五号，星期天。这里是 X 每日 AI 播报。

解读：周末消息不算多，但有几条挺值得坐下来细聊的。

主持：头一件，Cursor 把上个月那起安全事件的来龙去脉，完整公布了。

解读：起点不在 Cursor 自己身上，而是一把交给合作方的钥匙，最后一路通到了一个恶意扩展。

主持：第二件，Anthropic 发了一篇指南，讲怎么做一个全天候在线的智能体。

解读：有意思的是，它说所谓始终在线，其实智能体大部分时间都在睡觉。

主持：第三件，黄仁勋离开英伟达之后，开放模型圈开始担心，以后出事谁来撑腰。

解读：后面还有 Thinking Machines 的四比特训练，和 Shopify 让智能体攻击自家系统。

主持：最后会聊一个小故事：智能体为了重建一门诗歌课，一行一行地翻遍了互联网档案馆。

解读：先从快讯过一遍。

快讯

主持：先看工具。Claude Code 的项目功能大更新，协调多个并行任务的那个角色，变得主动多了。

解读：它会在项目聊天里回答问题、汇报各条线程的进度。还能给线程设提醒，到点再提出来。

主持：单条线程也能生成只读链接分享出去，但碰过你电脑的线程不能分享。

解读：这个限制挺合理。同一天，Claude Code 桌面版还支持自定义主题，换配色、加动画背景，让 Claude 直接帮你生成。

主持：好玩的是，Theo 的 T 三 Code 同一天也上线了，让智能体直接改你的界面。

解读：Theo 说，有个不懂技术的朋友在稳定版上让智能体改界面，结果它把整个源码克隆下来，她现在用的是个分叉版。

主持：我觉得这个段子挺说明问题的。智能体太听话，有时候比不听话还麻烦。

解读：Theo 自己的解释是，模型到了能轻松加、也能用这类功能的阶段，所以两家才会撞车。

主持：再看协议。Sierra 发布了个人智能体协议 Poppy 的一点零版。

解读：说白了，就是让你的私人智能体去企业网站办事时，先说明自己是谁、被允许做什么。

主持：Shopify 上每家店铺都自动接入了。Meta 的 Muse 智能体，访问每个网站都会先找这个协议。

解读：设计合作伙伴已经超过一百家。不过官方仓库里，当前文本还标着草案，定稿前可能还会改。

主持：选模型这件事，工程师 Addy Osmani 在 Claude 开发者博客上给了建议：日常就用 Opus 五点五，中档思考。

解读：吃力了先调高思考档位，再考虑换模型。最难的大迁移、长时间无人值守，才上 Fable 五点二。

主持：他引用的一份公开评测里，五十二个编程任务，两个模型解出来的差不多。

解读：但 Fable 每解决一个任务，花的钱是 Opus 的两点八倍。贵的不一定值。

主持：收购方面，Cohere 完成了对 AISLE 的收购，这家公司做自动发现和修复漏洞。

解读：代码审查平台 cubic 的团队也加入了。这是 Cohere 今年第四笔战略并购，方向很明显，押安全。

主持：研究这边，有个新基准叫 Infrathon，给智能体二十四小时，去优化真实的 AI 基础设施。

解读：一百五十次运行里，一百三十五次到了后半段还在继续变好。评测时间一长，模型排名都会变。

主持：也就是说，只跑一两个小时的评测，可能根本看不出谁更能熬。

解读：对，论文还说，拖后腿的主要是违反任务规则、测试不靠谱，还有没做完就宣布完成。

主持：英伟达技术博客有篇挺浪漫的文章：用 GPU 处理给黑洞拍照的数据。

解读：事件视界望远镜把全球十三个射电站连起来。英伟达说，十太字节的数据，七十秒就处理完了。

主持：比普通处理器快大约四百六十倍。论文这边，还有让智能体给电路板布线的，合成板子上全部干净通过。

解读：再看行业。WorkOS 宣布年经常性收入达到一亿美元，它现在说要做「人和智能体一起工作」的基础设施。

主持：美国这两天还出了一件跟 AI 无关、但很多人在聊的事：美国联邦航空局一度叫停了全美航班起飞。

解读：据 CBS 新闻的多方消息，是空管专用通信网络的一次更新，让系统重启时崩溃了。

主持：正好接上 Theo 的一个热帖，他说 AI 会让软件整体变得更稳定。

解读：levelsio 则拿 Revolut 的故障复盘说事：数据库节点挂了都没监控。他的意思是，大公司也一样会挂。

主持：还有一份「拒绝 AI 垃圾」宣言，在 AI 工程师大会上发布，已经有三百多人联署。

解读：里面有一句我挺喜欢：AI 不能取代人的判断，只能放大判断，或者放大判断的缺失。

主持：Jupyter 这边周末很安静。官方论坛上有两个实用的讨论帖。

解读：一个问笔记本越写越长，怎么保持可读；另一个问，在我这儿能跑、到你那儿就报错，第一步该查什么。

主持：Deepnote 那个智能体基准也有了新估算：一家七十人的模拟公司，一个月的群聊工作，贵配置要四千六百多美元。

解读：一个得分更高的便宜模型，只要两百八十一美元。不过还是那句话，基准是 Deepnote 自己建的。

主持：开放知识这边，维基数据十四岁了。加纳的一个小语种社区，专门办了活动来庆祝。

解读：他们教大家给自己的母语建词位，加释义和词形。印度理工学院德里分校，也开始设驻馆维基人。

主持：最后，Gradio 发起了一个挑战：让智能体去复现今年 NeurIPS 的论文，十一月二十号开始。

解读：报名截止是十九号，报名的人有二十美元的算力额度。快讯就先到这儿。

重点一：Cursor 事件，钥匙是怎么一路传下去的

主持：重点一，Cursor 公布了十月底那起安全事件的完整复盘。我先说结论：入口不在 Cursor 自己身上。

解读：对，起点在 Fireworks，一家做训练和推理的合作方。Cursor 发给它一把访问密钥，Cursor 说是 Fireworks 那边泄露的。

主持：攻击者拿着这把钥匙，进了一个专门用来跟 Fireworks 共享数据的存储桶。里面放的是什么？

解读：一批编码智能体的历史记录，大多来自二零二五年，是没开隐私模式、Cursor 获准拿去训练的会话。

主持：问题就出在这些历史记录里。有少量记录，里面的密钥没做脱敏，原样躺着。

解读：不到万分之一的客户，接口凭证暴露了。攻击者就拿这些凭证，进了 Cursor 用的一些第三方软件服务。

主持：然后就是大家最关心的那步：恶意扩展。

解读：十月二十九号，攻击者用偷来的凭证，把一个假冒的 Claude Code 扩展，放进了 Cursor 扩展市场的缓存里。

主持：最多大约五千名用户可能拿到了，挂了大概十一个小时才撤下。

解读：要强调一点，这不是 Anthropic 产品的漏洞，上游的扩展源也一直是干净的。Cursor 应用本身和发布签名都没受影响。

主持：我觉得这件事最值得记住的，是一条很长的链条：供应商的钥匙，旧记录里的密钥，再到分发渠道。

解读：每一环单看都不起眼。可我有点不同意把锅全甩给供应商，存了带密钥的旧记录，本身就是 Cursor 自己的风险。

主持：Cursor 也认了这一点。补救措施里，推理全部撤离 Fireworks，所有内部凭证全部轮换，扩展市场推倒重建。

解读：还给所有代码库加了密钥扫描。开发者 Daniel Avila 说得很准：问题不在保存历史记录，而在没把它们保护好。

主持：所以对用户来说，最实际的一件事：如果你在那十一个小时里装过或者更新过那个扩展，按官方公告去检查。

解读：公告里还特别提醒，光卸载扩展可能不够。

重点二：始终在线的智能体，其实大部分时间在睡觉

主持：重点二，Anthropic 在 Claude 官网发了一篇指南，讲怎么做始终在线的智能体。

解读：它的第一个观点就挺反直觉：始终在线只是用户的感受。智能体平时在睡，有事才被叫醒跑一次。

主持：睡着的时候不调用模型，也就不花钱。那叫醒它的是什么？

解读：一个收件箱。用户消息、外部通知、定时任务，全都先写进收件箱，再由一个工作进程领出来处理。

主持：为什么不让每个来源直接去叫智能体？听着更省事。

解读：两件事同时到，就会起两次互相打架的运行。进程一崩，事件就丢了。收件箱能记状态、能去重、能重试。

主持：我觉得这里最实用的一条建议是：用户连发好几条消息，就合并成一次运行，只回一次。

解读：第二个部件是计时器。分两种，一种是智能体给自己定的跟进，比如过两天看看对方回没回；一种是固定日程。

主持：第三是记忆。它有句话我很认同：记忆里只放以后查不到的东西，别处已经有的，存个指针就行。

解读：第四是权限，这是风险最大的地方。凭证不放进智能体里，由外面的代理在发请求时再补上。

主持：真正重要的决定，还是要停下来等人拍板。它管这叫延迟的工具调用。

解读：第五是发件箱，决定什么时候开口。它的建议是，一开始让智能体安静一点，慢慢再赢得你的注意力。

主持：中文技术博主 meng shao 的评价是，这些部件单独看都不新，很多团队早就用队列加定时任务拼过。

解读：可我觉得这正是它的价值。把每个部件的职责划清楚，比发明一个新东西有用。

主持：宝玉顺着这个话题，聊了另一个痛点：一个主会话不透明，一堆会话又太累。

解读：他理想中的样子是，人只盯主会话，协调器判断每句话属于哪个任务，但每个任务都能点开去干预。

重点三：黄仁勋走后，开放模型谁来撑腰

主持：重点三，英伟达的余波。这两天刷屏的，是一封叫「和黄仁勋站在一起」的公开联名信。

解读：levelsio 转发呼吁联署，李博杰说自己签了。据转发的消息，马斯克也说会签。

主持：我觉得签名本身改变不了什么，但它说明，开发者圈对这件事的情绪还很浓。

解读：比情绪更值得看的，是 Interconnects 作者内森·兰伯特的一篇长文，题目叫《没有黄仁勋的开源 AI》。

主持：他的核心担心是什么？英伟达总不至于不支持开放模型了吧。

解读：经济动机还在，英伟达不希望少数大客户自研芯片、集中权力。但眼下头号任务是稳住公司，按时交货。

主持：也就是说，黄仁勋那种创始人式的大手笔下注，很可能会断。

解读：而且他更担心监管。他说开放生态需要一个出了危机能接电话的人，黄仁勋扛这面旗大概两年了。

主持：他还引用了 SemiAnalysis 的迪伦·帕特尔：做出比 Kimi、DeepSeek 更好的开放模型，不是钱的问题。

解读：是人才的问题。最顶尖的人主要在几家闭源实验室，剩下的又分散在上百家创业公司。

主持：他觉得 Thinking Machines 的 Inkling 二 Small，是最近最好的西方开放权重模型，但离 Kimi 还远。

解读：李博杰有个不太一样的角度。他说英伟达要是真想彻底卡死中国公司用卡，技术上有的是办法。

主持：比如要求数据中心的卡定期连激活服务器，再用网络延迟识别是不是跨境。

解读：但英伟达没这么做。他的意思是，这个世界上大多数人还是相信科技向善。

主持：我更站兰伯特那边一点。一个生态如果要靠一个人挡子弹，这本身就是脆弱的。

重点四：四比特训完一个模型

主持：重点四，Thinking Machines 公开了一套低精度训练方案，用在 Inkling 二 Small 上。

解读：简单说，就是训练时用更粗糙的数字格式。数字越粗，算得越快，但四舍五入的误差会越积越多。

主持：那他们怎么平衡？全程都用四比特，听着就很冒险。

解读：他们一开始试过全程四比特，准确率掉得没法接受。最后的分法是，前向计算用四比特，反向更新用八比特。

主持：前向和反向，为什么区别对待？

解读：反向更新是很多数据一起平均，随机误差会被摊薄，但它怕系统性的偏差。所以反向用更精细的格式，再配上随机舍入。

主持：结果呢？我关心的是到底省了多少。

解读：在他们最大的任务上，比全程八比特，预训练快了百分之八，强化学习快了百分之二十。

主持：百分之八听着不多，但放到几周的训练上，就是实打实的机时。

解读：还有个好处：从预训练到最后都用同一套数字配置，训完不用再单独做量化校准。

主持：文章里还有个数字：这个模型六十八个小时就完成了预训练。这个数字要放对位置。

解读：没错，他们自己说，几个月前同规模要好几周，六十八小时是很多改进叠加的结果，数字格式只是其中一项。

主持：我觉得这条和前面兰伯特的文章能连起来看：西方开放模型想追，靠的就是这种工程上的硬功夫。

重点五：让智能体先攻击自己

主持：重点五，安全攻防。Shopify 公开了一套内部系统，名字叫网络混沌猴子。

解读：名字是致敬奈飞当年的混沌猴子。思路一样，主动制造问题，看系统扛不扛得住。

主持：不同的是，这次上场的是智能体，而且直接对着生产环境攻击。这不吓人吗？

解读：Shopify 的理由是，模型让找漏洞变得太便宜了。他们的漏洞赏金报告，自二零二四年以来涨了将近百分之三百。

主持：也就是说，外面的人已经在用模型找了，自己不先找，就只能被动挨打。

解读：对，所以他们把源码、历史报告和测试店铺的凭证交给进攻的智能体，让它像赏金猎人一样去打。

主持：我最感兴趣的是怎么拴住它。

解读：每个任务单独一个容器，没有提权，出口只放行白名单。另外还有一个裁判智能体，用不同的模型实时读日志。

主持：一发现危险动作，裁判就叫停。裁判自己出问题，任务也会结束。

解读：Shopify 说已经跑了上万次进攻，找到几十个有实际影响的问题，没造成过一次停机。

主持：正好可以对照 Semgrep 首席执行官在斯坦福的一堂课。他说已公开的漏洞里，真被利用的只有大约百分之二。

解读：但几个低危问题串起来，可能就变成严重漏洞，而大模型恰好擅长串。所以他不信把漏洞全修完这条路。

主持：他主张让攻击变得更贵。我觉得 Shopify 这套做法，正是这个思路的一种落地。

重点六：路演里的一张算力效率图

主持：重点六，一张幻灯片引发的讨论。前 Anthropic 员工雅各布·考克森说，这张图是他离职的重要原因。

解读：图来自 Anthropic 的上市路演，画的是预训练的算力效率随时间的变化，纵轴是对数坐标。

主持：对数坐标上还一路往上，意思是达到同样的水平，需要的算力在成倍地往下掉。

解读：他还说，现在已经可以用原来一小部分的算力，重新训练出 Mythos。

主持：李博杰的解读是，人类水平的 AI 会被商品化。

解读：他说这跟刘知远二零二三年提的密度定律是一回事：同等水平的模型，推理成本每年降大约十倍。

主持：那他的推论呢？

解读：个人智能体会回到渠道为王。拥有设备和流量入口的平台，优势会很大。

主持：可我有点不同意推得这么远。这张图的具体数字没公开，我们看到的都是两个人的解读。

解读：这个提醒很必要。考克森自己也说，这不严格等于纯软件的智能爆炸，因为研发投入也在涨。

主持：我能接受的结论是：训练越来越便宜，这个趋势大概率是真的；谁会赢，还早。

评论一：旧记录，是新的高价值数据

主持：评论第一件，回到 Cursor。我想说的是，智能体的历史记录，已经成了一种新的高价值数据。

解读：它比代码还敏感。代码里一般不会写密钥，但人在跟智能体干活时，经常随手把密钥贴进去。

主持：而且这些记录又特别有用，拿去训练模型、做离线分析，谁都舍不得删。

解读：所以矛盾就在这儿：留着有价值，留着也有风险。我觉得至少，进存储之前得先脱敏。

主持：我更进一步，交给外部合作方的那份数据，应该默认是会泄露的。

解读：这个标准有点严，但这次事件说明，它不算过分。

主持：给开发者一个具体建议：这周翻一下你的智能体对话记录，看看里面有没有贴过真实的密钥。

解读：有的话，先把那把密钥换掉，比什么都实在。

评论二：先安静，再赢得注意力

主持：评论第二件，Anthropic 那句建议：让智能体一开始安静一点。我觉得这是整篇里最有分量的一句。

解读：正好呼应前两天 Deepnote 的基准。模型不该插话的时候，有四成会插嘴。

主持：太吵的助手，用户第一周就会把它静音。之后它再有要紧事，你也看不到了。

解读：可我觉得太安静也有代价。它漏掉一件重要的事，信任掉得可能比吵还快。

主持：所以它建议做评测去找平衡点，而不是凭感觉调。

解读：换我我会先从「只汇报结果、不汇报过程」开始，再看用户愿不愿意多听。

主持：如果你在做这类产品，可以先数一数：你的智能体一天主动发几条消息，用户点开了几条。

评论三：生态不能只靠一个人

主持：评论第三件，开放模型和黄仁勋。我想先问：一个生态到底该不该依赖某一个人？

解读：理想上当然不该。但兰伯特说得很现实，危机来的时候，得有人能打电话、能说上话。

主持：我觉得这暴露的，是美国开放模型阵营的组织能力很弱，钱有，但没有共同的代言人。

解读：可我有点不同意只看美国。开放模型的人才和成果，很大一块在中国，Kimi 和 DeepSeek 都是例子。

主持：这正是兰伯特担心的另一面。他觉得一旦出现跟中国开放模型有关的安全事件，监管可能会来得很草率。

解读：所以他的结论是，开放模型的支持者需要重新结盟，去找超大云厂商这样的新靠山。

主持：我的判断是，短期看英伟达的资金会不会缩，长期看有没有一家美国公司，真正把开放当主业。

评论四：智能体涌进档案馆

主持：最后一件，是个小故事。宾大教授伊森·莫利克，让 Fable 五点二重建诗人奥登一九四一年的诗歌课。

解读：那门课号称人文学科最难，资料早就散了。智能体在互联网档案馆找到一本冷门的书。

主持：然后它的读法很特别：靠一遍遍全文检索，一行一行地读。

解读：结果重建得相当好。但莫利克自己也提醒，研究型的智能体群会带来巨大的流量，它们不知疲倦。

主持：我觉得这是开放知识的新难题。档案馆是为人设计的，一个人一天能翻多少页？

解读：可他又不希望设太多门槛，把正当的学术研究挡在外面。他事后给档案馆捐了款，但说这不是长久之计。

主持：昨天我们聊过印度语维基的读者在流失。这边是机器读者在暴涨，两件事放在一起看挺讽刺。

解读：换我会建议，让智能体用档案馆的批量接口，而且用完记得捐一点。公地是要有人养的。

收尾

主持：今天的主线，是智能体越来越能干，也越来越需要被管住：钥匙、权限，还有什么时候该开口。

解读：另一条，是开放生态的韧性，从英伟达，到档案馆。

主持：原帖和文章链接都在网页上。

解读：祝你周末愉快。明天早上，我们接着聊。

  • #Anthropic《Building always-on agents》：始终在线 agent 的五个部件长文
    Claude 官网 · meng shao · 宝玉 · 宝玉（主会话与 Session）

    Anthropic 应用 AI 团队的 William Hu 在 Claude 官网发布指南。核心观点：「始终在线」只是体验，agent 大部分时间在休眠，被事件唤醒跑一次（run）再睡。五个部件：事件收件箱（所有来源先把事件写进持久化列表，由一个 worker 领取，同一收件箱同时只有一个活跃 worker，连发的消息合并成一次运行）；计时器（跟进和日程两类，由调度器轮询到期项再往收件箱加事件）；

    记忆（只存以后查不到的东西，别处已有的只存指针）；权限（凭证由 agent 环境外的代理注入，高风险动作用自动模式的分类器审，重要决定用「延迟工具调用」等用户批准）；发件箱（控制什么时候开口，建议「先安静，再逐步赢得用户注意力」）。文中称在一项长周期编程基准上，Opus 5.5 每个解决任务的成本比 Opus 5 低 78%（Anthropic 自报）。

    meng shao 评价这些部件「单独看都不新」，价值在于职责划清；宝玉做了一期中文讲解。宝玉另发帖讨论交互形态：只有一个主会话，子任务不透明；一堆 Session，人又得自己记住谁在干什么，理想是人只盯主会话、由协调器判断消息归属，但每个任务都能点开干预。
