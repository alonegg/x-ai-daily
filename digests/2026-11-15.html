  • #Shopify Cyber Chaos Monkey：带内部知识的 agent 在生产环境做受控攻击，另派一个 agent 当裁判长推
    Shopify Engineering · meng shao

    Shopify 工程博客介绍内部系统 Cyber Chaos Monkey，名字致敬 Netflix 的 Chaos Monkey。理由是前沿模型让发现漏洞越来越便宜，Shopify 漏洞赏金的报告量自 2024 年以来增加了近 300%，他们决定抢先找。

    进攻 agent 手里有源码、威胁情报、历史报告和真实测试店铺的凭证，向线上系统发真实请求；隔离层包括每个任务一个独立的 Kubernetes Job、无提权容器、凭证代理和出口白名单；另一个用不同提示和不同模型的「裁判」agent 实时读日志，发现危险行为就终止任务。

    Shopify 称已执行上万次进攻任务，发现并处理几十个有实际影响的问题，没有造成停机或事故。

  • #Anthropic《Building always-on agents》：始终在线 agent 的五个部件长文
    Claude 官网 · meng shao · 宝玉 · 宝玉（主会话与 Session）

    Anthropic 应用 AI 团队的 William Hu 在 Claude 官网发布指南。核心观点：「始终在线」只是体验，agent 大部分时间在休眠，被事件唤醒跑一次（run）再睡。五个部件：事件收件箱（所有来源先把事件写进持久化列表，由一个 worker 领取，同一收件箱同时只有一个活跃 worker，连发的消息合并成一次运行）；计时器（跟进和日程两类，由调度器轮询到期项再往收件箱加事件）；

    记忆（只存以后查不到的东西，别处已有的只存指针）；权限（凭证由 agent 环境外的代理注入，高风险动作用自动模式的分类器审，重要决定用「延迟工具调用」等用户批准）；发件箱（控制什么时候开口，建议「先安静，再逐步赢得用户注意力」）。文中称在一项长周期编程基准上，Opus 5.5 每个解决任务的成本比 Opus 5 低 78%（Anthropic 自报）。

    meng shao 评价这些部件「单独看都不新」，价值在于职责划清；宝玉做了一期中文讲解。宝玉另发帖讨论交互形态：只有一个主会话，子任务不透明；一堆 Session，人又得自己记住谁在干什么，理想是人只盯主会话、由协调器判断消息归属，但每个任务都能点开干预。

  • #开发工具速递
    Addy Osmani · Claude 选型指南 · 向阳乔木 · Daniel Avila（数据库） 等 9 位

    Addy Osmani 建议把 Opus 5.5 中档思考作为日常主力，吃力时先调高思考档位再换模型，最难的大迁移、长时间无人值守任务再用 Fable 5.2；他引用的一份公开评测里，在 Claude Code 的 52 个编程任务上，Fable 5.2 解题率 82.7%、Opus 5.5 为 84.6%，但每个解决任务的成本是 Opus 的 2.8 倍。
