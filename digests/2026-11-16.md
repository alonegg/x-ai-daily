## Agent 与开发工具
- **Lauren Tan《All Code Is Slop (Except Mine)》：Grok Bot 团队一个月合并 1.1 万个 PR，撤回率约 0.5%** {#lauren-tan-slop} [长文]：SpaceXSI 首席工程师 Lauren Tan 在 AI Engineer Code Summit 主舞台做了 17 分钟分享。她说自己上个月往生产环境合并了 3000 个 PR，其中不少是在睡觉时合进去的；团队一个月合并约 1.1 万个 PR，撤回约 0.5%，应用比刚发布时还快。方法上她用「倒金字塔」安排投入：底层是接口设计、架构，以及 lint、类型系统、编译器和测试，用来限制 agent 能写出什么；往上是运行时验证和形式化验证；最上面才是少量书面规则和 AGENTS.md。几条具体做法：每纠正 agent 一次，先想能不能写成可重复的检查；代码库是 agent 最主要的输入，坏写法会被下一个 agent 当惯例照抄，所以要保持干净；React 的 useEffect 在产品代码里禁用，只在自研框架 Dune 内部允许；用 electron-main 和 electron-renderer 两个顶层目录加 lint 规则禁止跨边界导入；禁掉 99% 的代码注释；让 agent 自己把程序跑起来、交录屏和截图，她的 token 大部分花在这一步。她的结论是：先打好地基再谈全自动，否则全自动只会更快地产出烂代码。李博杰评论说，这么大的代码库一个月合 1.1 万个 PR 而功能基本没回退，非常快。同一团队的 Lauren 和 Roman Ugarte 还上了 YC 的 Lightcone 播客，讲七周从第一行代码到上线 Grok Bot；meng shao 提醒，访谈中「每月 4000 个 PR」之类的数字是自述，没有独立审计。swyx 说大会第一天直播是史上最快破 10 万观看的一次。来源：[宝玉（要点）](https://x.com/dotey/status/2121835140850602200) · [meng shao（长文）](https://x.com/shao__meng/status/2121947842050982253) · [AI Engineer（经 swyx 转发）](https://x.com/swyx/status/2122031609117647281) · [李博杰](https://x.com/bojie_li/status/2121853649173528786) · [meng shao（Lightcone 访谈）](https://x.com/shao__meng/status/2121791852559188373) · [swyx](https://x.com/swyx/status/2121896675048587765)
- **Claude Code 实验功能 Code Mode：先写一段 JavaScript，一次调多个工具** {#claude-code-mode} [长推]：Claude Code 2.1.325 起可以实验性开启 Code Mode（环境变量 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1）。开启后，Claude 不再一次调一个 Bash、Read 或 Edit，而是写一段 JS 在本地会话里批量调用工具：独立命令可以并行，上一步结果直接传给下一步，大量中间输出先在代码里过滤，只把需要的部分放进上下文。官方例子是把重试上限从 3 改成 5：找文件、改参数、跑测试、只回传路径和测试输出，原来四五轮的操作一步做完。限制不少：只支持终端交互会话；只支持 Opus 5.5、Sonnet 5.5、Haiku 5.5 和 Fable 5.2；不能走网关、Bedrock 等；前台代码最长跑 10 分钟、后台最长 2 小时；写在项目设置文件里不生效，避免克隆来的仓库偷偷打开。权限上，每次工具调用仍过 deny、ask 规则和 PreToolUse 钩子，但 auto 模式的分类器改为审整段代码、看不到运行时才算出来的值，官方建议必须管住的调用靠规则或钩子兜底。来源：[Daniel Avila](https://x.com/dani_avila7/status/2121789088499933223) · [meng shao](https://x.com/shao__meng/status/2121899873083764877)

## 模型、训练与研究
- **OpenAI 开科学博客；首篇：GPT-6 Astra 帮物理学家写出标准模型格点定义的证明** {#openai-lattice-sm} [长文]：OpenAI 上线科学博客，专门发研究者用 AI 推进科学发现的一手记录。首篇客座文章作者是加州大学圣塔芭芭拉分校粒子理论组负责人、OpenAI 访问科学家 Nathaniel Craig。问题背景：标准模型在实验上极其成功，但一直缺少「非微扰」定义，也就是不把相互作用当作小修正来处理的严格定义；放到格点（把时空离散成网格）上时，弱相互作用只作用于左手粒子，最直接的格点规则会多冒出不想要的右手「替身」（doubler）。重叠费米子能去掉替身，但相位怎么定，对完整标准模型已经悬了 25 年以上。Craig 的思路是把同一组场依次放到更细的网格上，逐级比较、累加得到相位修正；他说 GPT-6 Astra 提出了把场搬到更细网格的正确方式，证明了比较会收敛，并主导写出详细证明；三位格点场论专家 Maarten Golterman、Andreas Kronfeld、Yigal Shamir 审阅并提问。结果是一个「候选」非微扰格点定义，前提是格点尺度上的场强有上界；Craig 自己强调这更像原则上的答案，离实用的格点模拟还远，下一步要看它在有限格距下是否满足反射正定性。来源：[OpenAI（文章）](https://openai.com/index/step-toward-defining-the-standard-model) · [OpenAI（科学博客）](https://openai.com/index/our-new-blog-for-science)

- **论文速递：视觉模块该放哪、差演员也能当好老师、SimpleHC、FinDendro** {#papers-1116}：Meta 和纽约大学研究视觉多模态模型设计：视觉编码器可以跟主模型从零一起训；必须保留图像专用参数，否则要多花 3 倍算力才能追平；专用参数嵌进语言模型前八层效果最好，17 亿参数模型在 H200 上首字延迟从 64 毫秒降到 37 毫秒。JEV 当「老师」能把 15 亿参数策略在 ALFWorld 上的成功率从 72.8% 提到 82.9%，哪怕是它自己做不好的任务。SimpleHC 发现超连接（Hyper-Connections）只需简单的门控、不做混合就能达到 mHC 的质量，共享内存访问让 150 亿和 300 亿参数 MoE 的训练开销降 62% 到 76%。FinDendro 发现 GPT-5 能答对 76% 的受控事实，却只声称知道 38%，这会让金融回测失真。另有 InfraRSI（分布式训练基础设施优化 agent，最高提速 2.75 倍）和 Open Vision Banana（基于 FLUX.2 把图像生成模型变成分割、深度、法线统一感知模型，全部开放）。来源：[Meta/NYU（Gorden Sun）](https://x.com/Gorden_Sun/status/2121806966062485776) · [JEV](https://x.com/HuggingPapers/status/2121878360133341452) · [SimpleHC](https://x.com/HuggingPapers/status/2122059973114962262) · [FinDendro](https://x.com/HuggingPapers/status/2121759891912048880) · [InfraRSI](https://x.com/HuggingPapers/status/2121938850146861226) · [Open Vision Banana](https://x.com/HuggingPapers/status/2121817605396664807)
- **李博杰：照抄 Moshi 做全双工语音不是正路** {#full-duplex-voice} [长推]：李博杰认为关键问题是「不能用说话来思考」：今天所有类 Moshi 的全双工模型，包括 GPT-Live 1，都要把工具调用委托给后台慢思考模型，两来两回导致延迟高。他现在倾向「语义 VAD + 多模态大模型 + 流式 TTS」的三段式：由语义 VAD 决定何时触发模型，开口、停下、改口都由模型决定，说话本身也可以是一次工具调用。他引用的原帖指出 Moshi 每个文本 token 与一帧音频锁死，无法暂停音频时钟去「静默思考」。来源：[李博杰](https://x.com/bojie_li/status/2121903370609062376)

## Jupyter 社区与自动运行
- **pyOpenSci：维护者谈 AI 贡献，最在意的是「看不见另一头的人」** {#pyopensci-ai-contrib} [长文]：pyOpenSci 在 EuroPython 2026 组织了一场试点焦点小组，15 位来自科学 Python 核心项目和 Linux 项目的维护者聊了两个多小时。原以为会集中在审 AI 代码费时间，结果反复回到「人与人的联系在流失」：分不清对面是 agent 还是真人（有人怀疑贡献者是 agent，结果是真人「昨晚自己写的」）；借助 AI 的贡献者觉得自己什么都能做，不再和维护者交流；为了刷简历和 GitHub 资料的「刷 karma」式批量 PR 变多，有维护者宁可自己重做 bot 的小修复也不想把功劳记给 agent。与会者一致认为全面禁止 AI 是错的，只会把使用藏起来；更好的做法是先开 issue 再提 PR、披露 AI 使用、质量标准不变，有人甚至要求贡献者开个会证明自己是在乎项目的真人。不要一律贴「AI slop」标签，关键看对方愿不愿意投入精力参与。这是 Sloan 资助研究的一部分，后续会做问卷。来源：[pyOpenSci](https://www.pyopensci.org/blog/when-the-human-disappears-europython.html)
