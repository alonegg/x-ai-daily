  • #Claude Code 团队怎么做验证：端到端、属性、差分三种测试，加一套「防作弊」规则长文
    Anthropic 开发者博客

    Addy Osmani 在 Anthropic 开发者博客写道，Claude Code 团队约 90% 的代码由 Claude 编写和审查。内部测试里，让单独的评分器按评分表检查 Claude 的结构化文件生成，任务成功率最多提高 10 个百分点，越难的题提升越大。

    推荐三种测试：端到端测试最难被糊弄；属性测试（如编码再解码得回原值、余额永不为负、操作做两遍等于一遍）用测试库生成成千上万输入；差分测试拿旧系统当标准答案，适合大规模迁移。团队做法：在仓库里放名为 verify 的 skill，让 Claude 提交前把应用真正跑一遍；检查连续三轮还失败就停下叫人；维护一份 39 项的可靠性清单，每项都有能从 diff 里读出的触发条件，Claude 只查命中的那几项（通常 3 到 10 项）；

    不靠叠加更贵的第二个审查者，而是调好一个审查者并写 REVIEW.md；审查规则从基础分支读取，改动不能修改评判它的检查；每个 commit 标注验证方式（包括「none」），新闸门先用 observe 模式只记录不拦截。不稳定的测试不许加 sleep 或反复重试，找不到根因就删掉并写明原因。

  • #Philipp Schmid：harness 删掉 90%，分数差不到 6 分，费用差一倍多长文

    Google DeepMind 的 Philipp Schmid 在 AI Engineer Code Summit 2026 分享，他大约每半年把编码 agent 的运行框架推倒重来一次，最近只留一个 Bash 工具，计划和记忆都放进文件系统；系统提示加工具定义从 2025 年中期 16 个工具约 12400 token 降到 574。

    用 Gemini 4 Carbon 跑 DeepSWE 1.1 的一道题，8 个结构化工具走了 47 次模型调用、4.2M token，只用 Bash 是 18 次、1.7M token。在他自有的 350 多项任务上用 Gemini 4 Argon 比较四种框架，分数落在 6 分以内、token 相差 39%；只用 Bash 分数最高（74.9%）却最贵（每项 5.33 美元），最省的是 Bash 加看图工具（每项 2.33 美元、89% 缓存命中）。

    他强调每项任务只跑了一次，小的分差可能是噪声；而且弱一些的模型（Gemini 3.5 Flash）删了工具也不会自己学会合并步骤。下一步可能是让模型直接写 TypeScript 或 Python 执行。转述与解读：shao__meng · 演讲文字稿

  • #主会话用便宜模型、子线程用强模型？宝玉的分法长推
    宝玉 · 回应

    宝玉认为「主会话 + Thread」模式优化好了 token 消耗还好：主会话像公司前台，只负责甄别和路由，Sonnet 5.5 级别就够；真正干活的 Thread 用更强的模型（他在 Claude Project 里主会话用 Sonnet 5.5、子任务用 Opus 5.5）。

    主会话消息稀疏、缓存难命中，缓存过期后只发最近几条加会话检索；Thread 则建议在缓存快过期（如一小时缓存的第 50 分钟）时压缩上下文。有网友做数学研究，认为统筹的主 agent 应该更强；宝玉回应两者场景不同，具体研究任务就该让强模型（如 Fable）计划、调度和验收。
