- **Uber AutoClean：AI 清理 1.6 万个过期 feature flag、百万行代码** {#uber-autoclean} [长推]：meng shao 整理 Uber 工程博客。删代码比写代码难：把 flag 内联成 true 后，还要判断参数能否删（查所有调用方）、旧分支是否不可达、配置是否被别处依赖、测试该删还是改写，静态工具擅长确定性改写，AI 的价值在这些「传播决策」。三阶段：改写阶段 agent 负责搜索编辑，布尔代数和条件化简通过 MCP 调 Uber 的确定性引擎 PolyglotPiranha（化简出错会悄悄改变线上分支）；修 CI 阶段以 monorepo 全量 CI 为准，先用便宜的确定性修复器，处理不了再交给 agent，并收窄权限——测试修复器只能改测试文件，否则 agent 会改生产代码让测试通过；验证阶段先跑静态检查再交给 CodeCourt：把观察到的失败模式写成正确性属性（只删不增、行为语义不变、不偏离目标、不留推理注释等），每条由一个专门审查 agent 并行检查，任一失败就放弃该 diff，单 agent 端到端审查效果不如拆开。原因是指令一多长任务 agent 就会漏约束、只追「CI 通过」，所以把约束移到验收端。来源：[meng shao @shao__meng](https://x.com/shao__meng/status/2112723092468605242)
