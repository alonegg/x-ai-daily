开场与头条预告

主持：早上好，今天是十一月十六号，星期一。这里是 X 每日 AI 播报。

解读：新的一周，周末攒下来的东西还不少，咱们挑最有嚼头的聊。

主持：头一件，据《金融时报》报道，黄仁勋正在考虑重回英伟达，当 CEO。

解读：上周三他才刚辞职，独立调查还没结束，这就已经在谈回来了。

主持：第二件，SpaceXSI 的工程师劳伦·谭讲了她们团队怎么一个月合并一万一千个代码合并请求。

解读：数字很吓人，但她真正讲的是怎么让智能体少写烂代码，这个后面细聊。

主持：第三件，OpenAI 开了个科学博客，第一篇是物理学家写的，说 GPT 六 Astra 帮他写出了一个证明。

解读：证明的对象是粒子物理里的标准模型，悬了二十多年的一块拼图。

主持：另外还有 Claude Code 的新玩法，和一批 Lovable 应用的数据暴露。

解读：最后评论环节，咱们聊聊开源维护者为什么说，想看见屏幕另一头的人。先过快讯。

快讯

主持：先看开发工具。阿里开源了一个代码审查工具，叫 OpenCodeReview，说是内部打磨了两年。

解读：能按具体行号给修改意见，也能接进 Claude Code 或者 Codex。内部已经有几万名开发者在用。

主持：准确率比通用工具高、还更省钱，这些是官方的说法，还得看大家实际用下来怎么样。

解读：对，代码审查这块现在挤得很，上周 Cohere 刚收了一家做审查的团队，阿里这时候开源，挺有意思。

主持：第二个是给 ChatGPT 用户的小技巧。你在家里一台小电脑上搭了个 MCP 工具服务，现在不用公开到网上了。

解读：MCP 就是让模型调用外部工具的一套接口。OpenAI 出了个隧道客户端，建一条安全通道，ChatGPT 就能直接连。

主持：说白了，不用自己做登录鉴权，也不用部署到服务器。自己用的小工具，这样最省事。

解读：我倒觉得要提醒一句，通道是安全了，但你那台机器上的工具能干什么，还是得自己管住。

主持：本地模型这边，llama.cpp 正式到了一点零版。这个在自己电脑上跑大模型的老牌项目，终于发了稳定版。

解读：还有华为的一篇论文，叫 MACaQ，一套四比特量化方法，文本、图像、视频、音频、三维都能用。

主持：量化就是把模型压小一点，好在普通显卡上跑。它有个数字挺唬人。

解读：一个一千二百二十亿参数的模型，三十二点五 G 显存，六十四分钟就量化完了。预量化好的文件也放出来了。

主持：DHH 说他的 Linux 发行版 Omarchy，在英伟达新的 N 一 x 芯片上，十八秒就装完了。

解读：装完马上提示你下载本地模型。他的态度一直很鲜明：这些东西本来就不该又难又慢。

主持：再看研究。Meta 和纽约大学研究视觉多模态模型该怎么搭，有个结论挺实用。

解读：处理图像的专用参数，最好直接嵌进语言模型的前八层。放到中后层反而拖后腿。

主持：而且这样首字出来更快。十七亿参数的小模型，响应时间从六十四毫秒降到三十七毫秒。

解读：还有一篇叫 JEV 的挺反直觉：一个自己做事做不好的模型，当老师却能教得很好。

主持：它带的一个十五亿参数的小模型，在家务模拟任务上，成功率从七成多提到了八成多。

解读：金融这边有篇论文叫 FinDendro，测的是模型知不知道自己知道什么。

主持：结果 GPT 五能答对百分之七十六的事实，却只承认自己知道百分之三十八。

解读：这对拿模型做金融回测的人是个警告。它嘴上说不知道，其实早就知道答案了，回测结果就不干净。

主持：还有一条只能算传闻，说 Claude 从哥德尔用速记写的笔记里，找出了他当年声称做过的一个证明。

解读：故事很精彩，但我们只看到二手转述，没有看到原始报道，听听就好。

主持：安全方面，Anthropic 有个网络安全验证计划。通过了，做防御工作时被拦得更少。

解读：比如分析恶意软件、验证漏洞、处理安全事件。个人研究者和开源维护者也能申请。

主持：另一条转帖说，美国联邦调查局发通告，提醒防范一个叫 ARTEX 的开源渗透平台。

解读：这条同样没核到官方原文，先当线索。但智能体帮着自动攻击，这个趋势是真的在发生。

主持：智能体设计上，有几条经验挺接地气。第一条是，先写评测，再写智能体。

解读：先把怎么算对定下来，之后每改一次模型、工具，都在同一套题上重新打分，不靠感觉。

主持：第二条来自一家叫 Actively 的公司：别一个客户配一个智能体，改成一类工作配一个。

解读：这样在一个客户那儿学到的教训，别的客户也能用上。同样的错，不用纠正好几遍。

主持：第三条更有意思。向阳乔木转了 Anthropic 一篇文章，说团队共用一个智能体，比每人一个效果好。

解读：他调侃说跟人类组织一样，人一多，责任就分摊了。我倒想看看他们具体怎么测的。

主持：观点方面，Steve Yegge 讲软件工厂，结果最让听众意外的，是他劝大家慢一点。

解读：把 AI 的产出节奏压到人跟得上的速度。他说推得太猛的团队，已经开始出故障了。

主持：投资人加文·贝克有个说法：美国只放较弱的芯片给中国，这个政策是成功的。

解读：他引用的估算说，美中 AI 算力差距从二零二三年的两点八倍拉到今年的八点八倍。这是他的推算，不是官方数据。

主持：还有，Cloudflare 原来押注模型会越来越小，结果越来越大，现在干脆自己训练模型了。

解读：李博杰也发了一个长帖，说照抄 Moshi 那种全双工语音模型不是正路，因为说话的时候没法思考。

主持：他更看好的是三段式：先判断用户一句话说完了没有，再交给多模态大模型，最后流式合成语音。

解读：好处是工具调用的延迟反而更低。这个思路他觉得对视觉和操作电脑也适用。

主持：最后是 Jupyter 和开放科学。有位数学老师在网上问，怎么最省事、最便宜地让全班在云端用 notebook。

解读：回复里有人推荐 nbgitpuller 链接：老师把 notebook 放到代码仓库，学生点一下，就登录进去了，作业也拉好了。

主持：也有人推荐 2i2c，一家专门给学校提供 Jupyter 云服务的非营利机构。另外 JupyterLab 四点六点五修了内存泄漏。

解读：维基媒体那边，有人盘点了志愿者平台 Toolforge 上的工具，光是有多少个，几个来源就对不上，大概四千多个。

主持：他的结论是，工具很少是因为 bug 死掉的，多半是没人维护、也找不到。

解读：这话放到所有开源项目上都成立。好，快讯就到这儿，进重点。

重点一：黄仁勋，可能要回来了

主持：重点一，英伟达。据《金融时报》周日报道，黄仁勋正在考虑重新出任英伟达 CEO。

解读：时间线很紧。十一月十二号，英伟达宣布他辞去 CEO 和董事，CFO 科莱特·克雷斯当临时 CEO。

主持：三天后就传出要回来。而且董事会对他的独立调查，还没结束。

解读：报道说，他一位没公开身份的盟友，正在召集一批硅谷高管组一个作战室，游说董事会让他复职。

主持：还要去争取白宫的支持。这个架势，说白了就是在给董事会施压。

解读：公开站出来的人也多。那封「和黄仁勋站在一起」的公开信，据报道已经超过十万人签名。

主持：其中五千多人自称是英伟达在职员工。马斯克也说自己签了。

解读：投资人那边口气要谨慎一些。两位知名基金经理写信给董事会，希望接班慢一点，把他回归留作选项。

主持：注意，他们没要求他马上复职。我觉得这个分寸挺关键，投资人要的是稳，不一定是黄仁勋本人。

解读：可我有点不同意。对英伟达来说，稳和黄仁勋很难分开，客户、合作方很多是冲着他这个人来的。

主持：这也是为什么预测市场上，他回归的概率一下子跳到了百分之二十。

解读：还有一个挺有意思的角度。有位开发者用一群智能体分析了近两千篇相关报道。

主持：他想看这个故事是从哪儿传开的？

解读：对，用网页排名那套算法看谁引用谁。结论是《纽约时报》是源头，其他几家大报贡献了大部分报道量。

主持：这个分析本身就有立场，他是想说媒体带了节奏。我会把它当一个视角，不当结论。

解读：同意。最根本的一点没变：间谍指控到现在都没证实，回归也只是在考虑。

主持：所以这周值得盯的，是董事会的调查什么时候给结论，范围有没有公开。

解读：这才是决定他能不能回来的那个开关。签名再多，也替代不了调查结果。

重点二：一个月一万一千个合并请求，靠的是什么

主持：重点二，劳伦·谭在 AI 工程师大会上的演讲，题目挺挑衅，叫「所有代码都是垃圾，除了我的」。

解读：她现在负责 Grok Bot 桌面版。开场就说，自己上个月往生产环境合了三千个合并请求，不少是睡觉时合进去的。

主持：整个团队一个月合了一万一千个，被撤回的大概只有百分之零点五。

解读：应用还比刚发布时更快了。李博杰看完说，这么大的代码库，这个速度非常快了。

主持：但我觉得数字不是重点。她真正想说的，是怎么在产出暴涨的时候，代码质量不往下掉。

解读：她画了一个倒金字塔。最底下是架构、接口设计，还有类型系统、编译器、测试这些确定性的东西。

主持：往上是验证，最上面才是一点点写给智能体看的规则文件。

解读：对，最核心的一句话是：每纠正智能体一次，先想能不能写成一条自动检查，而不是往说明文件里再加一行。

主持：道理很简单。写在文档里的话，智能体不一定照做；写成检查，违反了直接报错，提交不上去。

解读：第二点我特别认同：代码库是智能体最主要的学习材料。

主持：你是说，里面的坏写法会被当成惯例？

解读：没错，临时补丁、过时写法，下一个智能体看了会照抄，像杂草一样越长越多。所以代码库得保持干净。

主持：第三点更狠，容易用错的东西直接禁掉。比如 React 里那个 useEffect，人都常用错，智能体更用不好。

解读：她们在产品代码里直接禁了，只在自研框架里允许。这一类问题，从此就不用在代码审查里盯了。

主持：还有一条我有点犹豫：百分之九十九的代码注释都禁掉。

解读：她的理由是，智能体爱在注释里给自己走的捷径找借口，后来的智能体就照着学。

主持：可我觉得对小团队来说，注释有时候是唯一的文档，一刀切太猛了。

解读：这个分歧挺合理。她的场景是几百个智能体同时往里写，跟三五个人的项目确实不一样。

主持：最后一点，让智能体自己检查自己的活：把程序跑起来，像用户一样点一遍，交上录屏和截图。

解读：她说自己的 token 大部分花在这一步。人审代码，就变成看这些材料。

主持：她的结论是先打地基，再谈全自动。地基没打好，全自动只会更快地产出烂代码。

解读：还要补一句，有人提醒过，访谈里这些数字是她们自述的，没有第三方审计。

重点三：AI 写证明，人类专家来审

主持：重点三，OpenAI 开了一个科学博客，专门记录研究者怎么用 AI 推进科学发现。

解读：第一篇是客座文章，作者是加州大学圣塔芭芭拉分校的粒子物理学家，内森尼尔·克雷格。

主持：他要解决的问题，听着很抽象：给标准模型一个严格的定义。

解读：标准模型描述了已知的基本粒子和三种力，跟实验对得极准。但它一直缺一个不靠近似的严格定义。

主持：物理学家平时的做法，是先假装粒子之间没有相互作用，再一点点把修正加回去。

解读：对，这叫微扰。但很多现象靠这套算不出来，比如质子的质量，主要来自里面夸克和胶子的相互作用。

主持：那另一条路，就是把时空切成一个个格子，在格子上算。

解读：这叫格点场论，对强相互作用很成功。麻烦出在弱相互作用，它只认左手粒子。

主持：他用了个镜子的比方：你只放进左旋的光，普通镜子一反射，盒子里就多出了右旋的光。

解读：格子上也一样，你只想要左手粒子，规则会自动送你一个右手的替身。这个问题前人已经部分解决了。

主持：剩下的一块，是一个相位怎么定，对完整的标准模型，悬了二十五年以上。

解读：克雷格的思路是把同一组场放到越来越细的格子上，一级一级比较，再加起来得到修正。

主持：关键在这儿：他说 GPT 六 Astra 不只是帮忙算，而是主导写出了详细证明。

解读：它提出了把场搬到更细格子上的正确方式，还证明了这个比较会收敛。

主持：我觉得这个说法分量很重。以前说 AI 帮科研，多半是查文献、写代码。

解读：但我想泼点冷水。他自己也说，这只是一个候选定义，要靠同行讨论来判断它是不是对的。

主持：而且是原则上的答案，离真正拿来做格点模拟还很远。

解读：三位格点领域的专家帮他审过证明、提过尖锐问题。这一步，我觉得比 AI 写证明本身更重要。

主持：说白了，AI 写得再快，最后还得有懂行的人来把关。

解读：这个分工以后可能会越来越常见：AI 出草稿和证明，人负责提问题、判断值不值得信。

重点四：Claude Code 学会了先写一段程序

主持：重点四，Claude Code 出了一个实验功能，叫 Code Mode，默认是关着的。

解读：打开以后，Claude 调用工具的方式变了。以前是一次调一个，看完结果再决定下一步。

主持：那现在变成什么样了？

解读：现在它先写一小段 JavaScript，在里面一次调多个工具，由 Claude Code 在你本地执行。

主持：官方举的例子，是把重试上限从三改成五。

解读：它会写一段代码：先搜到文件，改参数，跑相关测试，最后只把文件路径和测试结果交回来看。

主持：原来要来回四五轮的操作，现在一步做完。好处我能想到的是快，还省上下文。

解读：对，独立的命令可以并行跑，大量中间输出先在代码里过滤，只把有用的部分塞进上下文。

主持：但限制也不少。只能在终端的交互会话里用，不支持桌面端、云端。

解读：只支持几款最新的模型，前台代码最多跑十分钟。写在项目的设置文件里也不生效。

主持：这条我觉得是刻意的：免得你克隆一个陌生仓库，它就偷偷替你打开了。

解读：我最在意的是权限这块。每次工具调用还会过你设的规则，但自动模式的审查方式变了。

主持：变成审整段代码了？

解读：对，而且看不到运行时才算出来的东西，比如从搜索结果里取出来的文件路径。

主持：那就有点像你批准了一段脚本，但脚本具体删哪个文件，是跑起来才知道的。

解读：所以官方也建议，必须管住的操作，要靠规则或者钩子兜底，别只指望自动审查。

主持：我的看法是，这个功能对重复性的批量改动很香，但默认关着是对的。

解读：想试的话，先在一个不怕弄坏的项目里开，盯一下它写的那段代码，再决定要不要放进日常。

重点五：七千多个应用，不登录就能读数据

主持：重点五是安全。有研究者扫描了十五万九千多个 Lovable 项目，Lovable 就是那种一句话做出应用的平台。

解读：结果发现七千四百零三个应用，不用登录，就能读到含用户邮箱的记录。

主持：有些还涉及私信、护照信息和客户数据。问题出在哪？

解读：出在它们用的 Supabase 数据库，有一项按行控制谁能看什么的权限，没配好。

主持：也就是说，门是装了，但锁没锁上。

解读：可以这么说。而且要讲公平，研究只针对用 Supabase 的应用，Lovable 自己托管的后端没查出同样问题。

主持：但这也不是第一次了。去年三月就有研究在一千多个项目里，找到一百七十个类似的漏洞。

解读：那次还拿到了一个高危的漏洞编号，Lovable 对这个编号有异议。

主持：Lovable 后来加了发布前的自动安全扫描，它们的安全负责人也承认，权限放得太宽是最常见的问题。

解读：但新研究没说清楚，这些扫描是没拦住，还是这些应用是加扫描之前发的。

主持：我觉得责任主要在平台。用户本来就是不懂数据库才来用你的，默认就该锁上。

解读：我倒觉得两边都有份。你把应用发出去收别人的护照信息，就得对这些数据负责，不能全推给工具。

主持：这个分歧挺真实的。那对已经用这类平台做了应用的人呢？

解读：最实在的就是今天试一下：退出登录，直接请求你的数据接口，看能不能拿到别人的数据。

重点六：个人智能体，一人一台虚拟机是不是太奢侈

主持：重点六，聊聊个人智能体的架构。李博杰发了个挺冲的帖子。

解读：他不理解，为什么现在的个人智能体，都要给每个用户分一台云端虚拟机，一个月几十美元成本。

主持：他做第一个智能体的时候，假设是一个服务同时扛很多用户，从来没想过一个人能独占一个进程。

解读：网页用无头浏览器就够了，文件放云盘一类的虚拟文件系统。更没想到，有人敢把密钥放进沙盒里。

主持：但我得替做虚拟机的人说句话。你想啊，智能体要跑用户给的命令、执行自己生成的代码，隔离开是最省心的。

解读：这个我同意一半。安全上虚拟机确实省事，但成本是真的高，很多产品就是把现成的编程智能体换个壳。

主持：他还吐槽了自己的 Claude Code，一个会话跑几天，就占了五个 G 内存，经常卡死。

解读：另一个帖子更有意思，他说日常生活里的 AI，不是越多越好。

主持：家里换了个 AI 水龙头，要先点纯水、再点出水，原来拧一下就行。

解读：扫地机器人每隔几分钟就说一句话。用 Muse 盯会议酒店房价，它每天准点报还没降价。

主持：结果真正降价那个短暂窗口，它没盯到，是他自己写的脚本抓到的。

解读：这个例子太扎心了。主动提醒本身不值钱，在对的时候提醒才值钱。

主持：我觉得这跟上周 Anthropic 那篇指南说的对上了：先安静，再慢慢赢得用户的注意力。

解读：对。他还转了一张图，说豆包手机被一百五十多家应用拒绝接入。

主持：对照的是海外，个人智能体协议在 Shopify 全部店铺都默认打开了。

解读：所以国内的个人智能体，难的可能不是技术，是别人愿不愿意给你开门。

评论一：每纠正一次，就写一条检查

主持：进入评论。第一件还是劳伦·谭那套方法。我觉得它最值钱的，不是一万一千这个数字。

解读：是那条习惯：纠正一次，写一条检查。规则文件里的话会被忘掉，检查不会。

主持：但有人会说，小团队没精力搭这么多检查，写两行说明多省事。

解读：短期是快，可你会发现同样的错一周纠正三次。那时候写一条检查，其实更省事。

主持：我更站中间：先挑最常犯的那一两个错，别想一口气全写成规则。

解读：这个折中挺好。给你一个具体做法：这周记下你纠正智能体最多的那件事。

主持：然后试着把它写成一条代码检查，或者一个测试，看下周还会不会再犯。

评论二：AI 写的证明，谁来签字

主持：评论第二件，回到 OpenAI 那篇物理文章。我想聊的是署名和责任。

解读：克雷格说 AI 主导了详细证明。那以后论文出了错，算谁的？

主持：我觉得还得算人的。他提出了思路，请了专家审，最后是他对外说这个结果可信。

解读：可我有点不同意。如果核心步骤是 AI 想出来的，只说人负责，其实掩盖了真实的分工。

主持：那你的意思是，要把 AI 做了什么写清楚？

解读：对，像他这篇就挺好，哪一步是 AI 提的，哪几位专家审过，都写明白了。

主持：这个透明度值得其他人学。给做研究的听众一个建议：用了 AI 推导，就在论文里写清它负责了哪一步。

解读：最好再找一个不用 AI 的同行，专门挑那几步的毛病。

评论三：维护者想看见另一头的人

主持：评论第三件，来自 pyOpenSci。他们在欧洲最大的 Python 大会上，请了十五位核心项目的维护者聊 AI 贡献。

解读：本以为大家会抱怨审 AI 代码太费时间，结果聊来聊去，都回到一件事：人和人的联系在消失。

主持：有个小故事挺尴尬。维护者说，这看着像 AI 写的，对方回，我昨晚自己写的。

解读：两边都难受。维护者分不清对面是谁，真心来帮忙的人还被怀疑。

主持：还有人为了刷简历，批量提代码合并请求。有维护者宁可自己把那些小修复重做一遍，也不想把功劳记给智能体。

解读：但他们有一点很一致：一刀切禁止 AI 是错的，只会让大家偷偷用，更不透明。

主持：我同意。他们建议先开个议题聊一聊，再提代码，用了 AI 就说一声，质量标准不变。

解读：有人甚至要求贡献者开个会，证明自己是在乎项目的真人。这个门槛我觉得有点高了。

主持：是有代价，维护者花了好多年降低门槛，现在又被迫加回去。

解读：如果你给开源项目提过代码，这周不妨在提交之前，先在议题里跟维护者打个招呼。

评论四：测量追不上能力

主持：最后一件，伊森·莫里克做了个叫 SatBench 的东西，统计 AI 基准被打穿的速度。

解读：二零二三年以来各大实验室引用过的一百七十三个基准，百分之六十三已经饱和了，而且越来越快。

主持：私有基准一开始更难，但掉得一样快。他的原话是，AI 进步得比我们测量得还快。

解读：有个细节挺好玩：这套分析放两年前要做好几天，这次他给模型写了大概四条提示就做完了。

主持：我的担心是，基准一饱和，大家就只能听厂商自己说了。

解读：所以我更相信自己的小题库。拿你工作里真实的十道题，换模型的时候跑一遍，比看排行榜靠谱。

收尾

主持：今天的主线，是把关这件事：董事会怎么把关，代码怎么把关，证明和权限谁来把关。

解读：能力越来越强，真正稀缺的，是判断和兜底。

主持：原帖和文章链接都在网页上。

解读：新的一周，祝你顺利。明天早上，我们接着聊。

  • #Lauren Tan《All Code Is Slop (Except Mine)》：Grok Bot 团队一个月合并 1.1 万个 PR，撤回率约 0.5%长文
    宝玉（要点） · meng shao（长文） · AI Engineer（经 swyx 转发） · 李博杰 等 6 位

    SpaceXSI 首席工程师 Lauren Tan 在 AI Engineer Code Summit 主舞台做了 17 分钟分享。她说自己上个月往生产环境合并了 3000 个 PR，其中不少是在睡觉时合进去的；团队一个月合并约 1.1 万个 PR，撤回约 0.5%，应用比刚发布时还快。

    方法上她用「倒金字塔」安排投入：底层是接口设计、架构，以及 lint、类型系统、编译器和测试，用来限制 agent 能写出什么；往上是运行时验证和形式化验证；最上面才是少量书面规则和 AGENTS.md。几条具体做法：每纠正 agent 一次，先想能不能写成可重复的检查；代码库是 agent 最主要的输入，坏写法会被下一个 agent 当惯例照抄，所以要保持干净；React 的 useEffect 在产品代码里禁用，只在自研框架 Dune 内部允许；

    用 electron-main 和 electron-renderer 两个顶层目录加 lint 规则禁止跨边界导入；禁掉 99% 的代码注释；让 agent 自己把程序跑起来、交录屏和截图，她的 token 大部分花在这一步。她的结论是：先打好地基再谈全自动，否则全自动只会更快地产出烂代码。

    李博杰评论说，这么大的代码库一个月合 1.1 万个 PR 而功能基本没回退，非常快。同一团队的 Lauren 和 Roman Ugarte 还上了 YC 的 Lightcone 播客，讲七周从第一行代码到上线 Grok Bot；meng shao 提醒，访谈中「每月 4000 个 PR」之类的数字是自述，没有独立审计。swyx 说大会第一天直播是史上最快破 10 万观看的一次。

  • #Claude Code 实验功能 Code Mode：先写一段 JavaScript，一次调多个工具长推
    Daniel Avila · meng shao

    Claude Code 2.1.325 起可以实验性开启 Code Mode（环境变量 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1）。开启后，Claude 不再一次调一个 Bash、Read 或 Edit，而是写一段 JS 在本地会话里批量调用工具：独立命令可以并行，上一步结果直接传给下一步，大量中间输出先在代码里过滤，只把需要的部分放进上下文。

    官方例子是把重试上限从 3 改成 5：找文件、改参数、跑测试、只回传路径和测试输出，原来四五轮的操作一步做完。限制不少：只支持终端交互会话；只支持 Opus 5.5、Sonnet 5.5、Haiku 5.5 和 Fable 5.2；不能走网关、Bedrock 等；前台代码最长跑 10 分钟、后台最长 2 小时；写在项目设置文件里不生效，避免克隆来的仓库偷偷打开。

    权限上，每次工具调用仍过 deny、ask 规则和 PreToolUse 钩子，但 auto 模式的分类器改为审整段代码、看不到运行时才算出来的值，官方建议必须管住的调用靠规则或钩子兜底。

  • #个人 agent 架构之争：一人一台虚拟机，还是一个服务扛多个用户长推
    李博杰（虚拟机） · 李博杰（AI 不是越多越好） · 李博杰（豆包手机）
