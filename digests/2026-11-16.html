  • #Lauren Tan《All Code Is Slop (Except Mine)》：Grok Bot 团队一个月合并 1.1 万个 PR，撤回率约 0.5%长文
    宝玉（要点） · meng shao（长文） · AI Engineer（经 swyx 转发） · 李博杰 等 6 位

    SpaceXSI 首席工程师 Lauren Tan 在 AI Engineer Code Summit 主舞台做了 17 分钟分享。她说自己上个月往生产环境合并了 3000 个 PR，其中不少是在睡觉时合进去的；团队一个月合并约 1.1 万个 PR，撤回约 0.5%，应用比刚发布时还快。

    方法上她用「倒金字塔」安排投入：底层是接口设计、架构，以及 lint、类型系统、编译器和测试，用来限制 agent 能写出什么；往上是运行时验证和形式化验证；最上面才是少量书面规则和 AGENTS.md。几条具体做法：每纠正 agent 一次，先想能不能写成可重复的检查；代码库是 agent 最主要的输入，坏写法会被下一个 agent 当惯例照抄，所以要保持干净；React 的 useEffect 在产品代码里禁用，只在自研框架 Dune 内部允许；

    用 electron-main 和 electron-renderer 两个顶层目录加 lint 规则禁止跨边界导入；禁掉 99% 的代码注释；让 agent 自己把程序跑起来、交录屏和截图，她的 token 大部分花在这一步。她的结论是：先打好地基再谈全自动，否则全自动只会更快地产出烂代码。

    李博杰评论说，这么大的代码库一个月合 1.1 万个 PR 而功能基本没回退，非常快。同一团队的 Lauren 和 Roman Ugarte 还上了 YC 的 Lightcone 播客，讲七周从第一行代码到上线 Grok Bot；meng shao 提醒，访谈中「每月 4000 个 PR」之类的数字是自述，没有独立审计。swyx 说大会第一天直播是史上最快破 10 万观看的一次。

  • #Claude Code 实验功能 Code Mode：先写一段 JavaScript，一次调多个工具长推
    Daniel Avila · meng shao

    Claude Code 2.1.325 起可以实验性开启 Code Mode（环境变量 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1）。开启后，Claude 不再一次调一个 Bash、Read 或 Edit，而是写一段 JS 在本地会话里批量调用工具：独立命令可以并行，上一步结果直接传给下一步，大量中间输出先在代码里过滤，只把需要的部分放进上下文。

    官方例子是把重试上限从 3 改成 5：找文件、改参数、跑测试、只回传路径和测试输出，原来四五轮的操作一步做完。限制不少：只支持终端交互会话；只支持 Opus 5.5、Sonnet 5.5、Haiku 5.5 和 Fable 5.2；不能走网关、Bedrock 等；前台代码最长跑 10 分钟、后台最长 2 小时；写在项目设置文件里不生效，避免克隆来的仓库偷偷打开。

    权限上，每次工具调用仍过 deny、ask 规则和 PreToolUse 钩子，但 auto 模式的分类器改为审整段代码、看不到运行时才算出来的值，官方建议必须管住的调用靠规则或钩子兜底。

  • #agent 设计三则：先写评测、按工作类别分 agent、团队共用一个 agent
    vitalflux（经 Harrison Chase 转发） · Actively（经 Harrison Chase 转发） · 向阳乔木 · Steve Yegge（经 swyx 转发）

    Harrison Chase 转发一个用 LangChain deep agents 做采购发票查询的案例：先写评测运行器再写 agent，用小接口加 mock 适配器返回固定测试数据，每次改技能、模型或工具都在同一份黄金数据集上重新打分。

    他还转了 Actively 的经验：从「每个客户一个 agent」改成「每类工作一个 agent」，经验能跨客户复用，同样的纠正不用重复。向阳乔木分享 Anthropic 一篇文章的结论：给团队每个人配一个独立 agent，整体表现不如大家共用一个，他调侃这和人类组织一样，人一多责任就分摊。

    Steve Yegge 在两场大会讲「软件工厂」后总结听众最意外的观点：他劝大家放慢，把 AI 产出的节奏压到人能跟上的速度，推得太猛的团队已经开始出故障。

  • #OpenAI 开科学博客；首篇：GPT-6 Astra 帮物理学家写出标准模型格点定义的证明长文
    OpenAI（文章） · OpenAI（科学博客）

    OpenAI 上线科学博客，专门发研究者用 AI 推进科学发现的一手记录。首篇客座文章作者是加州大学圣塔芭芭拉分校粒子理论组负责人、OpenAI 访问科学家 Nathaniel Craig。问题

    背景标准模型在实验上极其成功，但一直缺少「非微扰」定义，也就是不把相互作用当作小修正来处理的严格定义；放到格点（把时空离散成网格）上时，弱相互作用只作用于左手粒子，最直接的格点规则会多冒出不想要的右手「替身」（doubler）。重叠费米子能去掉替身，但相位怎么定，对完整标准模型已经悬了 25 年以上。

    Craig 的思路是把同一组场依次放到更细的网格上，逐级比较、累加得到相位修正；他说 GPT-6 Astra 提出了把场搬到更细网格的正确方式，证明了比较会收敛，并主导写出详细证明；三位格点场论专家 Maarten Golterman、Andreas Kronfeld、Yigal Shamir 审阅并提问。

    结果是一个「候选」非微扰格点定义，前提是格点尺度上的场强有上界；Craig 自己强调这更像原则上的答案，离实用的格点模拟还远，下一步要看它在有限格距下是否满足反射正定性。

  • #论文速递：视觉模块该放哪、差演员也能当好老师、SimpleHC、FinDendro
    Meta/NYU（Gorden Sun） · JEV · SimpleHC · FinDendro 等 6 位

    Meta 和纽约大学研究视觉多模态模型设计：视觉编码器可以跟主模型从零一起训；必须保留图像专用参数，否则要多花 3 倍算力才能追平；专用参数嵌进语言模型前八层效果最好，17 亿参数模型在 H200 上首字延迟从 64 毫秒降到 37 毫秒。

    JEV 当「老师」能把 15 亿参数策略在 ALFWorld 上的成功率从 72.8% 提到 82.9%，哪怕是它自己做不好的任务。SimpleHC 发现超连接（Hyper-Connections）只需简单的门控、不做混合就能达到 mHC 的质量，共享内存访问让 150 亿和 300 亿参数 MoE 的训练开销降 62% 到 76%。
