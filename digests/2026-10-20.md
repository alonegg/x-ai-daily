## 开发工具与 Agent 工程
- **Addy Osmani 拆解 Claude Code 的分层代码审查** {#claude-code-review-ga} [长推]：后续：meng shao 详细整理了 Addy Osmani 对 Claude Code 团队审查流程的解读：Claude 写了 Claude Code 约 90% 的代码，6 月到 9 月合并的 PR 翻倍以上，回滚率反而降了 40% 多。瓶颈从写代码转向证明代码能用，审查的问题从「有没有人读过」变成「可能出什么问题、该由哪一层抓」。流水线分四层：提 PR 前 Claude 跑测试、构建和 linter 并展示真实输出，再由一个全新上下文的 subagent 独立审 diff；PR 上必需的 CI 阻塞合并，多个 AI 审查 agent 并行找 bug，由「验证者」投票过滤误报（内部 PR 获得实质评论的比例从 16% 升到 54%），另有独立的安全审查；风险由分类器而非作者判定，低风险零人工、中风险一人、高风险（计费、自动更新等）两人，AI 的批准永远不占人工名额；合并后先用 feature flag 内部灰度，每周 on-call，复盘追问「哪一层本该拦住」。两个细节：把历史上引发事故的 PR 做成每日评测集，审查器的任何改动分数不升就放弃；一个 PR 曾一夜被 AI 审了五十多轮，59% 反复标记的是旧代码，于是定下三轮封顶、只审新增 diff，一轮通过率从 65% 升到 78%。人保留方向和品味、高风险审批、架构决策和最终问责。宝玉则调侃：他那期讲「两个 AI 一个审一个改、来回 50 多轮」的视频下面，两个 AI 账号又互相评论停不下来。来源：[meng shao @shao__meng](https://x.com/shao__meng/status/2112007112511607291) · [Addy Osmani @addyosmani](https://x.com/addyosmani/status/2111604705340326393) · [宝玉 @dotey](https://x.com/dotey/status/2111974893676060990)
