## Anthropic 工程与研究
- **Anthropic 把 Messages API 从 Python 整体迁到 Rust：agent 写代码，线上流量当裁判** {#katelyn-lesse-multiagent} [长文]：后续：11 月初 Latent Space 与 Katelyn Lesse 等人的节目里预告过的这次迁移，今天有了完整工程博客。背景是 2024 年初到 2026 年秋 API 流量涨了约 1800 倍，Python 每处理一个请求都要反复创建对象、释放内存，开销成了瓶颈；早先只把解析部分换成 Rust 的增量方案，CPU 只省了 8% 到 10%，还多了跨语言调用的复杂度，于是改为整体重写。Claude 大约一周写出核心请求路径的第一版，但验证成了瓶颈：原有约 700 个集成测试和 Python 实现绑得很紧，审计移植后的测试发现 100 多处断言被削弱；Rust 版 4 月通过了约 98% 的测试，线上真实请求却只有大约四分之一结果一致。团队的做法是把线上 Python 服务当「标准答案」，把生产流量影子复制给 Rust 版，用检查点定位差异发生在哪一步、用「指纹」区分不同 bug；内层循环让 agent 在沙箱里几秒内复现和修复，外层由工程师审 PR 后上线观察，最外层把人工纠正沉淀成 CLAUDE.md 规则和代码检查（6 月一个 agent 梳理了约 60 条评审意见，提出规则，工程师修改后批准）。结果：9 月公开流量全部切到 Rust，每请求 CPU 降约 70%，首字延迟中位数快约 20%，全程不停服、功能开发也没冻结。Latent Space 另外转述：每请求内存降 80% 以上，生产输入一致率从 4 月约四分之一升到 8 月 99.6%，并称团队「没有一个 Rust 开发者」。文章原话：「Verification, not generation, had become the bottleneck.」来源：[Anthropic 工程博客](https://www.anthropic.com/research/migrating-api-to-rust) · [Anthropic](https://x.com/AnthropicAI/status/2125627317263466739) · [ClaudeDevs](https://x.com/ClaudeDevs/status/2125628717263372512) · [Latent Space](https://x.com/latentspacepod/status/2125629574755270872)
- **Anthropic Fellows：回到「神经元」做可解释性** {#anthropic-neuron-basis}：可解释性研究这几年基本放弃了逐个神经元分析，理由有三：一个神经元常对多个不相关输入都激活；同一概念在相邻两层的表示会变；事实知识分散在大量神经元里。新研究换了个角度，不看「什么让神经元激活」，而看「神经元对输出贡献了什么」，结论是这三个问题都比原先以为的小：神经元很少同时输出两个无关概念，输出含义在多数层之间大致稳定，事实虽然分散但仍可读出。第二篇把发现用起来：不做额外训练，仅靠开放权重模型里的神经元，就能检测有害文本、引导模型行为、找出微调模型里隐藏的行为。来源：[Anthropic](https://x.com/AnthropicAI/status/2125365268381929637)
- **Bun 作者 Jarred Sumner：140 个 agent、5 次重写，以及为什么没把 Claude Code 改写成 Rust** {#bun-aot-140-agents} [长文]：shao__meng 整理了 Sumner 在 AI Engineer Code Summit 的演讲。目标是让 Claude Code 更快、更省内存。团队此前做过 Bun 从 Zig 到 Rust 的重写，那次原有 TypeScript 测试能同时检查新旧实现；而重写 Claude Code 要连测试一起迁，「实现和验证依据一起变」，就很难判断行为是否真的保持。于是改走第三条路：给 Bun 做提前编译器。一个多月里 5 次重写，140 个 agent 并行生成代码，长期运行的子 agent 持续修复，用既有测试、差分执行、模糊测试和每小时评分表约束结果。展示的数据是 Claude Code 启动时间从 430 毫秒降到 194 毫秒，等待输入时内存从 158MB 降到 36MB。和上一条放在一起看，两家团队得出同一个结论：先选能验证的路线，再决定让 agent 写什么。来源：[shao__meng 长文](https://x.com/shao__meng/status/2125404503788953647) · [swyx 转发](https://x.com/swyx/status/2125364153263202688)
- **Claude Managed Agents 团队谈「重建三次」的经验** {#claude-managed-agents-arch} [长文]：Claude 官方对谈，Managed Agents 产品经理 Jess Yan、工程师 Michael Cohen 和 Claude Platform 的 Lance Martin 讲平台为什么重做：Anthropic 先为内部提效搭基础设施，再为应用重搭，第三次才意识到很多工作一直在重复。核心思路被概括为三句：让基础设施负责故障恢复，让工作流负责多 agent 协作，让离线整理负责纠正记忆（避免 agent 因记错而反复犯同一个错）。Lance Martin 在另一场演讲里演示让 Claude 在任务之间把公司文档整理成 wiki，实验里「wiki 加搜索」胜过只用搜索。Daniel San（dani_avila7）同时放出 7 个模块的 Managed Agents 教程仓库。来源：[shao__meng 长文](https://x.com/shao__meng/status/2125433198389891545) · [AI Engineer 片段（swyx 转发）](https://x.com/swyx/status/2125364213459865614) · [dani_avila7](https://x.com/dani_avila7/status/2125609655493615757) · [教程仓库](https://github.com/davila7/claude-managed-agents-cookbook)

## 数学与 AI 做科研
- **OpenAI 预印本：矩阵乘法指数 ω 恰好是 9/4** {#openai-matrix-omega} [长推]：宝玉的解读：两个 n×n 矩阵相乘，课本做法要 n³ 次乘法；1969 年 Strassen 把指数降到 2.807，此后几十年一路压到 2.371 附近，今年 8 月 Google DeepMind 借助 AlphaEvolve 降到 2.371177 以下。10 月初 OpenAI 用一个未发布的内部模型把上限直接降到 2.25，随后 Houxi Lü 和 Amanov、van den Berg、Zuiddam 等人类研究者把结果推广到所有数域并写出完整的重新证明，Amir Shpilka 给出了可写出的具体算法。11 月 24 日 OpenAI 在 GitHub 数学仓库放出 111 页预印本，补上下限：用反证法证明，若有算法比 2.25 还快，就能把一项最低成本已有证明的任务做得便宜到不可能。论文还给出各尺寸的具体底线，比如 1024×1024 矩阵按 Strassen 一类方法至少约 590 万次乘法，课本做法约 10.7 亿次。边界：计数规则只数代数运算次数，不管位数和内存搬运，近似计算、低精度量化都不在框架内，所以 AI 训练推理用的矩阵乘法不受影响，GPU 实际一直用课本算法加一两层 Strassen；Lean 证明的是「不用除法」的版本，主定理允许除法，范围更宽；下限部分尚无同行评审，也还没有查到专家对下限的公开评价。Latent Space 补充了几方反应：Sébastien Bubeck 称结合 Lee 等人的旧结果可推出线性规划能在 n 的 9/4 次方时间内求解；Omri Weinstein 说如果成立「truly surreal」，因为多数专家预期 ω 是 2。来源：[宝玉](https://x.com/dotey/status/2125464294401720614) · [Latent Space AINews](https://latent.space/p/ainews-math-proofs-are-landing-faster-than-we-can-read-them/)
- **「证明来得比读得快」：AI 数学成果的十一月** {#ai-math-wave-1126}：Latent Space 统计了今年 64 项挑选出来的 AI 辅助研究进展，11 月就占 20 项，其中 6 篇预印本来自 Google 的 Cogentic 项目。它也提醒数量会掩盖细节：OpenAI 的稿件目录列了 730 份手稿、375 个结果族，修订日志里记着 10 月有 3 篇因一处符号错误连带撤回。同期 OpenHuman 说，黎曼猜想在 Lean 里被证明后三天，它的 agent 用这一结果证明了 17 个结论，其中 6 个是 11 月 20 日前仍未解决的命名猜想，包括 Lindelöf 假设、Erdős 第 985 号问题，每一个都经 Lean 检查。关于「OpenAI 或 Anthropic 能多项式时间分解整数」的传闻，Latent Space 明确标注为未经证实。来源：[Latent Space AINews](https://latent.space/p/ainews-math-proofs-are-landing-faster-than-we-can-read-them/) · [AK 转发 OpenHuman](https://x.com/_akhaliq/status/2125588780879134770)
- **Ai2 访谈 17 位科学家：AI agent 做科研，边界划在哪** {#ai2-scientists-agents} [长文]：Ai2 在 Hugging Face 博客发布访谈研究，对象是自然科学、应用科学和社会科学领域的 17 位科学家。他们归纳出科研信任的五个维度：验证、隐私、客观性、问责和透明。科学家希望自己参与决定 agent 做哪些任务、怎么做、怎么评估；即使答案技术上正确，如果过程无法检查，或 agent 访问了未授权的文件，结果也不适合用于科研。Ai2 的观点是，科学 AI 的安全不只是生物、核领域的灾难性风险，也包括 agent 是否遵守「负责任的研究行为」规范。来源：[Ai2 / Hugging Face 博客](https://huggingface.co/blog/allenai/where-scientists-draw-the-line-on-ai-agents)
