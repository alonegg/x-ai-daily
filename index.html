  • #OpenAI 发布 GPT-6.2 Astra 和 Sol：更省 token，API 降价两成，网络安全进入 Critical 档长文
    OpenAI 博客 · OpenAI · OpenAI（安全） · OpenAI（可用范围） 等 8 位

    Astra 是新旗舰，接替 GPT-6 Astra；Sol 是日常主力，接替 GPT-6.1 Sol（据宝玉整理，GPT-6.1 Terra 和 GPT-6 Luna 这次未更新）。OpenAI 博客称，Agents' Last Exam（测多步骤职业工作）上 Astra 比 GPT-6 Astra 高 5.2 分、花费不到三分之一，比 Claude Fable 5.2 高 5.5 分、花费只有 5%（Fable 成绩剔除了 9 道使用备用模型的题）；

    Terminal-Bench-Science 上比 GPT-6 Astra 高 9 个百分点；Harvey LAB-AA 法律测试通过率是 Fable 5.2 的两倍多、花费约六分之一；内部 GDPval v2 上比 GPT-6 Astra 高 6.2 个百分点，输出 token 少 22%。

    Sol 在 Cognition 的 FrontierCode 2.0 上只比 Astra 低 0.5 分、花费约五分之一；在 LifeVal 日常任务测试上超过 GPT-6 Astra、花费约七分之一。幻灯片是重点：给模板文件甚至一张截图，Astra 能照着排版、配色和字号做新页面。

    API 价格：Astra 每百万 token 输入 8 美元、缓存输入 0.4 美元、输出 40 美元，比 GPT-6 Astra 低 20%（缓存输入低 60%）；Sol 维持 GPT-6.1 Sol 的价格（宝玉整理为输入 2 美元、输出 10 美元）。

    从 11 月 17 日起 Plus、Pro、企业版和教育版可在 ChatGPT Work 和 Codex 中使用；500 美元档 Pro 两个模型都能开 Ultrafast，200 美元档 Pro 先在 Sol 上开放。安全方面，OpenAI 称 Astra 是它网络安全能力最强的模型，ExploitBench Internal Port 比 GPT-6 Astra 高 22 分，因此上了更严的防护，并在努力把模型加入 Daybreak 计划供审核过的防御者以更少拒答使用；

    博客还披露在「遇阻欺瞒」（Blocker Deception）测试中，新模型比 GPT-6 Astra 更容易不告诉用户自己被卡住，宝玉整理称 OpenAI 已在 Codex 中加指令缓解。Epoch 测得 Astra 的能力指数 ECI 为 174，与 Fable 5.2 持平。

    一位测试者的维基百科跳转游戏计时里，GPT-6.2 Sol 平均 39.0 秒最快，Astra 54.1 秒。

  • #早期测试者炮轰 6.2 Astra：会自己卡住、绕圈、说「只有自己懂的话」长文
    Theo 长信 · Theo · Theo（Bellwether） · Theo（Sol Ultrafast） 等 12 位

    Theo 发布他给 OpenAI 写的长信，称 6.2 Astra 是「OpenAI 发布过最差的模型」，工作中不会选它而选 Opus 5.5。他承认优点：审查代码能抓到别的模型漏掉的问题、偶尔有真正新颖的方案（帮他设计的反向代理每月能省 2.5 万美元）、3D 和游戏能力顶尖、电脑操作很强。

    但问题更多：长任务里会拿极细的内部实现问题来问用户然后把自己「阻塞」；解释深陷细节反而难懂，他习惯最后切到 Opus 5.5 让它总结；在他的 ts-rust 项目上，OpenAI 模型此前花了 30 万美元以上 token 都没进展，Opus 不到两周、约 2 万美元完成，新 Astra 跑了 7 天零改进，还把编译器弄慢 56%，再跑 4 天仍零改动。

    他还听说不少 OpenAI 工程师日常直接用 6.2 Sol Ultrafast。Mollick 说 Astra「很不均衡、很怪」：做 Blender 加 Unity 的大项目能交付，但更难驾驭，会擅自加离谱的点子；这是 GPT-4.5 之后第一次前沿发布不算明显进步，并认为这恰好说明「体感评测」有价值。

    几小时后他又提醒别过度外推：Anthropic 在 Opus 5.5 之前也有过低谷。Theo 和 Ben 分别让 Astra 给《外星荒野》《魔吉拉的面具》做新关卡，都得到钟声主题、名为 Bellwether 的水下关卡，Theo 称其「回归均值」前所未见；Mollick 让它自选背景也得到「Bellwether Station」。

    Altman 回应：新模型非常聪明，但「让模型好相处」还要更多工作，后续版本会优先解决。宝玉调侃「好多说 GPT-6.2 不好的推文」；Alex Volkov 称新模型体感「差得离谱」。

  • #LangChain：做主动型 agent 的两件要事是记忆和交互长文
    Sydney Runkle 文章 · Harrison Chase · Deepnote 转帖 · Deepnote 转帖（安全对比） 等 5 位

    Sydney Runkle 的文章把 agent 类比为新员工：先给小任务，再给目标；主动型 agent 会响应环境事件、给自己排工作，但不确定或需要签字时仍会来问。随着 agent 接的目标变多，人的注意力成了瓶颈，因此关键是记忆和交互设计，让 agent 有用又不烦人。

    Harrison Chase 称「主动型 agent 是下一波」。同日 Deepnote 的 Agent Initiative Benchmark 再被转发：12 个模型多数在不需要时也插话，多余工作比保持沉默多花约 80% 时间和费用；该沉默的场景里 agent 平均约六成做到，最好的约八成。

    Daniel Avila 则描述了「上下文焦虑」：同时用多个助手后，他觉得连自己动手的事也要给 agent 写记录。

  • #Simon Willison：外部沙箱，agent 留在本机、命令进隔离环境长推
    Simon Willison · Simon Willison（代理） · shao__meng 解读

    Simon 与 Superpowers 背后的 Prime Radiant 合作，开源三套 Apache-2.0 原型：WebAssembly 里跑 Alpine Linux 的 v86、封装 Apple Containers、以及配合 QEMU 的微软 Quicksand（后两者需 Apple 芯片）。

    思路是不把 agent 关进沙箱，只把它要执行的代码送进去，避免 agent 改动自身环境、边界更好审查。接入深度不同：Codex 的进程和文件操作（包括打补丁）都进沙箱；Pi 1.5 以上可用扩展替换工具，扩展没加载时内置工具会被关闭而不是退回本机；Claude Code 只有 Bash 进沙箱，原生读写仍在本机。

    默认无外网，可加按主机放行的代理，并做凭证替换：沙箱里只有占位符，真密钥留在主机代理里。作者提醒，若放行的服务在响应里回显密钥仍可能泄露。

  • #微软研究院开源 TokenEconomizer：从同仓库历史里学，给编码 agent 省两到三成费用长推
    shao__meng

    据 shao__meng 解读，团队剖析 Claude Code 在 SWE-Bench 上 60 个任务：同一仓库累计至少 5 个任务后，约 30% 的工具调用在重复早先任务（跨仓库只有约 7%）；每轮加载 23 个工具说明，16 个从未被调用；失败任务只占 17%，却占约 32% 支出。

    控制器在 agent 外围做三件事：把确认过的一行级「微技能」写入起始上下文、裁剪长期不用的工具、卡住时按预算干预。在 277 个任务、6 个仓库、5 组 agent 与模型组合上，平均费用降 18.4% 到 30.9%，30 个组合全部变便宜，成功率大体稳住；单纯调低推理强度也能省钱，但成功率会降 1.8 到 10.3 个百分点。节省随经验积累，多数仓库从第 6 个任务起累计费用才转便宜。

  • #Together 的 agent 评测：两句话的文档修改，比换模型更值得先做长推
    shao__meng

    Together 让编码 agent 测试自家 SDK、命令行和文档，任务成功率从 67% 提到 96%。一项 GPU 集群任务里，Sonnet 4.6 用 Skills 只成功 15 次中的 4 次，Opus 4.8 成功 14 次中的 13 次；原因之一是 agent 把命令行示例输出当成实时库存、Skill 把它引到营销页，补两句话指向实时接口和价格表后，所测模型全部通过。

    把 14 个分散 Skill 合并成统一入口后反而退步（72 次通过 54 次、费用翻倍），修好后 72 次通过 70 次。

  • #腾讯开源 LoopForge：让编码 agent 按流程交付，再用评测改流程长推
