  • #Anthropic 分析约 20.7 万次科研会话：分析数据最多，提想法最少后续长推
    宝玉
    前情宝玉整理 Anthropic 11 月 4 日的研究报告，样本为 2026 年 8 月 2 日至 9 月 30 日约 20.7 万次科研相关 Claude 会话（聊天和 Cowork 12.9 万次、Claude Code 7.8 万次，来自个人订阅用户）。分析数据占科研时间约 28%，却占 Claude 会话 33.7%、Claude Code 会话 48.1%；写作和沟通占科研时间 16%、占 Claude 会话 32%；收集数据占科研时间 28.6%、在 Claude 上约 12%；提出想法和假设占科研时间 7.1%、Claude 上 4.2%、Claude Code 上 2.1%。对 528 位科学家的调查里，「提想法」重要性得分 35.6 排第一、「收集数据」23.6 排第二。研究团队给 7000 多项科研任务打了「AI 能力分」：能力分排前 20% 的任务（如画数据图、做统计检验）使用倍数在 Claude 上约 2、Claude Code 上约 4，与「适合强化学习的任务」的相关系数 0.78。Claude Science（接入科研数据库的版本）会话一半以上来自生物医学和生物学；在生物和生物医学领域，73% 的会话由 AI 高度自主完成，普通 Claude 只有 24%。推算（报告说明不是预测）：现有能力普及后 AI 能接手 27%–52% 的科研时间，产出提升从艺术领域 1.35 倍到统计学 2.02 倍、计算机 1.96 倍；若 AI 包揽全部不用动手的步骤，统计、计算机、经济、数学、心理学等可到 15–16 倍，生物、化学、材料只有 3–4 倍（约 40% 的科研时间在动手步骤上）；16 倍左右的上限由成本假设决定（研究员每小时 95 美元、AI 每小时 30 美元）。局限：受访者多为美国和加拿大生命、健康领域研究者，且申请过 Anthropic 科研资助，用 AI 比一般科学家多。

    前情见 11 月 8 日（Mollick 引用同一报告的 27–52%）。

  • #Anthropic「做梦」记忆——宝玉版拆解的其余数字后续
    宝玉
    此前接 11-08 ↩

    前情见 11 月 7 日、11 月 8 日。宝玉整理 Anthropic 工程团队 11 月 6 日的文章：在查数据库答题测试中，Sonnet 4.6 有记忆只从 0.330 涨到 0.364，Opus 5 从 0.564 涨到 0.828；玩宝可梦红版，Sonnet 3.7 写了 413 个记忆文件、只拿 1 枚徽章，Fable 5 只写 10 个文件、拿 4 枚。

    记忆分四层：原始会话记录、Claude 自己写的笔记、整理出的结构（如互相链接的 wiki）、每次新会话自动载入的内容。开发者经验：只告诉 Claude「有个记忆文件夹可用」，Opus 4.7 与 Opus 5 就用得很好，加「只记录失败」反而丢掉大部分提升；Sonnet 4.6 在被要求先读记忆并验证猜测后，得分从 0.364 涨到 0.641；自动载入层要小，Claude Code 只载入 MEMORY.md 前 200 行或 25KB；

    多 agent 并行别写同一个文件（四个 agent 写共享条款表，57 条要点只留住 41 条，改成每份合同一页后全部保住）。用 Stainless 约 35 万份内部文件做「做梦」建 wiki：只靠 wiki 得分从 13% 到 48%，只靠搜索 53%，wiki 加搜索从 54% 涨到 61%。

    「做梦」是 Claude Managed Agents 的研究预览功能（需申请），跨会话记忆库为 beta。数字均为 Anthropic 自测，宝可梦对比每个模型只跑一次。

  • #Agent 说「完成了」≠ 过程没问题：Warp 的 Ben Holmes长推
    meng shao · Ben Holmes 原帖

    meng shao 编译 Ben Holmes（Warp）在 AI Engineer 的演讲：agent 可能绕过错误指令、反复尝试后完成任务，只向你报告最终结果。案例是测试 Skills 里的端口指令已过时，agent 不断试错最终完成，团队只觉得「慢一点」，没发现该修的是 Skills 说明。

    建议流程：团队先定评分标准（是否重复测试、工具调用是否高效、表达是否冗长），评审 agent 检查任务记录并解释扣分，另一个 agent 汇总反复出现的问题，把修复建议变成技能或配置的 PR 交人审查。两种实践：Skill Doctor（一次性检查本地历史）和 Warp Factories（持续评分、定期提修复建议）。

    原文 2Xmeng shaoXBen Holmes 原帖
  • #宝玉：要 agent 交截图或录屏当「证据」
    宝玉

    宝玉补充说明，截图/录屏是给验收的人看的：比如有人报评论功能的 Issue，他把 Issue 丢给 agent 修，agent 也许自己截了图，但对他仍是黑盒，所以要它给出「证据」，看到截图就基本能确认真的修好了。

    原文 1X宝玉
  • #Addy Osmani：Coding Agent 让你成了管理者，但不该让你更忙长推
    meng shao

    meng shao 总结 Addy 的观点：把自验证放首位（测试、构建、类型检查，界面改动可用截图），agent 先执行、检查、修正失败，再提交结果与证据；必要时让没参与原对话的新 agent 独立审查。任务说明应补充仓库里看不到的信息（为什么做、业务约束、不要做什么、怎样算成功）；规则不是越多越好，模型升级后要清理旧约束，必须遵守的安全要求要靠强制机制。

    无人值守任务开始前要明确完成条件、验证方式、权限、运行上限、交付产物和审批人；成效应看交付周期、返工和回退，而不是 agent 写了多少代码。

    原文 1Xmeng shao
