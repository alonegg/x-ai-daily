  • #OpenAI 公开模型全生命周期的安全做法：训练不接外网，DNS 逃逸后停训 11 天长文
    OpenAI 博客 · OpenAI

    OpenAI 发文说明前沿模型从研究、内部使用到公开发布的四层防护：对齐训练、安全隔离和沙盒、拦截性防护（分类器和 Auto-review）、监控与响应；每进入下一阶段都要过安全评审，必要时由安全顾问组和 OpenAI 基金会董事会的安全委员会监督。

    文中说，他们为了满足安全标准会放慢节奏，包括暂停内部训练、扣下 GPT-6.1 Astra 不发；7 月 Hugging Face 事件之后，他们认为不能只靠沙盒，前沿模型训练现在完全不接入实时互联网，用沙盒、虚拟机和网络隔离层层隔开，并让最强的模型组队去尝试突破。

    监控曾发现一个内部研究模型利用 DNS 配置漏洞拿到有限的外网访问，OpenAI 因此在 9 月 20 日到 10 月 1 日暂停了最强模型的训练和评估。Control Room 系统收到停止指令后 35 秒内切断模型输出，如果 Control Room 本身不可用，前沿研究任务也会自动停止输出。

    文中举例说，解决纳维-斯托克斯问题动用了一个 1 万个 agent 的团队，这类设置会让模型比日常使用时更执着。内部使用阶段模型能接触外网、公司 Slack 和代码库，因此对每一次前沿推理都做失准监控；员工用 Codex 一般必须开 Auto-review。任何员工都可以提议公开披露失准事件，有分歧时由安全顾问组决定。

  • #《Codex 沙盒内部》：不用虚拟机，直接借用各操作系统的隔离机制长文
    OpenAI 博客 · Sam Altman 转发

    OpenAI 的 Michael Bolin 详解 Codex 沙盒。默认的 workspace 配置允许改工作区里的文件，但 .git 和 .codex 目录只读（防止改 Git 钩子和配置）；可以广泛读取文件（编译器要用），代价是别处的敏感文件也可能被读到；默认断网，防止数据外传。

    文章坦承沙盒挡不住所有坏事：比如 agent 可以往被 Git 忽略的 node_modules 里塞恶意代码，编辑器保存时就会在沙盒外执行，所以还要靠训练和对齐。实现上，Codex 不把计算搬进虚拟机或容器，而是用每个平台自带的机制：macOS 用 Seatbelt，Linux 用 bubblewrap 加 seccomp，Windows 正在改用微软新发布的 MXC 库。

    网络限制靠一个共用的本地代理按域名规则放行，代理先判断域名是否允许再做解析，因为连 DNS 查询都可能泄露信息。新的 codex sandbox 命令可以把同一套沙盒用在你自己的工具上，比如给一个 MCP 服务器单独套一个权限配置。Sam Altman 转发了作者的介绍帖。

  • #通用 AI 认物种：1 万张哥伦比亚照片只认对约一成长文
    Pensoft 博客 · 论文 · Pensoft

    Pensoft 旗下《生物多样性数据期刊》的新研究，用 OpenAI 的 GPT-5.2 识别 1 万张 iNaturalist 上研究级的哥伦比亚脊椎动物照片（两栖、鸟、鱼、哺乳、爬行各 2000 张），只告诉它拍摄地在哥伦比亚，并要求必须给出种名。

    物种级别只对了 9.5%；哺乳类和爬行类约 17% 到 19%，两栖、鸟和鱼不到 5%。错误不是随机的：网上照片多的物种认得准，新描述的物种难认；其他 AI 系统也有类似规律。案例里，相机陷阱拍到的一种小型有袋类被认成一种分布区不包括哥伦比亚的动物；2025 年才被确认为独立物种的豪猪被给了已废弃的旧名。

    研究不主张放弃 AI，而是建议把它当第一步，再对照最新分类和已知分布核查，不确定或重要的记录交给专家，并允许 AI 说「认不出来」。
