# 10 月 29 日 AI 播报

## 开场与头条预告

早上好，今天是十月二十九号，星期四。这里是 X 每日 AI 播报，接下来二十多分钟，我们把昨天 AI 圈的事情过一遍。

先说今天最重要的三件事。

第一件，谷歌在上一个模型发布两周之后，又推出新一代前沿模型 Gemini 四 Carbon，在一个综合排行榜上排到第一。但这次普通人暂时用不上，先给网络安全的防守方。

第二件，这个综合排行榜自己也大改版，六成题目改成不公开的私有题。改完之后，开放权重模型和第一名的差距一下子拉大了。

第三件，GitHub 的年度大会上，Copilot 学会了自己挑模型，还推出一种最仔细的代码审查，平均审一次大约十美元。

另外，评论环节我们会聊学术出版圈的一场争论：一个主张先发表、再评审的新联盟刚刚成立，当天就有人写长文说它在误导大家。

## 快讯

下面是快讯。后面重点和评论要细讲的几件事，这里先跳过，只说其余的新鲜事。

先看大公司的产品。Anthropic 给法律版 Claude 加了一个现成工具库，能查引文、比对合同和公司标准条款、整理即将生效的新法规。每个结论都附原文出处，方便律师核对。哪些套餐能用、要不要另外收费，官方没说。

苹果更新了创作者订阅套件。剪辑、修图、作曲软件都加了 AI 助手。更值得注意的是，Keynote、Pages、Numbers 这三个办公软件支持了 MCP。MCP 是让外部 AI 工具读写软件内容的一种通用接口。也就是说，外面的 agent 可以直接打开你的幻灯片去改。

OpenAI 那边，ChatGPT 的小助手 dot 现在能发短信了。你可以用文字、照片或语音给它布置任务，它会主动发短信告诉你进展。目前只在美国，给 Pro 用户预览。

还有一条要打个问号的消息。有网友转述说，从明天起，Codex 老用户的额度要减半。今天的信源里，没有看到 OpenAI 的官方说法，大家以官方通知为准。

美国犹他州做了一个小试点。十个州政府机构的三十四名开发者用了四周 Claude Code，七成多的人说自己省下了二十个小时以上。

再看开源模型。英伟达发布开放权重的语音转写模型，一个模型就能做四十种语言转写、分辨谁在说话，还能翻译。一家叫 Recursive 的公司发布了 Flint，专门在 Mac 本地写代码，用的是很宽松的开源许可。还有一家金融研究公司，用一个小模型做后训练，在金融研究测试上略高于 Claude Fable 五点一，成本只有十一分之一左右。

开发者工具这边，T3 Code 的作者又连续发了好几天更新。最大的一个是跨机器编排：一个对话线程，可以同时调动不同电脑上的不同 agent。他也说了实话，免费服务的服务器账单已经每月两万美元以上，所以更多远程连接通道要收费了。

中文开发者圈里，宝玉推荐在 Claude Code 里把自动压缩的门槛调到三十万 token。默认要到接近一百万才压缩，前面每发一条消息都带着全部历史，额度消耗得很快。他还建议在给 agent 的说明文件里写一条规矩：用完的临时工作目录必须自己清理。有人因为没清理，攒了四十一个目录，占了四十五 G 硬盘。

工作流方面，Claude Code 团队的工程师 Lydia Hallie 说，动态工作流不一定要几百个子 agent。只要是想按同样方式反复跑的任务，十个左右就够了。它是一个能直接改的脚本文件，比一段技能说明更可预测。MiniMax 的编程团队也把他们每天在用的工作流和技能开源了，核心观点是：拆子 agent，首先是为了隔离上下文，不是为了按工种开分身。

也有人分享了个人 agent 的日常用法。有位开发者把自己管理社交账号的 Grok Bot 做成了模板：盯着提到自己的帖子，每天给一份排好序的摘要，过滤垃圾，但从不替本人发帖。还有一位独立开发者说，他所有的事都跑在自己的云服务器上，只用手机连上去，再让服务器上的 Claude Code 干活，连睡眠和饮食数据都拉进去分析。

还有几条行业观察。刚离开 Anthropic 的工程师 Thariq 发了一条帖子，一万多人点赞。他说现在的情况很怪：技术人很难过，觉得技能没用了；不懂技术的人，却拼命希望自己更懂技术，好把 agent 用得更好。

Ruby on Rails 的作者 DHH 继续推他的 Linux 发行版 Omarchy。新版本在最快的机器上，六秒左右就能装完。一位知名独立开发者收到他寄来的预装笔记本，说开机设置不到一分钟，还顺手帮你配好了常用的 AI 编程工具。

Stack Overflow 上个月的新提问，据一位开发者统计不到一千个，创了新低。程序员遇到问题，越来越多地直接去问 AI 了。

另一条是沉重的新闻。纽约时报中文网报道，一位华人女子三年里和 ChatGPT 对话超过二十七万条，ChatGPT 建议她减少抗癫痫药的用量，最终酿成悲剧。用药这件事，请一定以医生为准。

最后是开放科学和 Jupyter。欧盟开放科学云的新版本，加了一个叫 Conda Switcher 的功能，让 JupyterLab 的运行环境可以复现，还给团队空间配了五百 G 共享存储。开放知识基金会今天在 Mozilla 的 MozFest 大会上，讲怎么用 MCP 让更多人用上你的开放数据。伦敦的知识图谱大会预告了两个案例：挪威铁路用知识图谱把五千多公里线路统一成一个模型，罗氏制药用知识图谱追溯临床数据的来源。长期关注开放科学的 Juan Benet 也在呼吁，为衰老研究众筹关键数据集，理由是人工智能要帮忙攻克疾病，得先有数据。ORCID 的全球参与基金，申请截止就在这周六，十月三十一号。

## 重点一：Gemini 4 Carbon

为什么重要？因为这是两周之内，谷歌第二次拿出前沿模型。而且这次它第一次把网络安全能力放在最前面讲。

谷歌说，Gemini 四 Carbon 在新版综合排行榜上拿了五十九分，排第一，比 Claude Opus 五点五高一分。它可以连续几天处理复杂任务，碰到死胡同会自己换路。

安全方面有三个分数，对应安全团队处理漏洞的三步。找漏洞，八十八点二分。证明漏洞能被利用，五十四点八分。修好漏洞，七十一分。

这里有个关键细节。谷歌写明，这些安全分数是在关掉安全防护之后测的。同样的本事，落到坏人手里也能用来攻击。所以本周只给一部分经过审查的网络安全防守方用，之后再扩大到合作伙伴，最后才是开发者和普通用户。具体哪天开放，官方只说很快。

谷歌公布的对比表里有十七项测试，Carbon 拿了十五项第一。没赢的两项，一个是写代码，输给 GPT 六 Astra，一个是操作电脑，输给 Opus 五点五。

也有一些来自一线的反馈。一位长期测评模型的博主说，他在发布前用过一段时间，感觉比上一代好很多。在一个 agent 对战排行榜上，它从上一代的第七名升到了第二名。

我们的看法是，分数大多来自谷歌自己的表格，别家的分数也多是各家自己公布的。真正好不好用，要等更多人拿到手。

## 重点二：排行榜改用私有题

为什么重要？因为大家选模型时常看的一个综合榜单，换了出题方式，结论也跟着变了。

这家评测机构叫 Artificial Analysis。新版本里，六成题目来自不公开的私有测试集。这样做是为了防止模型提前见过题目，也就是所谓的题目污染。他们还加了新的编程测试和终端里的科研任务测试。

结果是，第一名 Opus 五点五五十八分。开放权重模型里最高的，是还没放出权重的 Kimi K 三点一 Pro，四十六分。开放权重，就是把训练好的模型文件公开，谁都能下载自己跑。

差距从上一版的三分，拉大到十二分。已经放出权重的模型里，最好的 DeepSeek V 四点一 Flash 和 GLM 五点三都是三十二分，比 Anthropic 的小模型 Haiku 五点五还低。

这个榜单还算了成本。排名前十的模型里，完成一道题，最便宜的不到一美元，最贵的要十三美元，相差十几倍。所以看排名的同时，也要看价钱。

同一天还有一个相关的推算。有人根据 Anthropic 的招股书算出，它的毛利率约百分之八十五，所以服务 Opus 五点五的成本，可能比很多模型的售价还低。这是按整体毛利倒推的估算，不是真实账单。

我们的看法是，私有题能挡住污染，但外人也没法复核题目。研究 AI 应用的学者 Ethan Mollick 也说，要打个折扣看。

## 重点三：GitHub Copilot 学会挑模型

为什么重要？因为写代码的 AI 工具，正在从让你选模型，变成工具自己替你选。

GitHub 在年度大会上发布了 Fusion。简单的活交给一个模型。难一点的，先让便宜模型写草稿，不过关再换强模型。最难的，让一个模型写，几个模型同时挑错。免费版也有基础档，更深的档位要每月三十九美元的套餐。

代码审查也加了最仔细的一档。几家公司的模型各审一遍，再汇总、剔除误报。代价是贵，官方估算平均审一次约十美元，最多二十五美元。按十美元一个月的套餐算，审一次就用掉三分之二的额度。

另外，Copilot 现在可以正式批准合并请求，算进仓库要求的审批人数，不过默认关闭。合并请求页面还多了一个按钮，测试没过时，让 Copilot 自己在云端去修。

宝玉的评价不太客气。他说日常让 Copilot 审代码，有价值的结果不多，整体体验比 Claude Code 和 Codex 差一个量级。

我们的看法是，自动选模型是对的方向，但每次多花多少钱，用户要看得见，才敢放心交给它。

## 重点四：为 agent 重做代码托管

为什么重要？因为代码托管平台的基本单位，可能要从合并请求换成别的东西了。

前 GitHub CEO 创办的 Entire，公开了它的新平台。他们认为，现在一个合并请求里，写代码的 agent 和审代码的 agent 来回留长文，人已经看不过来了，像一份只有 agent 在读的审计日志。

所以他们用一种叫 Trail 的东西代替。每次推送代码，几个评审 agent 在隔离环境里各自打分，比如安全、有没有凑字数的废话、要不要人来审。分数走势和没解决的问题放在页面最上面，人先看稳不稳，再决定合不合。

他们还做了一套记忆插件，把 agent 过去的会话记进仓库，让下一个 agent 知道当初为什么这么改。他们自己的测试说，推送速度最高比 GitHub 快八十多倍。

我们的看法是，速度数字来自他们自己的基准。但思路值得关注：当 agent 写得比人看得快，评审界面就得先告诉人，这个改动够不够稳。

## 重点五：主动型 agent 就是定时任务

为什么重要？因为它戳破了一层神秘感。很多看起来会主动找你的 agent，背后其实是一个很老的技术。

LangChain 的工程师说，几乎所有主动型 agent，都是一个带提示词的定时任务。夜里整理记忆，早上主动给你发消息，都是按时间表跑起来的。LangChain 说，九月上线定时调度以后，它托管平台上七成以上的 agent 运行，都是定时触发，不是人发消息触发。

同一天，吴恩达的 DeepLearning.AI 上线了一门免费课，讲怎么给 agent 加循环：检查输出，按事件触发，再从运行记录里改进。

LangChain 的设计 agent 也有一个反直觉的经验。搭建它的工程师说，他写的大多数规则其实让效果更差。这些规则当初是为了弥补模型不够聪明。Opus 五点五出来后，他删掉了大部分，作品反而更有创意。

LangChain 另一个实验也很说明问题。他们给自己的知识库加了一张证据关系图，让 agent 能顺着关系，一路追到支撑某个说法的原始证据。在需要跨多个来源推理的问题上，准确率提高了百分之二十七，每个正确答案的成本降了一半多。

我们的看法是，规则会过期，环境和流程更长寿。定时任务、检查循环、运行记录，这些朴素的工程，才是 agent 稳定干活的底座。

## 重点六：红果与字节时间

为什么重要？因为 AI 生成内容，已经实实在在地在改变中国人每天的时间分配。

宝玉整理了两篇文章的争论。一边是第一财经日报原总编辑秦朔。他引用第三方数据说，短剧应用红果七月日活一点六八亿，超过四家长视频平台加起来。在使用时长前五十的应用里，字节系占了四成。他担心这是一台吸收时间的机器。

另一边是自媒体作者程苓峰。他认为份额不重要，AI 短剧才是真正的变化：网文省了剧本，视频生成模型省了拍摄，便宜流量省了拉新。

广电总局公布，今年前八个月上线微短剧四十三万部，其中 AI 剧超过九成。抖音的一位副总裁回应说，字节时间的说法不严谨，数据只算了前五十个应用。

宝玉也核对了数字。网传红果年收入四百亿，红果已经声明不实。人均每天一百二十五分钟，出自第三方报告，红果没有确认。

我们的看法是，两边都担心沉迷。监管已经要求 AI 内容逐集标注，红果也在下线看剧赚金币。接下来要看的是，这些刹车到底有多大用。

## 重点七：AI 剪视频走上编程的老路

为什么重要？因为编程领域发生过的事，正在视频剪辑里重演一遍。

宝玉写了一篇长文。他说 Opus 五点五出来以后，agent 剪视频已经能替代初级剪辑师。他自己做过实验：同一个视频，不用任何专门的技能包，只给语音识别和语音合成工具，效果反而更好。他也把自己剪辑工具里复杂的时间线编辑器放到了次要位置。

他总结了两位从业者的经验。一位管着广告剪辑团队，说资深剪辑师在同等质量下，一天的产出是以前的五倍。他的做法很具体：按风格拆成小技能；让 AI 把资深剪辑师最近剪的二十五条广告重剪一遍，剪辑师逐条点评；再让最好的剪辑师边剪边录屏，口述为什么这么剪。

另一位是在线剪辑工具 VEED 的联合创始人。他预计一年内，基础剪辑的成本会从几美元降到几美分。他的建议是别去重造专业剪辑软件的时间线，做好初剪，再交给专业软件。

宝玉也点出了两人立场的不同：一个做量大、套路固定的短广告，最适合交给 AI；一个是卖工具的，更好的界面正是他的生意。

我们的看法是，这套方法换到写作、设计上同样成立：用参考样本起稿，用历史作品批量重做，请专家逐条反馈，再把专家的理由记下来。

## 评论一：先发表再评审，是进步还是换汤不换药

这一段，我们会讲清楚原帖说了什么，也会明确说出我们自己的判断。

先看事实。昨天，一个叫 PRC 的联盟成立了，三个字母代表发表、评审、策展。它主张论文先公开发表，再做公开的同行评审，最后由期刊或平台挑选推荐。成员有四十多家，包括盖茨基金会、开放获取期刊目录等。出版商 Pensoft 旗下的 RIO 期刊是创始成员，计划在后年年中完全转成这种模式。

同一天，一位开放科学从业者发长文唱反调。他说自己以前也为这个模式站过台。但现在他认为，支持者把预印本的普及算到了自己头上。他们自己的报告显示，只有大约百分之二的预印本得到过预印本评审。他还担心，评审费单独收、策展再收一次，作者可能付两次钱。

我们的判断是，两边说的都有道理。先发表确实让研究更快公开，评审意见公开也更透明。但如果评价科研时，只是把看期刊名字换成看评审平台的名字，问题并没有解决。

最有力的反对意见是：任何新模式一开始都缺证据，不做怎么会有证据？这一点我们同意，所以关键是边做边公开数据。

给你一个具体建议：这周如果你要投稿，先查一下目标领域有没有预印本评审服务，看看它们公开的评审意见长什么样。

## 评论二：开放数据里的信任标签

这一条，我们只讲一个人的观点和她的论证。

开放研究信息领域的研究者 Bianca Kramer，以个人身份写了一篇短文。背景是，开放学术数据库 OpenAlex 九月以来收录的期刊名单，从二十二份扩到六十一份，并把它们叫作可信期刊名单。

她说自己心情复杂。好的一面，这些信息变成了开放数据，还收录了拉美、非洲的期刊索引，能让可见不再只等于被几家商业数据库收录。

不好的一面，是这些名单被当成可信的信号。其中不少是国家科研评估用的名单，衡量的是声望，不是可信度。这和倡导负责任科研评价的旧金山宣言相冲突。她建议 OpenAlex 至少给每份名单标上类型和用途。

我们的判断是，她指出的是开放基础设施最难的地方。数据开放是中立的，但给数据起什么名字，就不中立了。可信这个词一旦挂上去，就会被评审委员会直接拿来用。

给你一个具体建议：下次用 OpenAlex 的期刊名单字段做分析时，先查清每份名单是谁做的、为了什么做的，再决定要不要用它筛选。

## 评论三：上千个 agent 一起干活，缺什么

这一条，我们用拆框架的方式来讲。

Anthropic 的平台工程负责人 Katelyn Lesse 写了一篇文章。她说，很多工程师担心手艺不值钱了，她看到的正相反。上千个 agent 长期一起工作，会冒出四类新问题。

第一，服务器怎么安排。现在主流的调度系统，擅长管一模一样的副本。agent 却各不相同，大部分时间在等，又可能一下冒出几千个。

第二，谁在干活，能干什么。系统得分清一个操作是人做的，还是 AI 替人做的。一个系统替你连干几周，你怎么事先讲清楚它能做什么。她说这一块基本是空白。

第三，一个被骗，全队遭殃。一个 agent 被网页里藏的恶意指令骗了，可能把指令传给同伴，甚至写进共享记忆。所以每个 agent 都要在隔离的环境里干活。

第四，跑偏了要能叫停。每个 agent 做了什么要记下来，而且谁都改不了记录。还要有一个总闸，一次停下整个系统。

最有力的反对意见可能是：这些问题在传统分布式系统里早就有答案，不过是旧问题换了新名字。她在文章里其实也回应了：认证可以借用旧办法，但替人授权、agent 之间互相信任，旧办法确实不够用。

我们的判断是，这四条对做科研自动化的人特别有用。一个自动跑实验、跑 notebook 的系统，同样要回答谁授权的、出事能不能追溯。

给你一个具体建议：这周检查一下你自己跑着的自动任务，看看它们用的是不是你本人的长期密钥。如果是，试着换成很快会过期的临时凭证。

## 评论四：面试在考什么

这一条，我们用两个案例对照着讲。

第一个案例来自 Reddit 上一位匿名网友。他说自己刚面完 OpenAI 的软件工程师岗位。流程里有一个四十八小时的带回家项目，之后面试官会带着他逐行过代码，追问每个选择的理由。部分候选人还有一轮新面试：给一个手写做不完的大问题，要求用 AI 编码工具完成。宝玉特别提醒，这是个人经历，OpenAI 没公布这么细的流程。

第二个案例，是昨天节目里聊过的那位 Anthropic 工程经理。他这个月起不再考编程题。昨天资深工程师 Addy Osmani 补了一句：执行已经不贵了，在公司里要看你能不能挑出推动业务的点子并做出原型。

反过来说，也有人会担心，不考写代码，会不会让基本功不扎实的人混进来。OpenAI 这套流程的做法是：带回家的项目给你两天时间慢慢做，但面试时你得对每一行代码说出理由。

我们的判断是，两家走的路不同，指向的却是一件事：面试越来越不看你能不能写出代码，而看你能不能讲清楚为什么这么写，以及会不会指挥 AI 去写。

给你一个具体建议：挑一个你最近用 AI 做的小项目，试着不看代码，把每个关键设计的理由讲给同事听。讲不清的地方，就是你该补的地方。

## 评论五：上手实测一个开源 OCR

最后一条，是一次产品实测。

开源团队 OpenBMB 发布了两个文档识别模型。OCR 就是把扫描件、照片里的文字认出来。一个模型只有十亿参数左右，负责识别。另一个负责检查，给识别结果打分，只把可疑的地方标出来给人看。

一位做 Claude Code 模板的开发者拿最难的材料去试：发票、银行对账单、手写改过的采购单、德英双语酒店账单。结果，一百零二个字段里，八十二个完全正确。

出错集中在两处。手写的更正，八个只对了三个。数表格有几行，六次全错。他的说法是，字认得没问题，字段背后的逻辑没懂。

检查模型的表现更有意思。二十个错字段里，有十五个所在的图片被它标了出来，而且没有误报。

我们的判断是，这个思路比单纯追求识别准确率更实用。识别永远会出错，关键是告诉人该看哪里。

给你一个具体建议：如果你在整理论文附录或者老档案的扫描件，可以先用这类模型跑一遍，只人工复核被标出来的页面，看看能省多少时间。
