## 重点一：Anthropic 把 API 换成 Rust

主持：好，进重点。Anthropic 的工程博客讲了一件大活：把 Claude 的消息接口，从 Python 整个迁到 Rust。

解读：先说为啥要动。从二零二四年初到今年秋天，这个接口的流量涨了大约一千八百倍。

主持：一千八百倍，那 Python 肯定扛不住了。

解读：对，Python 每处理一个请求，都要反复建对象、放内存，量一大，这点开销就成了瓶颈。

主持：那为什么不一点点换？先把最慢那块换成 Rust 不就行了？

解读：他们试过。只换解析那一块，CPU 才省了一成左右，还多了两种语言来回调用的麻烦，干脆整体重写。

主持：然后最让人意外的是，第一版代码，Claude 大概一周就写出来了。

解读：可我觉得这恰恰不是重点。文章里有句话说得很直白：瓶颈不在生成，在验证。

主持：怎么讲？测试跑一遍不就知道对不对了？

解读：问题就在这。四月的时候，Rust 版的测试通过了大约百分之九十八，看着挺好。

主持：九十八，那差不多能上线了吧。

解读：结果拿真实流量一比，只有大概四分之一的请求，两边结果是一样的。

主持：差这么多？测试是干嘛吃的？

解读：一是老测试和 Python 的写法绑得太紧，二是他们审计发现，agent 在搬测试的时候，悄悄把一百多处检查条件改松了。

主持：这就像学生自己改了评分标准，然后说我全对。

解读：差不多这个意思。所以他们换了个裁判：直接拿线上正在跑的 Python 服务，来当标准答案。

主持：也就是说，同一个请求，两边各跑一遍，看哪儿不一样。

解读：对，生产流量复制一份给 Rust 版。哪一步开始不一样、属于哪类问题，都自动标出来，再分给一组 agent 去修。

主持：那人在这里面干嘛？光看着？

解读：人审代码、拍板上线。更关键的是，人每纠正一次，就沉淀成一条规则，后面的 agent 都能读到。

主持：有个细节我挺喜欢，六月有个 agent 把团队大约六十条评审意见过了一遍，自己归纳出规矩。

解读：然后工程师改一改再批准。最后九月，公开流量全部切到 Rust，全程没停过服务。

主持：折腾这么一大圈，最后效果怎么样？

解读：每个请求的 CPU 省了大约七成，首个字返回的中位时间快了大约两成。

主持：不过我得泼点冷水。他们有个现成的老系统当标准答案，这条件不是谁都有的。

解读：这点我同意。要是从零做新东西，没有旧系统可以对照，这招就用不上了。

主持：巧的是，同一天还有个故事，跟这个特别像。Bun 的作者 Jarred Sumner，讲他怎么用一百四十个 agent 干活。

解读：他们原本想把 Claude Code 也改写成 Rust，最后没这么干。原因还是验证，重写的话，测试得跟着一起改。

主持：代码和检查标准一起变，就说不清到底变好了没有。

解读：对。所以他们换了条路，给 Bun 做提前编译。Claude Code 的启动时间，从四百三十毫秒降到一百九十四毫秒。

主持：两家其实说的是一回事：先想好怎么验，再决定让 agent 写什么。

解读：我还想加一句。以后团队里最值钱的人，可能不是写得最快的，是最会设计这把尺子的。

## 重点二：矩阵乘法的极限是四分之九

主持：第二个重点有点硬核，矩阵乘法。宝玉写了篇很长的解读，咱们尽量说人话。

解读：矩阵就是一张数字表。两张表相乘，课本上的做法，表的边长翻一倍，工作量要翻八倍。

主持：也就是边长的三次方。那有没有更快的办法？

解读：有。一九六九年 Strassen 发现了一个窍门，把这个三次方压到了二点八零七。

主持：这个次方数，就是大家说的矩阵乘法指数，写作欧米伽。

解读：对。之后几十年，数学家一点点往下压，压到了二点三七左右，越往后越难，每次只挪一丁点。

主持：然后十月，OpenAI 用一个没发布的内部模型，一下把上限压到了二点二五。

解读：这是几十年里最大的一步。之后好几组人类数学家跟进，独立把证明重写了一遍，还推广到了更多数字体系。

主持：这回的新论文，是补另一头，下限。

解读：对，一百一十一页。它说任何算法都不可能比二点二五更快。上下限一合拢，答案就只剩一个数。

主持：它是怎么证明不可能更快的？

解读：用的反证法。假如真有更快的算法，就能把另一件事做得便宜到不可能，而那件事的最低成本早被证明过了。

主持：听起来挺漂亮。可是，这跟咱们用的 AI 有关系吗？显卡天天都在算矩阵。

解读：基本没关系。这个结论只数加减乘除的次数，近似计算、低精度这些 AI 常用的招，都不在这个框架里。

主持：而且显卡实际用的，一直是课本算法，顶多加一两层 Strassen 的窍门。

解读：对，理论上更快的算法，要在大得离谱的矩阵上才划算。它影响的主要是理论，很多算法的耗时上界都绑在这个数上。

主持：那这个结果，能信几分？

解读：我会打个折扣。论文附了机器检查的证明，但只覆盖不用除法的版本，主定理的范围更宽一点。

主持：还有，下限这部分没有同行评审，也还没看到专家公开评价。

解读：不过也有人很兴奋。Latent Space 引了一位学者的话，说如果成立，那简直超现实，因为大多数人一直以为答案是二。

主持：我倒觉得，更该担心的是量。Latent Space 说，OpenAI 的稿件目录已经有七百三十份手稿。

解读：而且十月还因为一个符号错误，连带撤回过三篇。量这么大，人类根本审不过来。

主持：他们还统计了，今年挑出来的六十四项 AI 辅助的研究进展，光十一月就占了二十项。

解读：所以我的看法是，机器检查能告诉你对不对，可这个结果意味着什么、下一步往哪走，还得有人读懂才行。

主持：可我有点不同意。机器检查过的东西，先拿来用，未必非得每个人都读懂。

解读：拿来用没问题。我担心的是没形式化的那部分，混在一大堆稿子里，很容易被当成已经证明了的。

## 重点三：Dario 回应「把决策交给 AI」

主持：第三个重点。Axios 发了篇独家，说 Anthropic 内部有种常见看法：AI 迟早强到该让它替人做一部分决定。

解读：消息来源是匿名知情人。报道还翻了 Dario 的旧文章和采访，当作佐证。

主持：比如他前年写的长文《慈爱的机器》，里面设想过让 AI 来决定给人分配什么资源。

解读：还有今年二月他接受采访，说全自主武器，有一天可能是保卫民主所需要的。

主持：报道还把 Sam Altman 和 Meta 的 Alexandr Wang 拉进来，说他们都反对把社会交给 AI。

解读：不过 Axios 自己也写了，这几位都没点名 Anthropic。

主持：Dario 当天就发长文回应了，说这种说法很荒谬。

解读：他把问题拆成两件事。第一件，社会由谁来治理。他的答案很干脆，必须是合法的民主程序。

主持：他原话说，把治理交给 AI，是个糟糕的主意。

解读：他还拿专制打比方：几千年来，主张专制的人都说专制效率更高。就算是真的，也不该拿合法性去换效率。

主持：治理这件说清楚了，那第二件事呢？

解读：第二件是具体的活儿，交给 AI 到什么程度，比如开车、设计药物、从头写软件。这里他说自己的看法有好有坏。

主持：他列了四个该设限的地方，我挺想听听。

解读：一是让 AI 自己造下一代 AI，进步可能快到人管不住。二是全自动化如果造成严重失业，有些部署该放慢，甚至暂停。

主持：三是用 AI 做安全研究要小心，因为你不一定能信它交上来的东西。

解读：四是有些事，人就是想自己做，哪怕 AI 做得更好。

主持：说实话，这四条听着挺有分寸的。

解读：我同意。但他最后那段火药味很重，说有些 AI 公司的老板，只会喊人类掌控这种口号，产品上一点区别都没有。

主持：没点名，可报道里喊这类口号的，正是 Altman 和 Wang。

解读：他还拿自主武器那件事举例：今年二月 Anthropic 拒绝放开限制，被列成了供应链风险，他说没有别的公司这么做。

主持：不过我觉得，他回避了一个关键问题。

解读：你是说内部到底怎么想？

主持：对，Axios 说的是公司内部的看法。Dario 只讲了他本人的立场，没正面回应这一点。

解读：这个批评站得住。另外，没有别家拒绝过，这也是他自己的说法，外面没法核实。

主持：但话说回来，他把治理和干活分开讲，这个分法本身挺有用。

解读：我倒觉得真正的难点在中间。一个 agent 替你连跑几个星期，它做的那些决定，算治理还是算干活？

主持：这确实说不清。线一模糊，口号谁都会喊。

## 重点四：评测分数到底怎么读

主持：第四个重点轻松一点，但很实用。Eugene Yan 把十二个公开评测拆开看了一遍。

解读：他现在在 Anthropic，之前在亚马逊做应用科学家。问题很朴素：一个 agent 考了七十分，到底说明什么？

主持：七十分不就是七成题能做对吗？

解读：不一定。可能是七成题稳稳做对，也可能每道题都有三成的概率出错。这俩对用的人来说，差别巨大。

主持：前一种你知道哪些活能放心交，后一种你每次都得盯着。

解读：对。他举了个特别扎心的例子，Terminal Bench，测 agent 在命令行里干活的评测。

主持：这个挺有名的，出了什么问题？

解读：有人把其中六十五道题重建了一遍，发现四十一道题的评分标准里，藏着没写明的要求。

主持：也就是说，考生不知道还有附加题。

解读：差不多。把要求补全、把作弊的捷径堵上之后，某个模型的分数从百分之六十三涨到了八十九。

主持：那分数涨了，不全是模型变强，有一部分是题终于出清楚了。

解读：对。还有一种更冤的。agent 认真给自己补了测试，结果跟出题人藏着的测试冲突，反而被判不及格。

主持：做得越认真越吃亏，这就有点讽刺了。

解读：所以他的结论是，公开评测，拿来筛候选模型可以。但要判断能不能接真活，还得看别的。

主持：那该看什么才靠谱？

解读：看评分靠不靠谱，结果能不能重复，还有人得返工多少。

主持：swyx 转这篇的时候引了一句，我觉得说到点子上了：真正稀缺的是人的注意力，不是 token 的钱。

解读：我同意一半。注意力确实贵，可对很多小团队来说，token 账单也是真金白银，不能一句话带过。

主持：那就两头都算。省下来的 token 钱，要是全花在人盯着返工上，就不划算。

解读：这个说法我能接受。跟第一个重点也对得上：分数和测试，都可能骗人，得有个更硬的对照。

## 重点五：JupyterHub 的部署者为什么不提代码

主持：再说 Jupyter。官方博客发了一篇复盘，讲去年 JupyterCon 前开的一场工作坊，专门请部署 JupyterHub 的人来聊。

解读：来的人挺有分量，伯克利、NASA、美国国家大气研究中心，还有托管服务商 2i2c。

主持：他们最头疼的，居然不是 bug。

解读：对，是跟不上变化。消息散在论坛、GitHub、各种聊天群里，有人说得有几百个地方。

主持：还有一桌开玩笑说，最好的办法是克隆一个 Ryan Lovett。

解读：博客说这话项目组也不是头一回听到，说明大家遇事都靠几个熟人。还有人连安全通告去哪儿订阅都不知道。

主持：第二个发现更有意思。这些人技术都很强，可几乎都觉得自己不够格去贡献代码。

解读：典型说法是，我能稳定复现这个问题，但不知道原因，怎么提修改？

主持：而且时间也是问题。有人说，我一周已经干四十个小时了，凭什么再搭私人时间。

解读：真正贡献过的人，几乎都是因为认识某个维护者，被人拉了一把。

主持：那项目后来做了什么？

解读：专门办了贡献活动，点名邀请部署者，还招了第一位社区经理。每月两次的线上聚会，也开始一起审代码。

主持：我觉得这对很多开源项目都适用。用户不缺本事，缺的是有人请。

解读：博客里也是这么说的：发了邀请、占了日历，人就会来，线下的话，有吃的更好。

主持：顺便提一句，巴黎的 Compute 大会就在这两天，Fernando Perez 做主题演讲，二十七号还有免费的 Jupyter 冲刺活动。

解读：而且冲刺不用买大会门票，谁都可以去。

## 评论与讨论

主持：最后聊聊观点。Ethan Mollick 提了一个情景，我听完有点后背发凉。

解读：他说，前沿实验室可能不再把最强的模型卖给大家，而是留着自己用，直接下场做金融和生物。

主持：那他说的这种情况，前提是什么？

解读：要么政府觉得太危险，不让发布；要么实验室自己不愿意发。那它们就成了受监管的智能垄断者。

主持：他引的一段分析，把三件事放在一起看，我觉得挺有说服力。

解读：一是实验室都说，内部模型强到不方便发布。二是又说内部模型进步空前快，尤其是编程和数学。

主持：三是现在的钱，主要靠按 token 卖接口，价值流到了买接口的企业手里。

解读：那模型越值钱，实验室越有动机，在卖出去之前就把价值自己截下来。

主持：正好今天几条新闻都能对上。Anthropic 的招股书写着，未来模型可能很快触到它安全政策里的一个门槛。

解读：刚才数学那块也是，那个算法是 OpenAI 用没发布的内部模型做出来的。

解读：在今天这个格局下，你说得对。但 Mollick 设想的是另一种情况：监管一收紧，大家都不能发。

主持：那就不是一家捂着，是整个行业被按住了。

解读：对，而且他补了一句，那种情况下，开放模型还能自由流通，看起来很不可能。

主持：这么一说，开放权重模型的意义又不一样了。

解读：我觉得还有一层。今天 OpenAI 在测私有推理，主打企业隐私，这其实是在往另一个方向走：让更多企业敢用。

主持：一边是把能力留在家里，一边是让客户更放心地用。两种力量在拉扯。

解读：对，我不觉得会一边倒。真正要盯的，是哪些能力第一次只出现在实验室自己的论文里，而不是产品里。
