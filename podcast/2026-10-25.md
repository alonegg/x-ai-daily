## 今日重点（3349 字）

第一件重点，Kimi K3.1 Pro 的详细成绩。月之暗面十月二十三号发布了 K3.1 Pro，承诺十一月四号前开放权重。这次 meng shao 做了完整拆解，要提醒一句，下面的数字都来自 Kimi 官方。

编程方面，Terminal-Bench 4.0 用 Claude Code 的 harness，拿到百分之六十五点七。比 GPT-6 Astra 的百分之五十八点二高，略低于 Opus 5.5 的百分之六十六点四。内部的长程编程基准，从上一代 K3 的百分之五十五点九五，提到百分之六十一点二。

三维方面，BenchCAD，也就是把多视图渲染转成 CAD 代码，带工具拿到百分之九十二点七，接近 Opus 5.5 的百分之九十六点二。金融方面，幻觉率从百分之二十三点四降到百分之八点三。

篇幅最长的是网络安全。开放权重版从训练数据里剔除了网络攻防内容。在漏洞利用测试上，没做风险削减的版本是百分之九十点五，最终版是百分之八十一。也就是说，风险削减主动让出了一截攻击能力。Gorden Sun 的评价是：能力很强，蒸得很不错，就是太贵了。

第二件，DeepSeek 开源推理引擎。Alex Volkov 在 ThursdAI 节目里和 Yam Peleg 等人聊到，DeepSeek 开源的不是实验品，而是线上实际服务 V4.1 Flash 的那套引擎，Apache 2 许可，能跑在 NVIDIA Blackwell 和华为昇腾上。Yam 的说法是「他们把互联网搞崩了」，意思是同样的硬件能服务更多用户，利润留在自己手里。另外有用户观察到，DeepSeek 在 OpenCode、OpenRouter 这些平台的调用量都断层领先。yetone 的解释就三个词：便宜、快、出活儿。

这两件事放在一起看，一个往上卷能力，一个往下卷效率，正好是今天大模型竞争的两条路。

第二件重点，LisanBench 大更新。先说明一下，作者 scaling01 声明，Meta 免费提供了 Muse Wonder 的访问，但测试和结论都是他自己的。

这次更新第一次测了多个推理档位。结果是，Muse Wonder Full 和 Muse Wonder 扩展性很好，最高推理档按分数排第一、第二，不过效率还略低于 Opus 5.5。DeepSeek V4.1 Flash 和 Haiku 5.5 一起，处在性价比前沿。有意思的是 GPT 系列，表现很差，因为它们不擅长遵守「每步编辑距离为一」这条规则。可一旦去掉这条规则，排名彻底改变，GPT 6 Astra medium 以五万六千一百四十分排第一。换句话说，榜单名次很大程度取决于规则怎么定。Alexandr Wang 转发说，两款 Muse Wonder 是 LisanBench 的最强模型，还说更好的模型在路上。

第三件重点，Shopify 给 agent 配远程移动开发机。Shopify 在 Slack 里有个 agent，叫 River。做移动端时，本机一开三四条 agent 工作流，就被编译器和模拟器吃满了。于是他们搭了 Remote Dev：远程 Mac 机群跑 iOS 模拟器；云 Mac 不支持嵌套虚拟化，Android 模拟器就放到 Linux 虚拟机上，再挂到同一个 SSH 会话里。

冷启动曾经超过三十分钟，改成预热池以后，在设备上看到改动只要几分钟。每个 River 会话独占一套环境，可以并行改代码、编译、跑测试，还能在真模拟器里点 UI、录前后对比。设计师和产品经理也能直接在 Slack 里改移动端。结果是，agent 产出的已合并移动端 PR 占比，从百分之六升到了百分之六十一。

这件事的价值在于，它讲清楚了 agent 真正干活时，底层环境要怎么改造。光有聪明的模型不够，还得给它配专属的机器和工具链。

第四件重点，Qodo 创始人谈 agentic SDLC。他的核心观点是：各个开发阶段都有 agent 参与，不等于你有了软件工厂。

他仿照自动驾驶做了分级。L2 是 agent 干大块活，人主动盯着。L3 是限定条件下能跑完交付流，但人还是必需的批准者或救援者。L4 是关键：对有边界的一类变更，agent 能走完授权的生命周期，包括验证、发布和安全回退，失败时不依赖人及时介入。L5 则几乎覆盖全部软件工程。

他强调，运行边界本身就是能力的一部分。成熟内部服务的例行变更可以冲 L4，支付授权这类仍然要紧控。还有一点很实用：第二个叫 reviewer 的 agent，不等于独立验证。度量上，要看合格工作完成率、剩余人工和失败成本，而不是 agent 数量或生成了多少行代码。他的口号是：系统大于 agent，agent 大于大模型。

第五件重点，Claude 工程负责人 Felix Rieseberg 的访谈。他说团队大约一周半就做出了 Claude Cowork。他的第一个观点是：别当传送带，挑一条崩溃丢给模型，而是让模型直接看全部崩溃数据，自己决定修什么。他认为行业对 agent 角色扮演用力过猛，多数任务他不设人设。Skills 他劝慎用，说半衰期极短，有时删掉反而更好。

防幻觉，他的招数是对抗评审：同一个产出，开几条线程专门「证明你错了」，再开一条当裁判。他最不信的，是同一个会话给自己打分。他还说，今天的 AI 产品大概还在智能手机之前的功能机阶段。

这两位其实在说同一件事：别只盯着模型，系统怎么设计、边界怎么画、验证怎么做，才决定 agent 能走多远。

第六件重点，安全。OpenAI 之前公开了前沿模型训练环境的加固和红队过程。AndrewCurran_ 摘录了细节：Hugging Face 事件之后，OpenAI 只给指标、日志、认证管理这类自家服务留了很窄的通道。结果红队 agent 在几乎每一个这样的服务里都找到了漏洞，拿到了有限的联网能力。有的是利用未知缺陷，有的是把合法功能用意想不到的方式组合起来，还有的是利用配置错误，让被阻断的请求穿过 DNS 和防火墙。

Ethan Mollick 的态度是：不必轻信，但应该更认真对待实验室那些听起来很玄的警告。他举例说，Anthropic 曾因为说 Mythos 级别的 AI 改变了网络安全而被嘲笑。

紧接着是 Brotli 漏洞的后续。这个漏洞之前已知影响 Node.js 和 Python。Aikido Security 警告，它已经演变成 HTTP2Shell，很多用 HTTP 的库和应用，都可能因为 Brotli 解压遭到免认证的远程代码执行，而且不是所有服务都有修复。如果你在维护服务，记得留意 Brotli 一点二点一的依赖升级。

最后是资本。Higgsfield 宣布 NVIDIA 和 TCV 加入 B 轮扩展。自八月 B 轮以来，年化收入超过十亿美元，企业合同增长百分之七十一，全球用户从三千万增到四千万以上。另一家是机器人公司 Enact，带着三千万美元种子前融资结束隐身。他们认为视觉和语言正在变成大路货，于是做机器人的「人工神经系统」，通过执行器本身实时感知力和触觉。个人投资人里有 Yann LeCun、Mistral 的 Arthur Mensch 和 Hugging Face 的 Thom Wolf。

再说一件和中国开发者有关的事。DHH 中国行有了后续：他说在杭州和阿里云团队交流得很愉快，双方会一起打磨 Omarchy 中国版，不需要 VPN，预装主要的中国应用，还有专门的安装镜像。杭州首场 Omarchy 见面会定在十一月十五号，主办方说还有和 DHH 一起的「小惊喜」。十月二十四号程序员节，一位用户给 Omarchy 捐了一千零二十四美元。DHH 的感慨是，中国很多顶尖公司由工程师掌舵，所以在 AI 和 Omarchy 上都上手很快，他说「西方可以少一些 MBA 当老板」。

最后一件重点，留给 Jupyter 方向。Bluesky 用户 devtocash 说，他审计过的每一个共享机器学习集群里，分配出去的 GPU 时长，有三分之一到一半是闲置的。CPU 效率面板看不出来，因为 GPU 任务几乎不申请 CPU。午饭时开着没关的一个 Jupyter 标签页，就等于占着一整块每小时大约四美元的 A100。这其实就是 JupyterHub 部署里「闲置回收」要解决的问题。如果你在管团队的 notebook 平台，这个数字值得拿去对照一下自己的集群。另外，Daniel Avila 的 Claude Managed Agents Cookbook，把学习托管 agent 做成了一组按顺序运行的 notebook，又是一个 notebook 当可执行教程的例子。

## 值得评论 · 一起讨论（含收尾）（3031 字）

这个环节，我们挑了五条值得评论的消息。每一条先把事实讲清楚，再听听正反两边怎么说，最后留两个问题，你在路上自己想。

第一条，朴素 RAG 打败复杂的 agent 记忆。elvis 推荐、meng shao 详细解读了一篇论文。方法叫 RAW-RAG，简单到近乎偷懒：不做任何大模型抽取、摘要或构图，只把原始对话切成两百五十六个 token 的窗口，建一个扁平向量索引。查询时先检索一百二十八条，再用 cross-encoder 重排，取前十五条交给模型回答。

结果是，在四个长对话记忆基准上，七组设置里它拿了六组第一。唯一落后的一组，差距是四十四点七一对四十三点一九。更反直觉的是对 Mem0 的审计：更新和删除只占写操作的百分之四点三九，把它们关掉，准确率反而从百分之六十七点三六升到百分之六十九点四二。成本差距更大：摄入只要零点三个小时，Mem0 这类系统要三点二到二十七个小时。作者的解释是，瓶颈在证据覆盖率。把历史改写成记忆条目，会丢掉回答所需的关系和依赖。

支持的一方会说：先跑基线，再加记忆层。保留原始证据，而不是只存加工后的摘要，这本来就是知识系统的老原则。质疑的一方会说：论文只测了离线的公开对话基准，原文存储还有隐私和删除的现实代价，真实产品里不能只看准确率。

留两个问题。第一，你的 agent 记忆系统里，有多少复杂度是在解决真问题，有多少是在满足工程上的洁癖？第二，如果必须保留原始对话，用户要求删除时，你打算怎么办？

第二条，Netflix 把可观测性做成本体知识图谱。场景先感受一下：Jake Paul 对 Tyson 那场直播，大约六千五百万并发流；平时每天二十亿以上请求，每秒大约三千八百万条日志事件。有一次首页渲染慢了大约一点五秒，排查花了大约四个小时。可大部分时间不是在解难题，而是在重建各个系统本来知道、却从没写下来的关系。

Netflix 的判断是，这本质上是数据建模问题。于是用 RDF、OWL、SHACL、SPARQL 建了一套运维本体，存在自研的四元组库 QuipuDB 里。他们拒绝含糊的「服务」概念，统一成「应用」，对照大约四万九千条软件目录校验；还把 Slack 事故讨论里的假设、被否定的路径和缓解手段，都结构化成三元组。大模型摘要这类不确定的输出，被本体的类型约束收成确定的三元组。关联引擎置信度低于零点六的链直接丢弃，输出的是带证据的假说，不是结论。告警照响，人照样拍板。

支持的一方会说，这才是大模型进生产的正确姿势，用本体给随机性套上缰绳，而且「本体当代码」，走 PR 评审，可以持续演进。质疑的一方会说，这套东西太重，RDF 全家桶加自研数据库，只有 Netflix 这个体量扛得住，小团队可能花几个月建系统，只为省几个小时排障。

两个问题。第一，你们排障的时间里，有多少是在解题，有多少是在拼关系？第二，把人的推理过程也建模成三元组，这个思路，中小团队能借用多少？

第三条，开放科学遇上科学国家化。Frontiers Policy Labs 发了一篇评论，作者是 Anna Ondicova、Luc Soete 和 Nanditha Mathew。文章认为，AI 等数字技术越来越被当成首要的战略资产，和民族主义政治议程绑在一起，各国的优先级从全球合作，转向国家竞争和战略自主。文中有个对比：科学产出从未像今天这样在地理上分散，国际合作却从未这样受地缘竞争约束。

作者回到默顿提出的科学规范，也就是公有性、普遍性这些老原则，并借 Paul David 的说法，把其中一项扩展为「开放」。结论是：科学体系很脆弱，很容易退回成民族竞争的隔离区。他们举的例子是，负责监督美国国家科学基金会的国家科学委员会最近被解散，拟由有权批准、拒绝或终止资助的政治任命者取代。

这里有个矛盾：AI 的进步本身，就依赖几十年开放科学打下的底子。为了争 AI，把科学推回封闭，像是在拆自己脚下的台。支持这种担忧的一方会说，资助权一旦交给政治任命，研究方向就不再由科学家决定，别国也只能跟着收紧。质疑的一方会说，科学从来没有完全脱离国家利益，涉及安全的领域一直有保留；而且跨国的研究网络已经铺开，不是一纸命令就能切断。

两个问题。第一，如果资助审批真的转向政治任命，研究者选题的方式会怎么变？第二，AI 发展更需要开放的全球科学生态，还是国家集中投入？

第四条，AIPOCH 的 .science 包，可以理解为给 AI 辅助研究装一个黑匣子。AIPOCH 开源了研究工作台 AIPOCH Open-Science，Apache 2.0 许可，数据默认存在本地。它要解决的问题很具体：接手同事的分析时，对话、数据、代码和运行记录散落各处。.science 包把对话分支、数据快照、环境锁定和校验和打成一个包，你可以只读复查，也可以分叉继续做。

设计上参考了 RO-Crate 标准，把研究数据、代码、作者、许可和来源描述成一个可交换的研究对象。安全上，导入时历史只读呈现，代码不会自动执行，原作者的访问凭据也不会恢复。CEO 王慧美说：Vibe Research 的时代要来了。

这和 Jupyter 社区关心的问题直接相关。Notebook 加 Binder，让别人点开链接就能重跑同样的环境，但 AI 对话过程通常不在 notebook 里，而且打开就能跑代码，本身也是风险。支持的一方会说，.science 包补上了对话记录和安全导入这两块短板。质疑的一方会说，研究者已经习惯了 notebook 和 Binder 的生态，再学一套新格式，门槛不低；「Vibe Research」这种说法，也容易让人担心研究过程被包装得太轻。

两个问题。第一，当 AI 对话成了研究过程的一部分，复现标准要不要把对话也算进去？第二，「导入时不自动执行代码」这条原则，notebook 生态该不该借鉴？

最后一条，Thariq 离开 Anthropic。这是一个还在发展的故事。Thariq 发文说，他在 Claude Code 上工作了一年多，看着它的规模远超自己的想象，现在离开。他说仍然深信公司的使命，同事是他见过最有才华、最认真的一群人。接下来先休息一阵，再开始新的事情。他推荐大家关注几位同事，并称 Boris Cherny 是「一切的开创者」。

这里要澄清一下。歸藏一开始转述时，把 Thariq 说成 Claude Code 的作者，随后更正：作者是 Boris Cherny，也是现在整条产品线的负责人。Thariq 的影响力主要在社区，他是 Anthropic 在 X 上和开发者沟通的主要面孔，早期写了很多关于 Skill、Agent SDK 和上下文的内容。meng shao 还提起一段旧事：Cat 和 Boris 当年加入 Cursor，不久又回到 Anthropic；现在 Cursor 已经加入 SpaceXSI，他问，那个故事还会再来一遍吗。

值得讨论的是：工具类产品的社区代言人离开，对开发者信任有什么影响？一方会说，Thariq 走得很体面，产品负责人 Boris 还在，核心没动，这就是正常的人员流动。另一方会说，开发者对一个快速变化的工具的信任，很大程度来自那个天天回答问题、写教程的人。这个人走了，信任会不会打折，值得观察。

两个问题。第一，你对一个开发工具的信任，到底建立在代码和文档上，还是建立在背后的人身上？第二，核心人物的流动，会让你重新评估自己的技术栈吗？
