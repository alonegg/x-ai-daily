# 11 月 3 日 AI 播报

## 开场与头条预告

早上好，今天是十一月三号，星期二。这里是 X 每日 AI 播报，接下来二十多分钟，我们把昨天 AI 圈的事情过一遍。

先说今天最重要的三件事。

第一件，有研究者让一个大模型直接动手改另一个模型的权重，不训练，只改了万分之一点六的参数，小模型的数学能力最多提高了六倍。

第二件，Anthropic 给开发者接口加了一个新功能，长对话不用每一轮都把历史重新发一遍，Claude Code 里，大请求的等待时间少了三分之一左右。

第三件，独立开发者 levelsio 用 Claude Code，把一款二十多年前的经典射击游戏，从机器码一路翻译成网页版，还能联机。

另外，评论环节会聊一个很实际的问题：为什么最有经验的程序员，反而对 AI 编程最谨慎。

## 快讯

下面是快讯。后面重点和评论要细讲的，这里先跳过，只说其余的新鲜事。

先看开发者工具和价格。DeepSeek 的搜索和网页抓取工具结束免费了。现在按成功的请求次数收费，每一千次零点七五美元。失败和空结果不收钱。如果你的 agent 每天大量搜索，月底会多一张工具账单。

OpenRouter 出了一份教程，教你搭一个会自己找证据的 AI 代码审查。它把改动传进一个沙箱，写小脚本把问题真的复现出来，每条发现都标上已确认或未确认。一次审查只要几美分。

一家叫 Arca 的公司，AI 负责人在访谈里讲了两条规矩。第一，按任务分模型，税务分析用最强的，后台杂活用便宜的。第二，凡是动钱、清算资产，或者直接联系客户，都必须有人把关。

字节跳动的智能体平台扣子要下线了。一位曾在那里做工作流引擎的开发者感慨说，拖拽节点的工作流不是被 AI 淘汰的，而是被模型自己会规划淘汰的。当年拼命做的那些节点，其实是在替模型的笨买单。

浏览器也成了 agent 的标配。LangChain 的工程师说，光是九月一个月，agent 操作浏览器的请求就涨了大约五倍。

再看产品。Theo 的 T3 Code 开始支持企业统一配置。他还说，照现在的速度，T3 Code 一年要跑掉的 token，大约是 OpenAI 去年全部用量的两倍。

独立开发者 yetone 做了一次个人 agent 大考核，让几个 agent 找一张壁纸的最高清版本。多数只找到一张小图就交差了，有的直接放弃。最让他惊喜的是他自己做的 Alma，不但找到了网上最清楚的那张，还自己调用超分程序再放大一遍。Alma 的安卓版也同一天发布了。

AI 博主归藏说，Grok Bot 最近用量收紧，很多人的额度一下子跳了两三成，用到最强模型的几率也在变低。他认为个人 agent 这门生意到底赚不赚钱，现在很难算。

Rails 的作者 DHH 那套 Linux 系统 Omarchy，四点五版的第三个候选版发布了，最快七秒装完。有人把它装上了老款 iPad mini，DHH 自己在英伟达的新芯片上离线跑本地模型。

一家法律 AI 公司的技术负责人在访谈里说，有一次模型升级，他们什么都没做，引用的准确率就从七成涨到了九成九。

再看模型和研究。有中文博主介绍了一个检索新方法。它把资料库整理成分类、标题、段落三层，让模型一层层打分往下找。在两百多万个维基百科段落里，一两秒就能找到答案。

还有两条传闻，都没有证实。一条说，一个叫 Fable 五点五、还没正式发布的新模型正在小范围测试，有人用它纯靠代码做出了一段很漂亮的视频。另一条说，网上出现了一个据称是超大模型的片段，参数规模达到十四万亿。

法国的 Mistral 发布了 Large 四的技术报告。有人总结，他们在训练中吃过一个亏：预训练的曲线看着很好，agent 能力却很差，后来动了大手术才解决。

论文方面，Meta 放出了一个空间推理测试，给你看几块拼起来的积木，让你猜被挡住的那一面长什么样。还有一个开放的语音模型，把听懂、推理和调用工具合在了一起。

安全这边。昨天的节目里说过一个 Linux 网络漏洞，只要开着一个端口就可能被接管。levelsio 说，Ubuntu 到现在还没修，他在考虑把服务器全换成 Debian。币安被盗案也有后续，美国联邦调查局全球通缉一名朝鲜黑客。

levelsio 还抛出一个争议：通行密钥通常存在密码管理器里，解锁一下就能用，所以它其实是单因素认证，并不比密码多一道保险。

观点方面。DHH 说，agent 时代对多数程序员是好事，但对难相处的人会很难，技术再稀有也不能当护身符了。他还说，对 agent 也要说请和谢谢，因为你怎么对它，就会怎么对人。

沃顿商学院教授 Ethan Mollick 说，理解 AI 实验室为什么总是突然改产品、沟通又差，要记住一点：在它们眼里，产品只是在真正的通用人工智能到来之前，为了融资不得不做的临时东西。

昨天节目聊过卡帕西用黑客新闻二十年评论做的视频站。现在有人发现，这份数据在 Hugging Face 上就能下载，一共十二个 G。AI 博主向阳乔木已经用它做了一个论文站和一个书籍推荐站。

最后是开放科学和 Jupyter。Jupyter 社区工作坊的提案征集，十一月三十号截止，每场一般能拿到五千到一万五千美元。欧盟启动了一个四年的分类学项目，经费一千二百万欧元，要把欧洲的物种鉴定数据和专家连起来。维基媒体尼日利亚社区办了一场活动，新写了五百九十八篇女性人物条目，大部分是用豪萨语和约鲁巴语写的。伦敦的 Connected Data 大会预告了一场对谈，请来语义网最早的作者之一，回顾二十五年前那个让机器读懂数据的设想，今天在 agent 身上应验了多少。心理学预印本平台 PsyArXiv 宣布迁到新的托管方。生物信息平台 Galaxy 的用户突破了五十万。

## 重点一：Claude 接口有了消息线程

为什么重要？因为 agent 一次任务可能来回几百轮，每一轮都要把整段历史重新上传一遍，光是传数据就拖慢了回复。

Anthropic 昨天宣布，开发者接口开始公测一个叫消息线程的功能。服务器在两轮之间帮你暂存对话。下一轮你只要发新消息，再带上上一条回复的编号就行。

效果怎么样？Claude Code 已经默认用上了。官方说，在几十万到上百万 token 的大请求上，等待第一个字出来的时间，中位数少了三成多。长对话里，一次请求的大小，从八百多 KB 降到不到两 KB。

但要注意三点。第一，它省的是上传，不省钱。模型每一轮还是要把完整对话读一遍，token 一个不少。第二，它和提示词缓存是两回事，缓存还得自己设，官方示例是两个一起用。第三，线程五分钟没动静就过期，所以你本地还得留一份完整记录。

还有一位开发者提醒得很到位：大模型本身还是没有记忆的，变得有状态的是接口，不是模型。

我们的看法是，这是给长时间运行的 agent 修路，不是给模型加记忆。对做编程 agent、操作电脑 agent 的团队来说，是实打实的速度提升。但它不支持零数据保留，对数据留存要求严格的企业，用之前要看清楚。

## 重点二：一款老游戏，从机器码搬到网页

为什么重要？因为这一次，没有任何前人的开源代码可以参考，AI 是从最底层的机器码开始，一点点把游戏重建出来的。

levelsio 说，《战地 1942》是他最喜欢的游戏。他之前把雷神之锤和毁灭战士搬上过网页，但那些游戏都有大量开源项目打底。这一款，厂商从没开源，也没人移植过。半年前他试过，基本放弃了。

这次他用 Opus 五点五，问了一句：能不能把这个文件夹里的试玩版移植到网页。

接下来，Claude Code 先反汇编，找出了五万七千个函数。再把每个函数翻译成 C 语言，一共写出十万行。然后编译成能在浏览器里跑的 WebAssembly，也就是网页里的高速运行格式。

游戏还用到大约三百个 Windows 和图形接口的函数，都要改写成网页能用的图形接口。最后，他们还自己搭了一套网络层，让游戏能连上联机服务器。

levelsio 很坦白地说，他完全不懂这些是怎么做到的。成本呢？输出大约一百万 token，按接口价格大约一百美元，而他付的只是每月一百美元的订阅。

我们的看法是，这件事的意义不在游戏，而在逆向工程的门槛。过去要一个专业团队干几个月的活，现在一个人一天就有了可玩的版本。但能跑和没问题是两回事，他自己也在请大家报 bug。另外，这是厂商放出的免费试玩版，版权上的边界，值得每个想照着做的人想清楚。

## 重点三：两个新基准，一个难，一个接地气

为什么重要？因为很多老牌测试已经被模型做满分了，大家需要新的尺子，量一量 AI 到底能干多少真活。

半导体分析机构 SemiAnalysis 发布了一个叫 GDPx 的新测试，专门衡量 agent 在最值钱的行业里能做成多少事。结果是，最好的模型也只拿到百分之十二。

Ethan Mollick 的评价很中肯。他说很高兴看到这个测试，但它缺一样东西：人类专家的基线。没有人的成绩做对照，十二分到底算好算坏，说不清楚。

他还发现一个有意思的细节：用 GPT 六 Pro 去检查，居然找出了评分本身的几处错误。他也认为，很多零分掩盖了真实的差别，有的模型差一点就成了，有的差得很远。

同一天，OpenAI 发布了另一个测试，叫 LifeVal。它的题目来自几千名 ChatGPT 用户的反馈，问的是大家最希望私人助理帮什么忙，比如找托育、办政府手续、管理家庭财务。

我们的看法是，这两个测试代表两个方向。一个往高处走，看 AI 能不能做专家的活。一个往低处走，看 AI 能不能帮普通人过日子。但注意，LifeVal 是 OpenAI 自己做、自己用的，要等第三方拿它去测别家模型，才更有说服力。

## 重点四：一颗红心，就能改变模型写代码的方式

为什么重要？因为它说明，图片对多模态模型的影响，可能悄悄发生，连模型自己都意识不到。

一位中文博主介绍了 Google DeepMind 的一篇论文。研究者在写代码、写文章这类任务里，塞进一些和任务毫不相干的小图形，比如红心、三角、箭头，一共两百多种。然后拿 Claude、Gemini、GPT 的几个版本做对照。

结果很奇怪。放一张红心，原本习惯用循环写法的模型，会全部改成递归写法。放一个圆圈，模型就更爱选环形缓冲区，也就是一种首尾相连的数据结构。

更值得注意的是，模型自己完全没察觉。研究者翻看它们的思考过程，模型会说这纯属巧合，或者编出一套听着很专业的理由。

还有一个发现：让两个模型用图画互相沟通，它们会形成人完全看不懂的暗号，彼此却一看就懂。

我们的看法是，这件事对安全的意义大于趣味。如果一张无关的图就能左右模型的选择，那网页、文档里的图片，都可能成为暗中引导 agent 的渠道。目前我们只看到中文转述，细节要以论文原文为准。

## 重点五：Anthropic 招资深人士转行做 AI 安全

为什么重要？因为它说明，前沿实验室觉得缺的已经不只是机器学习专家，而是会判断什么问题值得研究的人。

Anthropic 昨天开放了一个叫 Residency 的项目申请。这是一个付费的全职研究项目，分六周、三个月、六个月三档。招的是三类人：数学物理这类定量学科的教授，技术型创始人，还有大公司里资深的工程骨干。

最特别的一点是，不要求博士学位，不要求机器学习经验，也不要求发过论文。

每个人会配一位 Anthropic 研究员当导师，课题由对方提出，有专门的算力预算。方向有三块：安全与对齐，安全攻防和红队测试，还有模型训练背后的基础设施。

待遇不低。美国岗位年薪折合三十五万到五十万美元，按实际时长计算。十一月二十二号截止，预计明年一月发录用通知。

Anthropic 给的理由是，机器学习还是年轻领域，它自己很多资深研究员原本就是物理学家、数学家或者工程师。模型越强，越重要的是定方向、判断什么值得做。

我们的看法是，这是一个信号：在 AI 安全这件事上，跨行的资深经验开始被明码标价。如果你身边有这样背景的人，值得转给他看看。

## 重点六：pyOpenSci 拿到资助，研究 AI 怎么改变科学开源

为什么重要？因为科学研究依赖的大量 Python 软件，是靠志愿者维护的，AI 工具正在改变这些人之间的关系。

pyOpenSci 是一个帮科研人员写好软件、做同行评审的开源组织。它昨天宣布，拿到了斯隆基金会的资助，专门研究 AI 工具如何改变科学开源。

过去半年，他们在好几场开源大会上组织讨论，总结了三点感受。第一，维护开源的人确实吃紧，很多维护者怀念过去那种自然的人际交流。第二，关于 AI 的讨论很容易两极分化。第三，很多人在明确的场景里觉得工具真的有用，他们的评审数据显示，多数人每天都在用。

接下来分两步。先大规模倾听，做问卷和小组访谈，并分析各个项目已经写好的 AI 政策。再根据结果，给贡献者写一份实用指南，强调和工具一起设计，而不是照单全收。还会给维护者准备一套现成的资源，不用从零写政策，就能说清楚自己项目接受什么样的 AI 辅助贡献。所有成果都会开放许可。

我们的看法是，这比再写一份禁止或允许的政策更有价值。它想回答的是，好的 AI 使用到底长什么样。对做 Jupyter 和科学计算的人来说，这份指南出来以后，很可能成为各个项目参考的模板。

## 一起讨论

接下来是值得评论，一起讨论。我们会讲清楚原帖说了什么，也会明确说出我们自己的判断。

## 评论一：一个模型给另一个模型做手术

先说原帖。一位研究者说，他们让 GPT 六 Astra 去编辑一个只有八亿参数的千问小模型的权重，目标是提升数学能力。没有用梯度，也没有训练，只直接改了万分之一点六的权重。结果是，小模型原来会陷入的推理死循环修好了，数学最多提高六倍，听从指令的能力提高三倍。他们把这叫做权重空间编程。

反应很热烈。Mollick 说，要等别人复现，但这是件大事。MIT 的一位教授说，这是他同事的工作。另一位知名创业者干脆叫它人工脑外科手术。

我们的判断是：先别急着兴奋，也别急着否定。值得兴奋的地方在于，如果模型真的能读懂并修改权重，那调教模型的方式，可能从喂数据训练，变成直接动手改。

但最有力的反对意见也很清楚。第一，目前我们看到的只是一条推文的开头，细节在博客里，还没有独立复现。第二，改的是一个很小的模型，在大模型上能不能成立，完全是未知数。第三，最多六倍这种说法，要看是在哪些题上、从多低的起点算的。

给你一个具体建议：这周如果有人跟你转这条消息，先问两个问题。有没有第三方复现？改动前后能不能拿同一套公开题目对比？这两个答案出来之前，把它当成一个很有意思的假设，而不是结论。

## 评论二：MCP 是不是一个没有契约的接口

这一条，我们用正反两方来讲。

先说背景。MCP 是一种让 AI 连接外部工具的标准协议，很多网站都在给自己加 MCP。

一位开发者说了一个反直觉的观察：他在自己的应用里都做了 MCP，但他自己的 agent 几乎从来不用。原因不是 MCP 不好，而是大多数环境里，要人先去安装、配置连接器。agent 做不了这一步，只能停下来叫人。而它直接调接口、或者打开浏览器，就能把事办了。他甚至发现，有的 agent 悄悄绕开了专门为它们做的 MCP。

但他仍然在做 MCP，理由很有意思。传统接口要有契约，要版本化，要长期兼容，因为有别人的代码依赖它。agent 不一样，它每次都现读文档，所以接口可以随时重写，还能开放一些传统接口懒得做的功能，比如注册账号、删账号。他的结论是，MCP 最后会变成没有契约的接口。

levelsio 站在合并派。他说，长期来看，MCP 和普通接口会合成一个东西。

我们的判断是：没有契约这件事，对 agent 是好事，对人是隐患。agent 能适应变化，但做审计、做复现的人需要知道，昨天那个 agent 调用的到底是什么。在科研和自动化流程里，这一点尤其重要。

给你一个具体建议：如果你在给自己的服务做 agent 接口，这周先写好一份 agent 能直接读懂的说明文档，比急着上 MCP 更管用。

## 评论三：marimo 走进斯隆数字巡天

这一条是案例型，我们先讲故事。

斯隆数字巡天，是过去二十多年最有影响力的天文项目之一，积累了几十 PB 的观测数据，每年有几百篇论文引用它。

问题出在日常使用上。维护者电脑上能跑的 notebook，到新人手里经常坏。想看一个参数怎么影响结果，要手动改代码、一格一格重跑。新成员还得先啃大量文档，才知道自己要的数据在哪。

marimo 是一种响应式的 Python notebook，你改一个参数，相关的图和表会自动更新。一位天文学博士生用它几天就做出了合作组盼了好几年的工具：上传一串恒星编号，自动取回光谱，在散点图上框一下，就能看到对应的数据，不用写一行查询。

文章还提到两点。一是 notebook 存成普通的 Python 文件，依赖也记录在文件里，可以放进版本管理。二是可以发布到网页，直接在读者的浏览器里运行。过去要靠 Binder 服务器才能跑的教程，现在可以直接嵌进文档。而合作组的这些应用，本身就部署在一家研究所维护的 BinderHub 上。

我们的判断是：这个案例最值得关注的，不是哪家 notebook 更好，而是 notebook 的角色变了。它从个人的草稿本，变成了几百位科学家进入数据的入口。另外要提醒一句，这是 marimo 官方发布的案例，周数变分钟这类说法，是用户的原话，不是独立评估。

给你一个具体建议：如果你在维护某个数据集的教程，这周挑一个最常被问的问题，做成一个能直接点、能框选的小交互页面，看看新人上手是不是快了。

## 评论四：为什么最有经验的程序员最谨慎

这一条，我们先讲一个实验。

咨询公司 Thoughtworks 的一位技术负责人写了篇文章。她发现，很多一向爱尝新的资深开发者，对 AI 编程反而很谨慎。她说，这不只是爱写代码或者怕失业。

她的公司做了一周实验：人一行代码都不写，全部交给 agent，做一个航空类应用。结果做到了大约八成。人大部分时间站在白板前，理清业务、画好边界，给 agent 可执行的计划，再设计测试和检查。

但问题也出现了。应用能跑，构建却经常是红的。红灯一多，大家就麻木了，红不再意味着停下来修。检查不可信的时候，绿灯也不再让人安心。她还引用了一份行业报告：AI 的采用，和更高的产出相关，但也和更低的交付稳定性相关。

有人把资深开发者比作成年后才学滑雪的人，知道摔断腿的代价。软件专家 Martin Fowler 补了一刀：雪道上已经有无数人安全滑到底，agent 开发更像一片没有地图的野地。

我们的判断是：这篇文章和昨天聊过的证据包自动合并，正好是一体两面。一边说，靠测试、截图和录屏，就能放心让 agent 合并。另一边说，当测试也是 agent 写的，绿灯本身就需要被检验。两边都对，关键在于谁来检查检查者。

给你一个具体建议：这周看一眼你团队的构建记录，数一数红灯持续超过一天的次数。如果比用 AI 之前多了，先修流水线，再加 agent。

## 评论五：上市文件里的加速

这一条，我们只讲事实，然后说说怎么读。

Anthropic 准备上市，提交了修订版的上市文件。一位研究者注意到其中一句话：Anthropic 对未来模型的内部估计显示，它可能即将达到自己安全政策里定义的，由 AI 带来的大幅加速进展。

这个定义是什么意思？简单说，就是 AI 能力的进步速度，达到没有 AI 帮忙时的两倍，而且这种加速很可能来自研究和工程本身被自动化了。他打了个比方：两年的进展压缩到一年。

同一天，一档 AI 播客的主持人引用分析师的说法，Anthropic 的季度收入从五十亿美元左右，一个季度涨到一百一十五亿，下一季度又到了一百六十八亿。他也注明，最后这个数字来自文件之后的报道，不是文件本身。

我们的判断是：这句话要放在上市文件的语境里读。上市文件既要吸引投资者，也要充分披露风险，所以既可能有乐观的成分，也可能是出于谨慎的预先说明。原帖没有说 Anthropic 具体依据什么估计，我们也不猜。

但有一点值得记住：这是一家前沿实验室，在一份有法律责任的文件里，正式写下了加速可能就在眼前。

给你一个具体建议：如果你关心这件事，别只看二手解读，找到文件里风险因素那一章，自己读一遍原文。
