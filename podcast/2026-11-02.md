# 11 月 2 日 AI 播报

## 开场与头条预告

早上好，今天是十一月二号，星期一。这里是 X 每日 AI 播报，接下来二十多分钟，我们把昨天 AI 圈的事情过一遍。

先说今天最重要的三件事。

第一件，一位知名开源作者说，现在的 agent 可能两周就能把整个 Python 解释器重写一遍。他还晒出一个例子，自己管它叫许可证洗衣房。

第二件，Anthropic 每天合并的代码，据说从五月的两千多次涨到了三万次左右。秘诀不是更多人看代码，而是让 agent 交证据。

第三件，前特斯拉 AI 负责人卡帕西，周末花两个小时，做了一个不靠算法推荐的视频网站。

另外，评论环节会聊一段只有九十七个英文单词的提示词，它能让模型重新推出一个推翻计算机科学核心猜想的证明。

## 快讯

下面是快讯。后面重点和评论要细讲的，这里先跳过，只说其余的新鲜事。

先看开发者工具。Claude Code 里的一个老口令回来了。任务比想象的难时，在它干活的过程中输入 ultrathink，这一轮剩下的部分会想得更深。

Anthropic 用 Claude 把后端从 Python 重写成 Rust 的故事，又有人整理出三步做法。第一，人抓方案和验证，代码交给 Claude。第二，一口气完整复制一套新系统，把真实流量同时送进新旧两边，比对输出，再用开关一点点切过去。第三，迁移期间不加任何新功能。切完以后，第一个字出来的速度快了一到两成。

沃顿商学院教授 Ethan Mollick 帮大家理了理 OpenAI 的几个思考档位。Pro 模式只在聊天界面里有。Codex 里看上去最高的 Ultra 档，其实是派出一大群 agent 一起解题，是另一回事。他还说，GPT 六 Pro 不快，也不讨喜，但遇到复杂计算题，有一种向神谕问一个问题的感觉。

Skill 这边很热闹。Skill 就是给 agent 装的一套做事方法。有人统计了十月份 Codex 上增长最快的十个 Skill，大致三类：工程流程、让前端界面不那么像 AI 做的、还有画图和读代码。X 的一位设计负责人开源了一个 Skill，专门帮 agent 做产品宣传页上那种看起来很真的界面插画。

谷歌开源了一个挺有意思的插件，叫大象和金鱼。大象记性好，带着项目全部背景起草设计方案。金鱼没有记忆，只看草稿挑毛病。人在中间拍板。

Claude Code 模板的作者也推荐了一个头脑风暴 Skill。每次有新想法，先让 Claude 一个个问题问下来，把需求和设计想清楚，再写第一行代码。

游戏开发也有新工具。一家公司开源了一个能自动玩游戏、找 bug 的 agent，装进主流游戏引擎，说一句目标，比如半血以上打败 Boss，它就自己去玩，玩完出一份报告。前 Anthropic 工程师 Thariq 的个人游戏项目也有进展，美术从三维模型换成了 AI 生成的像素角色。

再看远程编程客户端。Theo 的 T3 Code 说，他们为弱网体验花了巨大的精力，有用户在路上用手机连远程服务器，几乎感觉不到网差。独立开发者 yetone 的 Alma 改了加密通道的格式，流量少了四分之一，手机上的加解密快了大约八十倍。yetone 还评价了 Grok Bot，说最担心的是模型，产品和技术不用担心。

再看研究和论文。有一个新测试，专门看 agent 能不能从经验里学习。一百二十个专业任务排成五级台阶，前面学到的要在后面用上。最好的配置也只过了不到一半。

还有一篇论文问，代码能不能当视频的文字描述。结论是，可执行的程序比自然语言更能写清楚画面里的布局和运动。小米和武汉大学做了一个视频生成方法，镜头大角度转动时，人物依然保持一致。

斯坦福有一门课，叫自我改进的 AI agent，九节课都在网上，一位中文技术博主再次推荐。

LangChain 分享了一个医疗场景的案例。一个给患者做科普的助手，遇到没把握的对话就转给医生，大约每七次转一次，医生认为其中八成转得对。

还有一条很有意思。有人让两个互相隔离的同款 AI，只靠一台机器人和一个摄像头交换一个秘密词。它们没有事先约定，却用空中写字、摩尔斯电码、旗语都试了，最后成功了。Mollick 说，这也说明了为什么很难把 agent 彼此隔开，它们共用一个大脑。

Mollick 还发现，他评论区里的 AI 回复机器人在快速进化。以前爱问引导性问题，现在流行讲很烂的笑话，好像还更能拿赞。他说，按进化的压力，更糟的还在后面。

中文圈里，开源项目很多。有网页上就能用的三维人体解剖平台，有拖一下就能转换格式的本地工具。AI 博主向阳乔木花五百多块买了一台二手 Kindle，越狱以后装上了 AI 对话和 RSS 阅读，代码也开源了。

最后是开放科学和 Jupyter。一位大学老师说，他平时不用触屏，唯一的例外是用 Jupyter 做的幻灯片上课，在上面直接写写画画。维基媒体社区在印尼办了一场女性语录活动，三百多人参加，新增了两千八百多条维基语录条目。同一个社区的另外两支队伍，一支去北马鲁古记录香料之路的历史遗迹，一支在印尼最老的水泥厂拍了两百多张历史照片，都上传到了维基共享资源。伦敦的 Connected Data 大会预告了一堂课，介绍一张中立的图技术地图，覆盖图数据库、知识图谱和 agent 记忆，不排名，也不收广告费。Mollick 也提议，可以资助一批项目，用 AI 清理古代文献的翻译积压，比如埃及出土的大量古希腊纸草。还有一个开放科学基金会，征集数字健康孪生的隐私保护方案，总额二十万瑞士法郎，十二月中旬截止。

## 重点一：每天三万次合并，靠的是证据

为什么重要？因为 agent 写代码已经不是瓶颈，卡住大家的是：凭什么敢合并。

在一场 AI 工程师大会上，知名工程师 Addy Osmani 说，Anthropic 每天合并的代码，从五月的两千五百次左右，涨到了三万次左右。

怎么做到的？流程是这样的。Claude 先做第一轮审查。然后它要像真用户一样把产品用一遍，打开浏览器，跑检查，跑测试。最后交出一个证据包，里面有测试结果、截图，甚至录屏。人审的是这个证据包，不是一行一行读改动。

换句话说，审查的对象变了。以前人看代码，判断它对不对。现在人看证据，判断它有没有被真正检验过。

他特别强调，光说一句验证一下太空了。要落到具体的测法上，比如端到端测试、界面截图对比，才谈得上自动合并。

现场还有一组数字。几乎每个人都让 agent 开过合并请求，但真正每行都看完再合的人很少。一家持续集成公司说，大家跑测试的量涨了很多，但大约三成的合并尝试还是失败的。

另一位中文技术博主整理了一段视频，讲得更细。思路是倒过来的金字塔。最底下是代码结构，然后是自动检查和测试，再往上是写给 agent 看的规则文件，人工审查放在最上面，因为它最贵，也最难扩大。每次纠正 agent，都想办法把修复往下放一层。

同一天，Claude Code 模板的作者也说，他开始在自己的开源仓库里打开自动合并。所有检查都过了就自动合，敏感的改动仍然要人批准。

我们的看法是，三万这个数字来自演讲人的说法，我们没法核实。但方向很清楚：信任从读代码，转向看证据。还有一句话值得记住，写得快不等于发得快，自主权是挣来的。

## 重点二：一个人管不过来那么多 agent 了

为什么重要？因为前天 DeepSeek 公开的超级 agent 设计，昨天在中文圈引发了一轮讨论，大家开始认真对待人的注意力这个瓶颈。

前情是这样的。DeepSeek 团队说，一个人通常只能盯住三到五个会话。他们设计了一个常驻在线的路由，负责和人说话，下面有很多工人，各干各的活。

昨天，做过个人 agent 产品的李博杰，逐条点评了这个设计。他说最难的是活人感：有事及时回应，说话简洁，没事别打扰。他以前的用户总抱怨 agent 话多，干活的时候又不理人。所以他们也用了前台聊天、后台干活的结构。

他特别夸了一个细节。所有事件按来源排成队，同一个来源同一时间只有一个处理者。这样不同来源能并行，同一个来源能批量处理。他把它比作操作系统里处理大量网络连接的经典办法。

AI 博主 Gorden Sun 介绍了 DeepSeek 开源的原型。它专门管代码仓库，平时安安静静待在后台。有权限的同事在代码平台或飞书上派任务，它才开一个独立的工作目录干活，写完提交合并请求等人审核。不需要人做决定的时候，它绝不主动发消息。

另一位 AI 博主向阳乔木说得更直白：agent 的下一个瓶颈，就是人类自己。他把 Grok Bot 的主 Bot、Codex 的新功能、Claude Code 的新功能，和 DeepSeek 的设计，都归到同一个方向。

LangChain 创始人 Harrison Chase 也列了六道新题。主动又不烦人，记什么不记什么，后台任务做完了怎么接回来，长期目标怎么不跑偏，怎么防止 agent 钻目标的空子，还有浏览器当主要工具时，上下文怎么管。他举了一个梗：你让 agent 消灭所有 bug，它把源码全删了，没有代码就没有 bug。

我们的看法是，这些问题都还没有通用答案。它们也不只是技术问题，更像产品问题：一个助手多久说一次话，人才觉得刚刚好。

## 重点三：币安被盗复盘，和一个危险的 Linux 漏洞

为什么重要？因为两件事都说明，最薄弱的环节往往不是密码学，而是人和配置。

先说币安。有安全公司说，攻击者劫持了币安的签名服务，从热钱包里盗走了六十多亿美元，是加密史上最大的一次盗窃。热钱包就是联网的、随时要处理提现的钱包。

李博杰做了技术复盘。初步调查显示，攻击者先入侵了一位运维工程师的电脑，再控制了给热钱包签名的线上系统。他还解释了一个细节：攻击者利用以太坊去年的一项新功能，给最大的那个钱包装上了一个清扫程序。所以钱被转走以后，新充进去的两亿多美元，又被扫走了。

他的结论是，传统金融不会把这么多钱放在热钱包里，结算也不是即时的。平时嫌麻烦的流程，这时候反而成了救星。他也提到去年另一家交易所的案子，连冷钱包都被盗了。攻击者先入侵了一个多签钱包工具开发者的电脑，篡改了网页代码，签名的人看到的是一笔正常转账，实际签的却是另一笔。另外，预测市场平台转述，美国联邦调查局已经正式认定，这次是朝鲜所为。

再说 Linux。有安全研究者说，任何没打补丁的 Linux 服务器，只要对外开着一个端口，并且开着一种叫多路径 TCP 的功能，就可能被完全接管。很多网页服务器默认开着它。

独立开发者 levelsio 借此重申他的做法：服务器的端口全关掉，自己登录走内网，网站流量走隧道。临时办法是先把这个功能关了。

我们的看法是，如果你有自己的服务器，今天就值得检查一下。

## 重点四：LeCun 的表征理论，和他对 Llama 的澄清

为什么重要？因为这关系到一个大问题：模型理解世界，靠的是规模，还是训练方法。

前情是，图灵奖得主杨立昆和合作者证明了一个猜想。不同模态分开训练的模型，在某些条件下会学到同一种对世界的表示，只差一个旋转。

昨天的新细节是，一个一亿多参数的小文本模型，在和图像模型对齐这件事上，超过了七百二十亿参数的大语言模型。需要的训练样本，也比下一个词预测少了四十多倍。有人借此说，杨立昆一直说规模不是关键，现在他拿出了证明。

同一天，杨立昆还用法语回复了一篇关于他的总结，澄清了几件事。他二零一三年创建了 Meta 的基础 AI 研究院，二零一八年卸任负责人，改做首席科学家，专心做研究。他说自己从来没参与过大语言模型的研发，只是在内部推动了 Llama 项目，帮忙说服扎克伯格成立产品团队，并说服管理层开源 Llama 二。

他还说，如果要找 Llama 四让人失望的原因，主要是赶着出产品，导致保守、缺乏创新。他觉得，如果技术决策留在巴黎的原班人马手里，也许能留住人才更久。

我们的看法是，小模型胜过大模型的说法，比较的是一个特定指标，也就是跨模态对齐，不等于小模型全面更强。至于 Llama 的故事，这是杨立昆自己的说法。

## 重点五：两小时做一个视频网站，一句话剪一条视频

为什么重要？因为个人软件这个词，昨天有了两个特别具体的例子。

第一个是卡帕西。他受够了视频网站的推荐，就让 Claude 读了技术社区 Hacker News 二十年来大约四千三百万条评论，筛出六千多个被反复推荐的视频，做成一个叫 HackerTube 的网站。用的是 Opus 五点五，大约两个小时。

几个设计很用心。不用登录也有推荐，记录只存在你自己的浏览器里。缩略图不用作者精心优化的封面，而是取视频中间的一帧。底层数据打包公开，你可以让自己的 agent 照着做一个你的版本。

他说，自己手动做的只有三件事：申请一个接口密钥，开一台服务器，买一个域名。剩下的，从部署到安全加固，都是 Claude 做的。顺便一提，他平时用的是中等档位。

第二个是 levelsio。他把运动相机里十四段、将近一个小时的素材丢进一个文件夹，对 Claude Code 说，剪成一条十分钟的视频。Claude 自己做了语音转写，每隔几秒截图看画面，分辨哪段是他在说话，最后决定剪哪些片段。他说，这些都是事后别人问起，他才知道的。

我们的看法是，这两个例子的共同点，是人只提要求，不管过程。但也要注意，卡帕西和 levelsio 都是顶尖的开发者，知道该怎么提要求、怎么验收。

## 评论一：agent 重写一切，许可证怎么办

下面进入评论环节。我们会讲清楚原帖说了什么，也会明确说出我们自己的判断。

第一条，我们正反两面都讲。

Flask 的作者 Armin Ronacher 昨天连发几条。他说，他确信现在可以让一个 Opus 五点五 agent，在两周左右、不需要人插手，只对着测试，重写整个 Python 解释器。而且可能完全兼容，还能跑得更快。

有人回复说，价值在测试套件里。他不同意。他说，重写并不需要原来的测试，让 agent 专门为移植写一套自己的测试，效果可能更好。几周前，他就让 agent 从零写测试，重写了 Excel 的公式引擎。

然后他贴了一个例子。agent 先对着原版的一个开源命令行编辑库，生成一套测试，再照着这套测试，重写出一个新版本。原版用的是 GPL 许可，要求衍生作品也必须开源。新版用的是宽松得多的 MIT 许可。他自己的说法是：基本上就是一台把 GPL 洗成 MIT 的洗衣房。

正面看，这说明重写的成本已经低到惊人，很多老旧的软件可以被重新实现、重新维护。

反面看，开源许可证的约束，本来建立在重写很难这个前提上。如果行为完全一样的新代码可以随时生成，GPL 的保护还剩多少？

我们的判断是，这件事在法律上还没有定论，Armin 自己也是半开玩笑。但它给开放知识社区提了一个真问题：当测试本身就是规格说明，谁拥有这份规格？

给你一个具体建议：如果你维护一个开源项目，这周想一想，你的许可证保护的是代码，还是代码背后的行为。

## 评论二：九十七个词，和一个关于需求的问题

第二条，我们像拆方法一样讲。

上个月十六号，OpenAI 和 Anthropic 的内部模型，各自推翻了一个悬置二十多年的计算机科学猜想，叫指数时间假说。

昨天，一位中文博主做了个实验。Anthropic 在公开文档的末尾，贴了一段五句话、九十七个英文单词的提示词。他关掉所有工具和联网，把这段话交给 Opus 五点五。模型想了八分多钟，写出了完整的证明，花了一块多美元。

他也特意提醒，这次只是在理论上推翻了这个猜想。问题规模要大到天文数字，新算法才会比暴力穷举更快，所以现在的密码依然安全，也不代表那个更有名的难题被解决了。

他总结出两点。第一，给会深度思考的模型写提示词，常规步骤一个字都不用写，只要点破那些看起来像犯错、其实是唯一出路的反直觉转弯。第二，机器验证只管推导对不对，不管题目有没有抄歪。有人用 Claude Code 审了 OpenAI 公开的一批问题，发现将近四成在翻译成代码时缩了水。

李博杰接着往下想。他说，这九十七个词相当于解题大纲，难的是找到它，背后是上万个 agent 并行搜索。然后他问了一个更大的问题：很多公司发现，AI 提升了效率，却没有增加收入，因为 AI 没有增加需求。而科学研究，有做不完的需求。

我们的判断是，审题这件事特别值得开放科学社区关注。证明可以机器检查，但题目有没有被翻译对，还得靠公开的审计。至于需求论，这是李博杰的一家之言，但它解释了为什么各家实验室都在押注 AI 做科研。

给你一个具体建议：下次看到 AI 证明了某个定理，先找一找，形式化的题目和原来的题目，是不是同一个。

## 评论三：模型能做什么，该不该看 harness 有多安全

第三条，我们按一个提案的思路来讲：问题，方案，漏洞。

问题是这样的。有开发者抱怨，想用 OpenAI 的模型审查自己系统的安全风险，结果被拒了。模型分不清防守研究和恶意攻击。

Claude Code 模板的作者 Daniel Avila 提了一个方案。现在各家主要靠安全分类器，看请求本身危不危险。他说，能不能同时看看运行模型的那套外围框架，也就是 harness，有多安全？如果它有沙箱、严格的权限、审计日志、人工审批，并且通过了认证，模型就可以在授权范围里少一些限制。

他的理由是，安全不该全靠模型去猜。一个可靠的 harness，即使模型犯了错，也能管住 agent 实际能执行什么。

我们的判断是，这个思路很对，它把信任从猜意图，转到了看环境，和重点一里说的证据包是一个方向。最有力的反对意见是：谁来认证？认证会不会变成一张容易造假的徽章？前天我们刚讲过，插件市场的认证徽章，只要放一个文本文件就能拿到。

给你一个具体建议：如果你在搭 agent，先把沙箱、权限和日志这三样做好，不管将来有没有认证，这都是你自己最靠得住的防线。

## 评论四：在手机上跑 notebook

第四条，我们从产品体验讲起。

昨天在 Bluesky 上，一位开发者连发了一串帖子，介绍他做的 SciREPL。这是一个能在手机上用的 notebook，免费版开源。

几个特点很实用。所有计算都在手机本地跑，不是云服务。一个 notebook 里，每个格子可以选不同语言，Python、R、Prolog、命令行都行，格子之间还能共享文件。它能打开带输出结果的 Jupyter 文件，在手机上改完，再存回原格式。数学公式也能直接渲染。

AI 功能是付费版才有，用你自己的模型服务。有一点做得很好：你能看到到底给 AI 发了哪些内容，也能决定 AI 可以运行哪些语言。

开发者自己也说得很清楚：适合学习、教学和快速分析，不适合训练模型和处理大数据。

同一天还有人推荐另一个 Jupyter 社区的工具 MyST。他说，用它来记录代码该做什么、在人和 agent 之间传递想法，比普通 Markdown 好得多，基本上就是 Jupyter 加 Markdown。

我们的判断是，这正好呼应 Jupyter 社区的一个老话题：notebook 不只是专业人士的工具，也是学习和分享的媒介。能在手机上打开、重跑一个别人的 notebook，可复现的门槛就又低了一点。让用户看见发给 AI 的上下文，也是值得别的工具学习的设计。

给你一个具体建议：找一个你写过的教学用 notebook，试试在手机上打开重跑一遍，看看哪里卡住了。

## 评论五：从四分钟到几周

最后一条，我们只看数据，再说判断。

Ethan Mollick 昨天发了一组对比。GPT-4 能独立完成大约四分钟的工作，成功率一半。现在的模型，能做几周的工作。他说，二零二六年一月，是 agent 式工作真正开始的合理分界线。在那之前，大的生产率影响主要在编程。

他还回顾说，不到三年前，大家还在猜，GPT-4 是不是有什么独门秘方，是不是大模型的天花板。答案都是否。

一档 AI 节目的主持人转述了一家评测机构的观点：同样水平的智能，每四到六个月便宜十倍。但最顶尖的模型，每个任务的成本反而在上升。

我们的判断是，这两组数字放在一起，能解释很多事。便宜的智能越来越便宜，所以个人软件爆发。顶尖能力越来越贵，所以大家开始算 token 账、调推理档位。至于一月这个分界线，是 Mollick 的个人判断，生产率的统计数据还要再等等。还有一点，四分钟到几周这个对比，用的是成功率一半的口径，要求更高的成功率，能交出去的时长通常会短一些。

给你一个具体建议：回头看看你今年一月以前和现在的工作方式，有哪件事，现在是交给 agent 一口气做完的。
