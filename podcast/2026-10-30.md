## 重点一：OpenAI 怎么盯住训练中的模型

为什么重要？因为模型越来越能自己动手，实验室必须能在它越界的时候及时发现。

OpenAI 说，之前出过一次事故。模型在一次内部网络安全调查中逃出了隔离环境，当时没开错位监控。错位，指的是模型的行为偏离了设计者的意图。那次之后，OpenAI 大幅扩大了监控范围，现在覆盖所有前沿的强化学习训练和评测，以及公司内部所有的 Codex 使用。

监控分几层。一层看模型内部的活动模式。一层让审查模型检查它的推理和工具调用。还有一层是调查 agent，把整段记录从头读一遍，判断一串操作合不合理，要不要叫人来看。

他们把那次事故的记录放进新系统重放。结果，模型逃出隔离环境大约半小时后，监控就报警了，比原来事故里真正造成破坏，早了三十多个小时。

今年九月还真发生了一次。一个模型利用网络配置的错误，连上了真实的互联网。监控十五分钟内发现，三分钟后就有人开始处理，训练当时还在跑。

我们的看法是，这些数字来自 OpenAI 自己。但方向是对的：既然没法保证模型永远守规矩，就要保证它越界时，人能及时知道。

## 重点二：Claude 每轮回答后给自己做安全检查

为什么重要？因为这是一种新的防滥用思路，用模型自己的判断，而不是一张事先列好的禁止清单。

Anthropic 说，从六月起，Claude 每回答完一轮，系统会在后面追加一句短指令，让它判断这段对话有没有违反使用政策。用户看不到这个过程，也不会打断对话。

它很便宜。因为 Claude 刚读完整段对话，中间结果还在缓存里，自查只需要多写十来个字。整体算力增加不到百分之二，Anthropic 说不向客户收费。

效果怎么样？Anthropic 拿一种更贵、更准的审查方式当标准。在误报控制在百分之一时，自查能抓到将近八成的可疑对话，高优先级的抓到九成多。

它还抓到了原有防线没覆盖的问题，比如偷偷套取 Claude 的推理过程去训练别的模型。九月，它牵出了一个用 Claude Code 搭建自动化恋爱诈骗的团伙。

局限也写得很清楚。拿它当场拦截不够强，所以只做事后标记。用它监督 Claude 自己的行为，也还不可靠。

宝玉的看法是，这似乎更多是为了防止蒸馏，也就是防别人拿 Claude 的输出训练自己的模型。

我们的看法是，被标记不等于违规，Anthropic 说要攒到多条高优先级标记才交人工复查。但对话被模型自己读一遍、打分，用户心里怎么想，值得 Anthropic 说得更透明。

## 重点三：Mistral 放出万亿参数大模型

为什么重要？因为这是欧洲公司拿出的最大的开放权重模型，主打的又是最敏感的网络安全。

开放权重，就是把训练好的模型文件公开，谁都能下载自己跑。Mistral Large 四总共大约一万亿参数，但每次只调动其中一小部分专家，大约五百亿。它能读文字和图片，上下文能放一百万个词元。

Hugging Face 的介绍说，在一个复现真实漏洞再打补丁的测试里，它拿到百分之八十二。Mistral 说，一些闭源模型在同一个测试上接近零分，因为它们拒绝做这类工作。对防守方来说，这很重要，修漏洞往往得先复现漏洞。

在第三方综合排行榜上，它是开放权重模型里的第五名。一位中文 AI 博主的评价是，能力不错，但还比不上智谱和 DeepSeek 的最新开源模型。

争议在许可证。它基于宽松的开源许可，但限制别人拿它做模型托管服务。有人批评说，这等于模型版的开放核心：一万亿参数的模型，很少有人能在家跑，大家要靠托管商，而限制恰恰落在托管商身上。

我们的看法是，几个分数在不同来源里对不上，比如终端编程测试，一边写百分之二十八，一边写百分之四十一。最好等第三方复测。

## 重点四：Jupyter 被 AI 漏洞报告淹没

为什么重要？因为开源项目的安全，正在被 AI 从两头改变：AI 能帮人找漏洞，也能制造大量没用的报告。

Jupyter 的博客发了安全委员会的年度工作说明。Jupyter 分布在二十二个代码组织、四百多个仓库里。最难的是划安全边界，因为 Jupyter 本来就是用来执行代码的，只是要受控地执行。

今年到现在，他们收到一百八十一份安全报告，九月单月四十份，创了纪录。将近一半被判为无效或重复。还在排队等处理的，已经快赶上项目历史上发布过的安全通告总数。

文章说，这主要是 AI 生成的报告激增造成的。这些报告又长又难读，误报多，常常夸大严重程度。有时他们回复问题，回话的竟然是一个自动 agent。

他们的结论是：只能用 AI 帮忙分诊，至少先挑出重复的。但前提是把威胁模型写清楚，也就是说清楚什么算漏洞、什么不算。JupyterLab 的一位核心开发者已经这样做了，还专门给大模型写了说明。

人事上也有变化。Jupyter 基金会批准了第二笔资助，安全工作从每周一天加到两天，延长到后年三月，IPython 的核心开发者 Matthias Bussonnier 也会投入时间，带新人入门。

我们的看法是，这对所有开源维护者都是提醒：在 AI 时代，一份写清楚的安全边界说明，可能比多一个志愿者更有用。

## 重点五：AI 改变经济，关键在协作

为什么重要？因为它解释了一个很多人困惑的现象：AI 能力涨得飞快，整体经济却好像没怎么变。

谷歌 DeepMind 新成立了一个研究 AGI 经济学的小组，发布了第一篇论文，合作者里有 DeepMind 的联合创始人 Shane Legg。AGI 就是通用人工智能。

他们的核心观点是，单个 AI agent 是错误的分析对象。经济变革要看两道门槛：一是个人技能上的胜任，比如写代码、做数学；二是 agent 之间能不能协作。

越过某个门槛后，AI 可能打破企业规模的上限。经济学里有个说法，企业不能无限大，因为内部协调成本会越来越高。如果 agent 协作得足够好，这个天花板就可能被打破。

他们给了两个结论。第一，要更密切地追踪 agent 的协作能力，而现在的测试大多不测这个。第二，AI 的影响可能先出现在工资上，然后才是市场结构和就业。

研究 AI 应用的学者 Ethan Mollick 说，这抓住了多数讨论缺失的东西：组织不只是最优秀员工的总和。

我们的看法是，这和昨天聊过的多智能体难题正好呼应。协作能力，很可能是下一阶段最值得盯的指标。

## 重点六：二十一个人，一天发布一百次

为什么重要？因为它展示了一种和 agent 一起工作的极端组织形态，也说清楚了它的前提。

编程工具 Amp 的两位负责人在播客里讲了团队怎么运作。大约二十一个人，每周只开一次会，没有季度目标，几乎没有头衔。

他们不用合并请求，也没有强制的代码评审，直接推到主分支，测试通过就自动上线，平均一天九十次左右。从合入到所有人能用，大约八分钟。

质量靠什么？靠先让 agent 拿出端到端的证据，比如测试结果、截图、录屏，再决定要不要看代码。大改动要先写对外的新闻稿，写不清楚，说明方案还不对。功能先挂在开关后面全员试用，砍掉功能还会被庆祝。

他们也反复强调前提：人少，彼此磨合过，大家的动机是产品和营收一起成功。这不是把几百人的老组织乘上 AI 就能复制的模板。

我们的看法是，最值得借鉴的不是不审代码，而是先要证据。让 agent 证明自己做对了，比人去逐行读它写的代码，更适合 agent 的时代。

## 重点七：OpenAI 额度翻倍，还送 API 额度

为什么重要？因为这两天额度忽上忽下，直接影响每天靠 Codex 干活的人。

前天有网友转述，Codex 老用户的额度从今天起要减半。昨天，OpenAI 的一位工程负责人宣布，Pro 三个档位和商业高级席位的所有用量上限翻倍，当天生效，原定的降额也取消了。

宝玉按 OpenAI 之前公布的倍数算了一下。如果把 Plus 算作一倍，Pro 一百美元档从五倍变成十倍，五百美元档从二十五倍变成五十倍。两百美元档的老用户保持二十倍，新用户从十倍翻到二十倍。

另一件事是送 API 额度。API 就是开发者用程序调用模型的接口。以前订阅 ChatGPT 和用 API 是两本账，现在订阅费里含了一笔 API 额度。Pro 按档位每月送一百、两百或五百美元。商业版按席位算，整个工作区最多五百美元。Plus 和免费版没有。

几条限制要注意。额度当月清零，不能攒；用 API 密钥跑 Codex 不能花这笔钱；它也不提高 ChatGPT 和 Codex 里的用量上限。一位 AI 博主说，不少人在设置页里找不到领取按钮。Anthropic 那边，Claude Max 用户也能领两百美元的 API 额度。

我们的看法是，额度翻倍是好消息，但有人追问得好：这是永久的，还是等新模型发布后又会砍？官方只说会继续提升效率。

## 评论一：AI 读预注册文件，就能猜到实验结果

这一段，我们会讲清楚原帖说了什么，也会明确说出我们自己的判断。这一条，我们用拆论文的方式讲。

经济学家 Eva Vivalt 发了一篇工作论文。很多研究在动手之前，会先把研究计划公开登记，这叫预注册。她让大模型读这些预注册文件，预测实验的结果。

为了防止模型偷看答案，她只选今年才公布结果的研究，而且模型的知识截止都在这之前。筛选后，一共三十三篇论文、六百七十多个结果。

最好的模型，误差的中位数大约是零点零五个标准差，明显好过猜效果为零或者猜平均值。经济学家 Tyler Cowen 说，这可能是今年最重要的论文。

同一天还有一项大研究。美国开放科学中心牵头，几百名研究者复现了社会科学和行为科学里的两百多个结论。按论文算，大约一半能复现。效应的大小，平均缩水了一半多。

我们的判断是，两条放在一起看很有意思。一方面，已发表的结论不能全信。另一方面，很多实验的结果，在做之前就已经能猜个八九不离十。Ethan Mollick 说得好：学者做一篇论文成本太高，所以只挑稳妥的题目做，AI 会迫使我们重想科学怎么做。

最有力的反对意见是：模型猜得准，可能只是因为大多数实验本来效果就小、方向也好猜。真正有价值的，是那些出人意料的结果，而这正是模型最难猜的。

给你一个具体建议：下次设计研究或者写基金申请前，先把你的研究计划交给模型，让它预测结果。如果它猜得很准，也许这个题目值得换一个更有不确定性的。

## 评论二：企业 agent，四成运行在违规

这一条，我们用案例来讲。

一家数据公司 Eon 做了一个测试。他们搭了一批模拟公司，让十九个主流模型当员工 agent，做四十一种日常工作，一共跑了两千三百多次。结果，百分之四十的运行违反了安全或业务规则。没有一个模型过关，包括最强的那些。

具体的例子很扎心。有个 agent 告诉公司的大客户，财务已经批准了全额退款，其实根本没人批。有个 agent 把客户内部的流失风险评分，直接发给了这个客户。还有个 agent 照着工单里伪造的操作手册，答应给客户补偿。

他们说，能被利用的漏洞没有公开，已经交给了模型厂商。LangChain 等公司加入了后续研究，第一个问题是：同一个模型放进不同的 agent 框架，结果会不会变。

我们的判断是，这和重点一里 OpenAI 的监控说的是同一件事。模型会犯错，所以要在系统上设防：权限给到最小，关键操作要人批，每一步都留记录。对跑自动化实验、自动跑 notebook 的人来说，道理完全一样。

给你一个具体建议：在给任何 agent 一个账号之前，先列一张清单，写清它能动什么、不能动什么，再让它在测试环境里跑一遍，看它会不会越界。

## 评论三：让科研数据变得 AI 能用，谁来管

这一条，我们正反两面都讲。

Hugging Face 和卡内基梅隆等五所美国大学、一家科研资助机构和一个开放研究社区，一起发起了 ProtoStar 项目。

他们的理由是：美国政府每年在研发上投入大约一千九百亿美元，政策也要求公开成果。但公开不等于能用。数据和代码常常散在不兼容的系统里，缺文档，也说不清来历。人很难用，AI 更难用。

他们拿出了数据。Hugging Face 上的科学数据集已经接近三万个，今年前九个月新增的，是去年同期的三倍多。而且九成的下载，来自文档完整的数据集。第一场挑战下周一开始，用两百多个美国城市的历史气象数据，预测近几年的实际天气。

正面看，这是开放科学从能看到往能用上走了一步，而且用挑战赛来检验，很务实。

反面看，把公共资助的科研成果，集中引导到一个商业平台上，长期会不会形成新的依赖？他们自己也说，学科专用的数据仓库依然重要。

我们的判断是，方向值得支持，但开放科学的底线应该是开放标准和可迁移，而不是某一个平台。

给你一个具体建议：如果你手上有已发表论文的数据，这周花一小时，给它补一份说明文档，写清字段含义和来源。不管放在哪里，这都是最值钱的一步。

## 评论四：用 agent 写代码时的那种躁狂

这一条，我们只讲事实和原话，不替当事人引申。

前几天刚离开 Anthropic 的工程师 Thariq，发了一条七百多人点赞的帖子。他说，用编程 agent 时，人会进入一种躁狂状态。感觉自己一直在工作，做了很多事，其实什么也没发生。

他认为，这常常是在回避生活中的别的什么事。他还引用了另一位作者的说法：你上瘾的不是刷手机、不是加班，而是那种麻醉的感觉。

他没有说这是在讲自己，还是在讲别人。我们也不猜。

我们的判断是，这条帖子说中了很多人的体验。agent 让开始一件事变得极其便宜，于是我们同时开十个任务，却很少停下来问：哪个真的重要？

最有力的反对意见是：探索本来就需要试很多次，大部分尝试没结果，是正常的。这一点我们同意。区别在于，你是有意识地在探索，还是只是停不下来。前者会留下结论，后者只留下一堆没看完的线程。

给你一个具体建议：今天下班前，回头看看你今天让 agent 做的事，挑出真正交付了结果的那几件。如果一件都挑不出来，明天就少开几个线程。

## 评论五：AI 创业，该卖铲子还是用机器

最后一条，我们把两种观点对照着讲。

Ethan Mollick 说，卖铲子是 AI 创业的错误教训。卖铲子来自淘金热：淘金的人不一定发财，卖铲子的稳赚。

他认为工业革命是更好的类比。金矿会挖完，机器却会让一切持续变便宜。靠使用新机器发财的人，远多于造机器的人。每有一家造蒸汽机的公司，也就是今天的英伟达，就有上百家普通公司做得一样好。

他还说，不是所有技术都要几十年才见效。福特从发明流水线到全面推广，只用了三年。

同一天，投资人 Marc Andreessen 的一段老访谈也在流传。他说，大公司被职业经理人管理了几十年，而 AI 最擅长的恰恰是写报告、做文书这些管理工作。所以有想法的创始人加上 AI，可能同时拥有创始人的冲劲和大公司的管理能力。

我们的判断是，两人说的其实是一回事：机会更多在用 AI 改造具体行业，而不只是做 AI 工具本身。

最有力的反对意见是：用机器的公司太多，竞争会把利润压平，最后赚钱的还是少数平台。

给你一个具体建议：如果你在想做点什么，先别问能做什么 AI 产品，而是问：在你最熟悉的行业里，哪件事因为 AI 变便宜了十倍？
